# T1.11 — IOBase/IOFactory id integrity

| Phase | Type | Depends on | Status |
|---|---|---|---|
| 1 | fix | Phase 0 | 📋 Backlog |

## Owned files
- `src/bin/calaos_server/IOBase.{cpp,h}`
- `src/bin/calaos_server/IO/IOFactory.{cpp,h}`

## Findings

### Major — lifetime: `io_table` keyed by a mutable `id`, no re-hash
`ListeRoom` keys its hash on the live id: `io_table[io->get_param("id")] = io` (`ListeRoom.cpp:51`) and `io_table.erase(io->get_param("id"))` (`ListeRoom.cpp:65`). But `IOBase::set_param` is unguarded — `virtual void set_param(const string &opt, const string &val){ param.Add(opt, val); }` (`IOBase.h:97`) — and `JsonApi::buildJsonSetParam` lets a client set **any** param including `"id"` (`JsonApi.cpp:419`). After an id change the object is still in `io_table` under the **old** key: lookups by new id fail, and `delIOHash` erases the wrong/none entry → dangling pointer / UAF. **Fix:** make `"id"` immutable after insertion (reject/ignore an `id` change in `set_param`), **or** notify `ListeRoom` to re-hash on id change. Provide the hook in `IOBase`; the `io_table` re-hash itself is applied in T1.3's `ListeRoom` via that hook (coordinate — disjoint files).

### Minor — correctness: duplicate/case-colliding IO type registration silently overwritten
`IOFactory::RegisterClass` (`IOFactory.h:64-66`) lowercases the type then `ioFunctionRegistry[type] = classFunc;`. Two `REGISTER_IO` names differing only in case (or duplicated) map to the same key; the second silently wins, and `origNameMap` is overwritten too. **Fix:** detect an existing key and `cError()` (or assert) on duplicate registration instead of silently overwriting.

### Minor — lifetime: `genDocIO` leaks every IO and pollutes the live `io_table`
`IOFactory::genDocIO` (`IOFactory.cpp:88`) does `auto io = CreateIO(it->first, p); IODoc *doc = io->getDoc();` with no null check (`CreateIO` can return `nullptr`), and each `new TYPE(_p)` runs the `IOBase` ctor → `addIOHash(this)` registering into the **real** `io_table` under the shared id `"doc"` (set at `:86`); none of the objects are ever deleted. **Fix:** `if (!io) continue;`, delete `io` after reading its doc, and build the documentation without inserting into the live `ListeRoom` hash.

### Minor — correctness: inconsistent battery-status contract
`IOBase.cpp:245` — `getStatusInfo` hides battery status at 0% yet the low-battery notification still fires, and the notification timestamp is recorded even when no notification channel is enabled. **Fix:** make the 0%-reading and notification-gating consistent; record the notif time only when a channel actually sends.

## Finding T1.3 (vague 2) — appelants de createIO sans check nullptr
T1.3 fait maintenant retourner `nullptr` à `ListeRoom::createIO` sur id dupliqué (en plus du type inconnu préexistant). Deux appelants déréférencent le retour sans vérification : `JsonApi.cpp:1366-1368` (`dynamic_cast` sur le retour) et `Scenario/AutoScenario.cpp:157-160` (`in->setAutoScenario`). Bug latent préexistant rendu plus atteignable — ajouter les gardes (fichiers hors périmètre T1.11 : à caser dans une vague où `JsonApi.cpp`/`AutoScenario.cpp` sont libres, ou étendre ce ticket au moment de le lancer).

## Acceptance
- Changing an IO's `id` via the API does not leave a stale/dangling `io_table` entry (either rejected, or re-hashed).
- Duplicate/case-colliding IO type registration is logged, not silently dropped.
- `--gendoc` does not leak IOs or insert `id="doc"` objects into the live table.
