## New findings (audit, English)

> ⚠️ **Correction:** the premise above — "`AVRMarantz.cpp` is byte-identical to `AVRDenon.cpp`, replace with `class AVRMarantz : public AVRDenon {}`" — is **incorrect**. The files are **not** identical. Do **not** delete `AVRMarantz.cpp` or collapse the class. Keep the header-comment fix and the log-domain fix, but the real work in this ticket is the correctness bugs below. (The BOARD quick-win about deleting `AVRMarantz.cpp` is removed.)

Real defects found in the AV receiver drivers:
- **critical/correctness** `Audio/AVROnkyo.cpp:137` (and `:178`) — packet reassembly does `brecv_buffer.insert(data.end(), data.begin(), data.end());` using `data.end()` (an iterator into `data`, not `brecv_buffer`) as the insertion position → **undefined behavior** / memory corruption. `:127` correctly uses `brecv_buffer.end()`. **Fix:** `brecv_buffer.insert(brecv_buffer.end(), data.begin(), data.end());` in both places.
- **major/correctness** `Audio/AVROnkyo.cpp:266` (SLZ) and `:275` (SL3) — zone-2/zone-3 input-source updates set `source_zone2`/`source_zone3` but emit `source_main`. **Fix:** emit the zone's own value.
- **major/correctness** `Audio/AVRPioneer.cpp:138` — the `YV` (zone-3 volume) branch updates `volume_zone3` but fires `state_changed_2` (zone-2 signal), so zone-3 never sees the change and zone-2 gets a spurious value. **Fix:** `state_changed_3.emit(...)`.
- **major/lifetime** `Audio/AVRManager.cpp:92` — `AVRManager::Delete` does `if (obj->ref_count <= 0)` with no null check; `Create()` returns NULL for an unknown `model` (`:69-70`) and the IO dtor calls `Delete(receiver)` unconditionally (`AVReceiver.cpp:251`) → NULL deref / refcount underflow. **Fix:** null-guard `obj` in `Delete`.
- **major/edge-case** `Audio/AVRDenon.cpp:260` — the volume stream's `width()`/`fill()` are applied to the literal prefix instead of the numeric value, mis-padding the command. **Fix:** set width immediately before inserting the value.

Acceptance (added): Onkyo reassembly clean under ASan; zone-2/3 source & volume routed to the correct signals; unknown AVR model does not crash; Denon volume command correctly zero-padded.
