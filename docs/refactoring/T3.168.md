# T3.168 — le `return ok? 0: 1;` de `MqttProcess::procMain()` n'est tenu par aucun cas de l'arbre

**Statut** : 📋 · **Type** : dette de test · **Phase** : 3
**Dépend de** : [`T3.108`](T3.108.md) · **Origine** : contre-mutation de [`T3.108`](T3.108.md).

---

## 1. Ce qui a été mesuré

Contre-mutation par échange sur `src/bin/calaos_server/IO/Mqtt/MqttExternProc_main.cpp` :

```
-    return ok? 0: 1;
+    return 0;
```

c'est-à-dire la forme que `T3.108` vient de retirer aux cinq autres sidecars, appliquée au seul qui
l'avait déjà. `make && make check` ⇒ **0 rouge sur 157 suites**, `CXXLD calaos_mqtt` **lu**.
`calaos_mqtt` est donc, depuis `T3.103`, la seule famille qui lit la réponse de `run()` — et
**personne ne le vérifie**.

⚠️ Ce n'est pas un trou de `core/MqttSidecarConfigWait_test` : cette suite tient les sorties non
nulles qui passent par `m_exitCode` (`brokerLost()`), lesquelles court-circuitent la ligne mutée
ci-dessus (`if (m_exitCode != 0) return m_exitCode;`). Le chemin non tenu est précisément
« la boucle a échoué **et** le courtier n'a rien signalé ».

## 2. Pourquoi le cas est plus cher ici qu'ailleurs

⭐ **Mesuré en écrivant `T3.108`** : `MqttProcess::setup()` attend sa configuration dans une **boucle
`select()` à lui**. L'interposition qui sert aux cinq autres familles — faire rendre `EBADF` au
premier `select()` — le fait donc sortir **avant** `procMain()`, avec un statut non nul qui ne dit
rien de la boucle principale. Un tel cas a été écrit, il était **vert**, et c'est cette
contre-mutation qui l'a démasqué : il a été retiré plutôt que gardé.

Ce qu'il faut pour un cas honnête, et que `core/MqttSidecarConfigWait_test` sait déjà faire :

1. un écouteur de bouclage qui joue le courtier (`openLoopbackListener()`), et une configuration
   écrite sur la socket (`frameOf(MqttWire::encodeConfig(...))`) — sans quoi `setup()` rend `false` ;
2. une interposition qui laisse passer les `select()` de `setup()` et n'échoue **qu'ensuite**
   (`CALAOS_SELECT_FAIL_AFTER` de `tests/core/selectfail_preload.c` prend déjà un compte) ;
3. l'oracle de `T3.108` : statut non nul, et un jumeau ordonné à statut nul.

⚠️ Le point 2 est le seul incertain : rien ne dit combien de `select()` libmosquitto appelle pour
son propre compte entre `connect_async()` et la première tour de boucle. **À mesurer avant
d'écrire**, sinon le compte est une **longueur** dont le cas dépend.

## 3. ⛔ Nu

- ⛔ **Aucun défaut n'est allégué** : la ligne est juste, elle n'est simplement tenue par rien.
- ⛔ **Le trou n'est pas comparé au reste de l'arbre** : d'autres lignes de `MqttProcess` peuvent
  être dans le même cas, seule celle-ci a été contre-mutée.
