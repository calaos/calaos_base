# E4.1b — Les trois invariants d'émission, posés AVANT toute migration

**Type** : fix (durcissement) · **Phase** : 4 · **Série** : E4.1 · **Vague** : 1
**Dépend de** : E4.1a ✅ · **Débloque** : tout sous-ticket qui bascule un émetteur (E4.1l, m, n, o, p, q, r, s)
**Régime de preuve** : structure/valeurs **couvert** (goldens) · forme d'octets **nu**, mais c'est
ce ticket qui la fixe.

## Pourquoi ce ticket d'abord — le fait qui l'impose

`nlohmann` **émet déjà en production**, aujourd'hui, sur la même API : les deux surcharges
`sendJson(const Json &)` existent et sont câblées (`JsonApiHandlerHttp.cpp:253-266`, appelée
`:214` ; `JsonApiHandlerWS.cpp:75-86`, appelée `:125`, `:147`, `:162` — le chemin `scope denied`).
Elles dument **à nu** : `json.dump()`, sans `ensure_ascii`, **sans gestionnaire d'erreur**.

Deux conséquences, mesurées :
1. **L'API émet déjà deux formes d'échappement différentes selon le chemin de code.** Les réponses
   jansson sont ASCII pur (`JSON_ENSURE_ASCII`), les réponses nlohmann sortent en UTF-8 brut.
   Ce ticket **supprime cette incohérence** et ne l'introduit pas.
2. ⛔ **Le `std::terminate` d'E4.0 (`E4.0.md:355`) n'attend qu'un appelant.** `dump()` nu lève
   `type_error.316` sur des octets UTF-8 invalides dans l'arbre. Aujourd'hui aucun payload
   client-influencé n'atteint ces deux surcharges (les charges y sont littérales, et `json_loads`
   refuse l'UTF-8 invalide **en entrée**). **Le premier sous-ticket qui bascule un constructeur
   nourri par `jParam` rend le crash atteignable** — c'est E4.1o (`get_param` réémet la clé
   fournie par le client). Le durcissement doit donc précéder, pas accompagner.

## Décisions utilisateur qui deviennent des invariants d'épique

1. **Clés triées assumées** — `nlohmann::json` standard, **jamais `ordered_json`**. Ne le prends
   pas pour « préserver » quoi que ce soit.
2. **UTF-8 invalide → U+FFFD** — `Json::error_handler_t::replace` sur **chaque** `dump()`.
   ⛔ **Pas de `try`/`catch` à la place** : le handler traite la cause, un `catch` le symptôme.
3. **`ensure_ascii = true`** (décision utilisateur 2026-08-24) — `dump(-1, ' ', true, error_handler_t::replace)`.
   Motif : **delta minimal**. Le wire reste **ASCII pur** comme aujourd'hui ; la seule différence
   avec jansson est la **casse de l'hexadécimal** (`\u00E9` → `\u00e9`). Les octets UTF-8 bruts
   (défaut nlohmann) ont été **écartés** : ils cessent de garantir l'ASCII-only, changement de
   forme bien plus large, dans une zone drivers sans filet. Passer aux octets bruts reste possible
   **plus tard, comme changement délibéré et déclaré**, jamais comme effet de bord d'une migration.

## Travail

**Appliquer les invariants 2 et 3 à tout `dump()` d'un payload sortant du serveur** :

| Fichier | Site | Nature |
|---|---|---|
| `JsonApiHandlerHttp.cpp` | `:255` | émetteur API HTTP |
| `JsonApiHandlerWS.cpp` | `:84` | enveloppe API WS |
| `RemoteUI/RemoteUIProvisioningHandler.cpp` | `:218` | wire appareil RemoteUI |
| `RemoteUI/OtaHttpHandler.cpp` | `:175` | wire appareil RemoteUI |
| `RemoteUI/RemoteUIWebSocketHandler.cpp` | `sendJson()` | wire appareil RemoteUI |
| `WebSocket.cpp` | `:326` | corps d'erreur |
| `NotifManager.cpp` | `:253`, `:261` | notification sortante |
| `Rules/ActionPush.cpp` | `:115` | `event_raw` persisté |

⚠️ **Ne touche PAS** aux `dump()` de wires **tiers déjà en service en UTF-8 brut** :
`Audio/RoonPlayer.cpp` (7 sites), `Audio/AVRRose.cpp` (8 sites),
`IO/OneWire/OWExternProc_main.cpp:209`, `bin/tools/calaos_config.cpp:347/:616`,
`lib/ConfigOptions.cpp:1493`. **Y ajouter `ensure_ascii` changerait les octets d'un wire que cette
épique ne migre pas** — c'est exactement la faute que la décision utilisateur interdit. Sur ceux-là,
**ajoute le gestionnaire d'erreur seul** (`dump(N, ' ', false, error_handler_t::replace)`), qui ne
change rien tant que les données sont valides. `CalaosConfig.cpp:558` le fait déjà : c'est le
précédent, recopie-le.

**Zéro appel jansson touché par ce ticket.**

## Pièges propres

- `dump()` a **quatre** paramètres : `dump(indent, indent_char, ensure_ascii, error_handler)`.
  Passer `true` en 3ᵉ position sur un appel qui avait un indent implicite change **aussi**
  l'indentation si tu oublies le `-1`. Les sites compacts veulent `dump(-1, ' ', true, replace)`.
- Une **assertion d'absence** (« ce dump ne lève pas ») n'a de valeur que si le canal a été
  **flushé** : pompe la boucle avant de conclure.

## Acceptation vérifiable

1. `grep -rn '\.dump(' src/bin src/lib --include='*.cpp' --include='*.h' | grep -v json.hpp | grep -v error_handler` → **zéro ligne**.
2. Un test qui injecte `\xff\x80` dans une valeur puis émet sur chacun des deux transports :
   **réponse livrée**, contenant `�`, **pas de `terminate`**, connexion toujours vivante.
   Contre-mutation **par échange** : retirer `error_handler_t::replace` d'**un seul** des deux
   émetteurs doit faire tomber **ce test-là et lui seul**.
3. Un test qui épingle la nouvelle forme des réponses nlohmann : `é` sort `\u00e9`, **pas** en
   octets bruts. Sonde : une valeur qui **ne peut pas devenir valide** par accident.
4. **Zéro golden modifié** — les goldens comparent des documents parsés, l'échappement leur est
   invisible ; si l'un bouge, tu as changé une **valeur**, arrête-toi.
5. `make check` vert en **distclean complet**, compte ≥ master.

## Méthode (rappel, non négociable)

Commit de **caractérisation d'abord** (tests seuls, **zéro `src/`**, vérifié commit par commit) ·
**contre-mutation PAR ÉCHANGE**, jamais par neutralisation · piège du **« fixture pauvre »** :
**7 récidives dans E4.0, toutes trouvées par les relecteurs, jamais par les implémenteurs** — un
jeu de données trop pauvre pour distinguer deux champs interchangeables · **ne recopie pas un
pompage que tu n'as pas mesuré** (3 des 6 rustines historiques n'absorbaient rien) · piège
**`_DEPENDENCIES` variante faux ROUGE** : `make distclean` avant de conclure.
