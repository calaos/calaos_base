> ## ⚠️ À lire avant d'implémenter
>
> **Il n'y a PAS de « 0 en cas d'échec ». Il y a DEUX régimes.**
>
> | Entrée | Retour | `dest` après appel |
> |---|---|---|
> | `""` | **`true`** | **NON ÉCRIT** |
> | `" "`, `"\t "` — **toute chaîne blanche** | **`true`** | **NON ÉCRIT** |
> | `"true"` (illisible, non blanc) | `false` | **0** |
> | `"12abc"` (préfixe lisible) | `false` | **12** |
> | `"12"` | `true` | 12 |
>
> Mesuré, pas raisonné : programme autonome, `g++ -std=c++17`, `dest` pré-semé à `0x5555` =
> **21845**. Sortie brute :
> ```
> ''       ret=1 dest=21845 | is_of_type<int>=1
> ' '      ret=1 dest=21845 | is_of_type<int>=1
> '  \t '  ret=1 dest=21845 | is_of_type<int>=1
> 'true'   ret=0 dest=0     | is_of_type<int>=0
> '12abc'  ret=0 dest=12    | is_of_type<int>=0
> ```
> **21845, c'est exactement le canal DMX que `calaos_ola` a envoyé** quand ce piège l'a tué.
>
> ⭐ **`Utils::is_of_type<T>("")` rend `true` lui aussi** (`StringUtils.h:96-103`, même `iss.eof()`,
> et son `T tmp;` est **lui-même non initialisé**). ⇒ **une garde `is_of_type` ne protège pas.**
>
> ⇒ la seule entrée qui **ment sur son retour** est aussi la seule qui **n'écrit rien**.

## 1. Le mécanisme

`src/lib/StringUtils.h:104-111` — ⚠️ **pas** `src/lib/Utils.h:308-315` comme l'écrit
`FINDINGS.md:616` : la fonction a déménagé en T2.2, `Utils.h` fait 238 lignes et ne contient plus
le mot `from_string`.

```cpp
template<typename T>
bool from_string(const std::string &str, T &dest)
{
    std::istringstream iss(str);
    iss.imbue(std::locale("C"));
    iss >> dest;
    return iss.eof();      // ← :110
}
```

Sur une chaîne vide **ou blanche**, la **sentinelle** de `operator>>` échoue en sautant les
blancs : elle pose `eofbit | failbit` et **`num_get` n'est jamais appelé**. Donc `dest` n'est pas
touchée — le « 0 en cas d'échec » de la norme est écrit **par `num_get`**, qui n'a pas tourné — et
`iss.eof()` est vrai ⇒ **retour `true`**.

**Trois corrections de fait portées dans `FINDINGS.md` par ce ticket :**
- `:616` « avec dest zéro-initialisée » — **faux**, `dest` n'est **pas écrite** ;
- `:1912` « `from_string()` en échec écrit 0, qui est aussi le défaut » — vrai pour `"true"`,
  **faux pour `""`**, et c'est `""` qui arrive (clé absente ⇒ `Params::operator[]` rend `""`) ;
- `:2458` « laisse `port` à **0** » — **faux**, elle le laisse **indéterminé**.
Le seul passage exact du document est `:1859-1863`.

### La conséquence réelle — ni dramatisée, ni minimisée

**Ce n'est pas un plantage.** `impulse_action_time` reçoit un entier arbitraire, et voici ce qui
en découle, lu à `OutputShutter.cpp:216-227` :

- **Valeur grande** (le cas le plus probable — pile non nettoyée) : `impulse_action_time +
  impulse_time < time * 1000` est **faux**, **aucune minuterie d'arrêt n'est armée**. L'impulsion
  dégénère en **course complète** : au lieu d'un à-coup de quelques centaines de ms, le volet
  monte jusqu'à sa butée (arrêté par `timer_end` à `:237-240`, ou pas du tout si
  `useExternalState`). ⇒ **effet physique observable, contraire à la commande donnée.**
- **Valeur négative** : `_t` négatif passé à `Timer::singleShot` — arrêt immédiat, l'impulsion ne
  fait rien. Et `impulse_action_time + impulse_time` peut **déborder l'`int`** : UB.
- **Dans tous les cas** : `cmd_state = "impulse up " + to_string(impulse_action_time)`
  (`:159`) puis `updateCache()` ⇒ **la valeur arbitraire est publiée dans l'état de l'IO et
  persistée dans le cache d'état**, donc renvoyée à tous les clients.

⛔ **Ce n'est PAS une prise de contrôle** : la valeur n'est pas choisie par l'appelant, seulement
non déterministe. **Et ce n'est pas non plus anodin** : un compte API ordinaire déclenche un
mouvement de volet **différent de celui qu'il a demandé**, de façon **non reproductible**, sur du
matériel qui pince les doigts.

## 4. Le correctif : local ou global ? — **les deux, dans cet ordre**, et voici la pesée

### ⭐ Recommandation (à valider, pas imposée)

**Étage 1 — corriger le RETOUR. Une ligne, `StringUtils.h:110` :**
```cpp
return !iss.fail() && iss.eof();
```
Table après : `""` → **false** · `" "` → **false** · `"true"` → false · `"12abc"` → false ·
`"12"` → true · `"12 "` → false (inchangé). **Un seul cas change** : le blanc, de `true` à
`false`. ⇒ auditer les **9** sites ci-dessus, **et eux seuls**. `WagoConfigParse.h:57` et
`GpioCtrl.h:78` en **bénéficient** (ils rejetteront enfin une valeur vide).
Faire de même pour `is_of_type` (`:102`), dont le `T tmp;` doit aussi être initialisé.

**⚠️ Étage 1 ne suffit PAS** — et c'est le point à ne pas rater : les 310 appelants qui **ignorent**
le retour ne voient aucune différence. **Le retour honnête ne referme rien à lui seul.**

**Étage 2 — ⛔ NE PAS forcer « 0 en cas d'échec ».** La correction « évidente »
(`T tmp{}; iss >> tmp; dest = ok ? tmp : T{};`) fermerait les 310 d'un coup… **et casserait 38
appelants nommables**, ceux dont le destinataire porte un défaut **utile** écrasé par 0 dès que la
clé est absente : `IO/Mqtt/MqttExternProc_main.cpp:194` (`port = 1883`) et `:197`
(`keepalive = 120`), `IO/LAN/PingInputSwitch.cpp:90` (`interval = 15000`),
`IO/RemoteUI/RemoteUI.cpp:525` (`brightness = 100`), `JsonApi.cpp:2234` (`perPage = 100`),
`IO/KNX/KNXIo.h:61` (`eis = EIS_Autodetect`), `lib/Logger.cpp:110`, les quatre `step = 1.0`
d'`OutputAnalog.cpp`, les quatre d'`IntValue.cpp`, les trois `a = 1.0` de `ColorUtils.cpp`.
**Le contrat « je n'écris pas si je ne peux pas lire » est celui sur lequel ces 38 reposent.**
⇒ ajouter **à côté**, sans toucher l'existante :
```cpp
template<typename T> T from_string_or(const std::string &str, T def)
{ T tmp; return from_string(str, tmp) ? tmp : def; }
```

**Étage 3 — initialiser les destinataires. C'est le vrai travail, et il est sûr.**
Aujourd'hui la valeur lue est **indéterminée** : **toute** valeur définie est une amélioration,
donc l'initialisation ne peut **pas** casser un appelant — contrairement à l'étage 2. Précédent
déjà dans l'arbre : `IO/Wago/WagoMap.cpp:203-204` (`UWord address = 0; int count = 0;`), posé par
E4.1h.
