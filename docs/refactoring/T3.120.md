# T3.120 — Deux autres façons dont l'ioDoc ment, trouvées par le recensement de T3.38

**Origine** : [T3.38](T3.38.md) §5.1 — le balayage des **508** appels `ioDoc->…` de l'arbre.

## 1. `grid_h` et `grid_w` publient chacun la description de l'autre

`IO/RemoteUI/RemoteUI.cpp` :

```cpp
ioDoc->paramAdd("grid_h", _("Grid horizontal size"), IODoc::TYPE_INT, true, "3");
ioDoc->paramAdd("grid_w", _("Grid vertical size"),   IODoc::TYPE_INT, true, "3");
```

⭐ **Ce n'est pas une question de goût, le code tranche** : `RemoteUIWebSocketHandler.cpp` écrit
`data["grid_height"]` depuis `get_param("grid_h")` et `data["grid_width"]` depuis
`get_param("grid_w")`. **Les deux descriptions sont échangées.**

**Conséquence** : un installeur qui pose un bandeau **4 colonnes × 2 lignes** lit « horizontal »
en face de `grid_h`, saisit `4` — et obtient une grille de **4 lignes sur 2 colonnes**. Le défaut
est **symétrique**, donc il ne se rattrape pas par tâtonnement : les deux champs mentent, et une
grille carrée le cache complètement.

**Le travail** : échanger les deux phrases, ou mieux, écrire `_("Grid height, in rows")` /
`_("Grid width, in columns")` — un mot qui nomme l'unité ne peut pas s'échanger en silence.
⚠️ Les deux chaînes passent par `_()` ⇒ **`po/`**, édition chirurgicale des `msgid` comme
[T3.29](T3.29.md) §5.4, **pas** `make -C po update-po`.

**Le test** : le patron existe, c'est `tests/core/IoDocRgbBounds_test.cpp` de T3.38 — lire le
document par le chemin de `--gendoc` et exiger que la description de `grid_h` nomme la **hauteur**
et pas la largeur. ⭐ **Et il y a mieux à faire ici** : le seul oracle qui ne se contente pas de
recopier une convention est de relier la description au **consommateur** — `grid_h` alimente
`grid_height`, c'est cela qu'il faut figer.

## 2. ⭐ Le DMX est-il indexé à partir de 0 ou de 1 ? — décision de produit, 4 sites

`OLAOutputLightDimmer.cpp` (`channel`) et `OLAOutputLightRGB.cpp` (`channel_red`,
`channel_green`, `channel_blue`) déclarent tous **`0..512`**. **Mesuré** contre la `libola` de
l'image de développement, dans le conteneur :

```
after Blackout: Size=512
ch511=200 -> Size=512 Get(511)=200
ch512=201 -> Size=512 Get(512)=0        <- deja hors borne
ch9999=202 -> Size=512 Get(9999)=0
```

`DmxBuffer::Blackout()` dimensionne le tampon à **512 créneaux indexés 0..511** et `SetChannel()`
ignore **en silence** tout indice au-delà — sans exception, sans valeur de retour, et la trame
part quand même. ⇒ **`512` est documenté comme valide et ne fait rien.**

⛔ **Ce n'est pas « changer 512 en 511 ».** Le nombre saisi dans `io.xml` est passé **tel quel**
comme indice de tampon, or **tous les manuels de projecteur numérotent les canaux à partir de 1**.
Un utilisateur qui écrit `1` pilote donc le créneau `1`, c'est-à-dire le canal DMX **2** de son
projecteur, et il ne peut pas atteindre le canal **512**. Trois issues, et il faut en choisir une :

| | Ce que ça change | Ce que ça casse |
|---|---|---|
| **A — doc seule** : `0..512` → `0..511` | la borne cesse de promettre un créneau inerte | rien : `512` ne faisait déjà rien |
| **B — doc seule, convention DMX** : `1..512` et `channel - 1` à l'émission | l'installeur saisit le numéro de son manuel | ⛔ **toutes les installations existantes** décalent d'un canal |
| **C — laisser** | — | la borne continue d'autoriser un créneau mort |

⭐ **Recommandation : A**, et **dire la convention** dans la description (« DMX slot index, 0
based »). B est la seule qui soit juste vis-à-vis du matériel et la seule qui soit inacceptable
sans migration.

## 3. Ce que le recensement de T3.38 a AUSSI trouvé, et qui reste à instruire

- ⚠️ **`eis` (`IO/KNX/KNXBase.cpp`) est déclaré `0..15`, et `KNXExternProc_cli.cpp` refuse
  `eis < 1`** à **trois** endroits (`Wrong EIS`, `Unable to convert data for eis`,
  `toKnxData()` qui rend `false`). La valeur `0` est donc offerte par l'installeur et rejetée par
  le pilote. Le défaut par défaut est `EIS_Value_Int` = 6, donc seul un `0` saisi explicitement
  est concerné. **Une borne à changer : `0` → `1`.**
- ⚠️ **`msec` (`IO/InputTimer.cpp`) est déclaré `0..999`** alors qu'`InputTimer` remonte **tout**
  intervalle sous **50 ms** à 50 (`if (msec < 50) msec = 50;`). La borne n'est pas fausse par
  elle-même — le plancher porte sur le **total** hour/min/sec/msec —, mais un timer demandé à
  10 ms bat à 50 ms **sans que rien ne le dise**. ⇒ soit la description porte le plancher, soit
  le plancher se signale.

## 4. Acceptation

1. `grid_h`/`grid_w` : la description de chacun nomme sa propre dimension, **liée au consommateur**
   par un test, pas seulement à une convention.
2. Le choix A/B/C du §2 est **tranché par l'utilisateur** avant toute ligne de code.
3. `eis` et `msec` : corrigés ou explicitement reportés, **avec le chiffre**.
4. Les `msgid` touchés sont repris **chirurgicalement** dans les 8 catalogues suivis ; `msgfmt -c`
   vert ; le nombre d'entrées `fuzzy` créées est **publié**.
