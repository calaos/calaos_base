## Findings

### F6 — major: path traversal in `event_picture`
`JsonApiHandlerHttp::processEventPicture` (`JsonApiHandlerHttp.cpp:932-935`):
```cpp
string pic_uid = jsonParam["pic_uid"];
string file = Utils::getCacheFile("push_pictures") + "/" + pic_uid + ".jpg";
```
`pic_uid` is concatenated without sanitization, then served via `buildHttpResponseFromFile`. `../` allows reading a file outside the cache (authenticated). **Fix:** route through `FileUtils::resolveSafePath` (`FileUtils.cpp:158`, already used for `/app/` and `/debug/` — `HttpClient.cpp:290,342`).

### F7 — major: argument injection into `calaos_picture`
`processGetCameraPic` (`:482-487`) builds `cmd = ".../calaos_picture " + url + " " + tempfname + " -w " + width + " -r " + rotate`, split on spaces (`Utils::CStrArray`) then `spawn`. `width`/`rotate` are unvalidated → `100 --flag x` injects argv. (spawn, no shell → not classic RCE, but argument injection.) **Fix:** validate `width`/`rotate` as integers. Same for `processGetCover` / `processAudio get_cover`.

### F3 — major: no rate-limit/lockout on login
HTTP login (`:98`) and WS login (`:113-138`) have no throttle or lockout → brute-force of the admin password. **Fix:** per-source failure counter + delay/backoff + temporary lockout.

### F4 — major: secrets logged before auth
Both handlers dump the full JSON before auth (`JsonApiHandlerHttp.cpp:75-78`, `JsonApiHandlerWS.cpp:97-101`) → `cn_pass`, `token`, `old_pw`/`new_pw` in cleartext at debug level. **Fix:** redact (`***`) known sensitive fields before `cDebugDom`.

### F2 — non-constant-time credential comparison + triplicated block
Credential comparison uses `operator!=` (not constant-time). The credential-lookup block is copied **3×** (`JsonApiHandlerHttp.cpp:88-96`, `JsonApiHandlerWS.cpp:116-124`, `JsonApi.cpp:1678-1686`). Additionally, the `login_service` token check at `JsonApiHandlerWS.cpp:529-532` claims "constant-time" in a comment but leaks length (`expected.size()==received.size()`) then short-circuits on the first mismatching byte — this gates the privileged `mcp_service_token` (serviceScope/`set_state`). **Fix:** centralize in `JsonApi::checkCredentials()` with a constant-time comparison (`CRYPTO_memcmp`); reuse the same helper for the service-token check.

### F11 — major: leak + UAF of the MJPEG camera stream
`processCamera get_video` (`:872-903`): `m_signalComplete` sets `cameraDl = nullptr` **without `delete`** (`:901`) → leak. `downloadCameraPicture` (`:908-930`) re-schedules via `Timer::singleShot` capturing `this`/`camera` without checking the connection still exists → UAF if the client disconnects mid-stream. **Fix:** free `cameraDl` correctly; add an is-alive/ownership guard on the re-arm.

### New — major/correctness: `processGetCover` brace-less `if` hangs the request
`JsonApiHandlerHttp.cpp:424-426` — `if (jsonParam.Exists("rotate"))` has **no body**, so `player->get_album_cover(...)` runs only when a `rotate` param is present. Without it the function returns having sent no `sendJson`/`sendData` → the HTTP connection hangs (no idle timeout on the API_HTTP path). The sibling `processGetCameraPic:478-480` does it correctly. Also `:443-447` never resets `exe_thumb_running` in the ExitEvent handler, so after one cover generation the guard `if (data.svalue=="" || exe_thumb_running)` (`:429`) permanently rejects further requests. **Fix:** brace the `if` and assign `rotate = jsonParam["rotate"]`; reset `exe_thumb_running = false` in both the ExitEvent and ErrorEvent callbacks.

## Acceptance
- `pic_uid=../../etc/passwd` → 404/refusal, no read outside the cache.
- `width=100 --flag` → rejected (non-integer).
- N consecutive login failures → throttled/locked.
- A login debug log no longer contains the password.
- Credential comparison constant-time, single implementation (incl. service token).
- Client disconnect during a camera stream → no crash, no leak (ASan/valgrind).
- `get_cover` without `rotate` returns a response (no hang), and repeated calls succeed.
