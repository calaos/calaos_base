## Constats

### F6 — majeur : path traversal `event_picture`
`JsonApiHandlerHttp::processEventPicture` (`JsonApiHandlerHttp.cpp:932-935`) :
```cpp
string pic_uid = jsonParam["pic_uid"];
string file = Utils::getCacheFile("push_pictures") + "/" + pic_uid + ".jpg";
```
`pic_uid` est concaténé sans sanitisation puis servi via `buildHttpResponseFromFile`. `../` permet une lecture de fichier hors du cache (authentifié).
**Remédiation** : router via `FileUtils::resolveSafePath` (`FileUtils.cpp:158`, déjà utilisé pour `/app/` et `/debug/` — `HttpClient.cpp:290,342`).

### F7 — majeur : injection d'arguments `calaos_picture`
`processGetCameraPic` (`:482-487`) construit `cmd = ".../calaos_picture " + url + " " + tempfname + " -w " + width + " -r " + rotate`, splitté par espaces (`Utils::CStrArray`) puis `spawn`. `width`/`rotate` non validés → un `100 --flag x` injecte des argv. (spawn, pas de shell → pas de RCE classique, mais argument injection.)
**Remédiation** : valider `width`/`rotate` en entiers. Idem `processGetCover` / `processAudio get_cover`.

### F3 — majeur : pas de rate-limit/lockout sur login
Login HTTP (`:98`) et WS (`:113-138`) sans throttle ni verrouillage → brute-force du mot de passe admin.
**Remédiation** : compteur d'échecs par source + délai/backoff + lockout temporaire.

### F4 — majeur : secrets loggués avant auth
Les deux handlers dumpent le JSON complet avant auth (`JsonApiHandlerHttp.cpp:75-78`, `JsonApiHandlerWS.cpp:97-101`) → `cn_pass`, `token`, `old_pw`/`new_pw` en clair au niveau debug.
**Remédiation** : rédiger (`***`) les champs sensibles connus avant `cDebugDom`.

### F2 (login) — comparaison non constant-time + duplication
La comparaison des credentials utilise `operator!=` (non constant-time). Le bloc de lookup credentials est copié **3 fois** (`JsonApiHandlerHttp.cpp:88-96`, `JsonApiHandlerWS.cpp:116-124`, `JsonApi.cpp:1678-1686`).
**Remédiation** : centraliser dans `JsonApi::checkCredentials()` avec comparaison constant-time (`CRYPTO_memcmp`).

### F11 — majeur : fuite + UAF du stream caméra MJPEG
`processCamera` get_video (`:872-903`) : `m_signalComplete` remet `cameraDl = nullptr` **sans `delete`** (`:901`) → fuite. `downloadCameraPicture` (`:908-930`) se re-programme via `Timer::singleShot` capturant `this`/`camera` sans vérifier que la connexion existe encore → UAF si le client se déconnecte en cours de stream.
**Remédiation** : libérer correctement `cameraDl` ; garde « is-alive »/ownership sur le re-arm.

## Acceptance
- `pic_uid=../../etc/passwd` → 404/refus, pas de lecture hors cache.
- `width=100 --flag` → rejeté (non entier).
- N échecs de login consécutifs → throttlés/verrouillés.
- Log debug d'un login ne contient plus le mot de passe.
- Comparaison credentials constant-time, une seule implémentation.
- Déconnexion pendant un stream caméra → pas de crash ni de fuite (ASan/valgrind).
