## 1. Le constat

`MqttCtrl::getValueJson()` et `WebCtrl::getValueJson()` contiennent **le même parseur d'environ
55 lignes**, copié. La copie n'est plus exacte :

- ⭐ **Elles ont déjà divergé** — sur un **chemin vide**, MQTT rend la **charge brute**
  (`MqttCtrl.cpp:92-101`, branche explicite) tandis que Web rend **`""`** (chute du
  `if (!tokens.empty())`). Cette divergence est **figée par test** (T3.29,
  `AnEmptyPathReturnsTheRawPayload` / `AnEmptyPathReturnsEmpty`) : elle est **voulue ou non**, mais
  elle est **connue**, ce qui est le préalable à toute extraction.
- **Tous les défauts sont en double** :
  1. le plantage sur un jeton `[` (T3.35) — **deux fois** ;
  2. un index non numérique lisant l'**élément 0 en silence** (`from_string` dont le retour n'est
     pas regardé — famille T3.25) — **deux fois** ;
  3. `from_string` **hors du `try`** — **deux fois** ;
  4. le message d'échec sans indication (option C de T3.29) — **deux fois**.

⇒ **Une seule extraction fermerait les quatre d'un coup**, et supprimerait le risque qu'un
correctif soit appliqué à une copie et pas à l'autre.

## 2. Ce que la revue a validé

⚠️ **T3.29 a eu raison de NE PAS unifier** : figer la divergence par un test d'abord, unifier
ensuite. Ce ticket hérite de cette caractérisation ; il ne recommence pas le travail.

## 3. Le travail

1. Extraire `resolveJsonPath(const Json &root, const string &path)` — fonction **libre**, testable
   sans objet, sans broker et sans fichier (c'est ce qui coûte le plus cher aujourd'hui : la suite
   T3.29 doit construire un `MqttCtrl`, qui **spawn** `calaos_mqtt`, et écrire un fichier temporaire
   pour le côté Web).
2. **Décider explicitement du chemin vide** : uniformiser (et le dire dans `RELEASE_NOTES`) ou
   garder la divergence en la documentant. ⛔ **Ne pas la changer par accident** — le test la fige.
3. Les deux appelants deviennent des enveloppes (lecture du payload / du fichier + appel).

## 4. Les tests

`tests/JsonPathSyntax_test.cpp` (T3.29) est **écrit pour survivre à cette extraction** : chaque cas
est joué deux fois, une par copie, à travers l'API publique. La suite doit rester **verte au
caractère près** pendant l'extraction — c'est l'invariant du ticket. Ajouter ensuite les cas
directement sur la fonction libre, et **retirer alors** la construction de `MqttCtrl` du fixture.
