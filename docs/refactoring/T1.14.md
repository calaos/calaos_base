# T1.14 — Reolink driver lifecycle & log hygiene

| Phase | Type | Depends on | Status |
|---|---|---|---|
| 1 | fix | Phase 0 | 📋 Backlog |

## Owned files
- `src/bin/calaos_server/IO/Reolink/` (`ReolinkCtrl.{cpp,h}`, `ReolinkInputSwitch.{cpp,h}`, `ExternProcReolink_main.py`)

## Findings

### Major — lifetime: event callback captures `this` in the long-lived ctrl singleton
`ReolinkInputSwitch.cpp:90` — `ctrl->registerCamera(…, [=](…){ eventReceivedCallback(…); });` stores an `std::function` capturing `this` in the singleton `ReolinkCtrl` (`eventCallbacks`/`allRegistrations`). `ReolinkInputSwitch` has no destructor and `ReolinkCtrl` exposes no unregister, so a destroyed IO (config reload) leaves a dangling callback that fires on the next camera event → **UAF**. **Fix:** add an `unregisterCamera` path and a `ReolinkInputSwitch` destructor that removes the callback from the singleton.

### Major — security: Reolink logs plaintext camera credentials
`ExternProcReolink_main.py:1593` — `cDebugDom("reolink")(f"Received message: {message}")` logs every raw inbound message; the `register` message carries `username`/`password` in cleartext. The extern-proc logger forces DEBUG output, so passwords land in the Calaos log in normal operation. **Fix:** log only non-secret fields (action/hostname/event_type), or redact `username`/`password` before logging.

### Minor — correctness: dead `json_decref` on the parse-failure branch
`ReolinkCtrl.cpp:55` — inside `if (!jroot) { … if (jroot) json_decref(jroot); return; }`, the inner `if (jroot)` is always false (jroot is null here) → dead code. **Fix:** remove the unreachable decref.

### Minor — other: dead `heartbeat_monitor` + leftover `print()` debug (Python)
`ExternProcReolink_main.py:823` — `async heartbeat_monitor(self)` is defined but never scheduled (`setup()` only starts the other background tasks), so its `reconnect_tasks` cleanup never runs; `:143,:151` have leftover `print()` debug. **Fix:** schedule `heartbeat_monitor` in `setup()` or delete it; remove the `print()` statements.

## Acceptance
- Deleting a Reolink IO removes its callback from the ctrl singleton; a subsequent camera event does not hit freed memory (ASan).
- Reolink logs no longer contain plaintext `password`.
- Dead decref and dead `heartbeat_monitor`/`print` resolved.

## Verification
`make` with the Reolink driver; ASan on the Reolink IO create/delete cycle with a simulated event; grep the log for `password` after a register message (absent).
