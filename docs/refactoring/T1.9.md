# T1.9 — ExternProc framing (F13 + sockfd)

| Phase | Type | Depends on | Status |
|---|---|---|---|
| 1 | fix | Phase 0 | 📋 Backlog |

## Owned files
- `src/bin/calaos_server/IO/ExternProc.{cpp,h}`

## Findings

### F13 — minor (local boundary): framing bugs
`ExternProcMessage::processFrameData` (`ExternProc.cpp:304-317`) tests `if (data.size() >= 3)` then reads `data[0]..data[4]` (5 bytes) and `data.erase(0,5)`. With 3-4 buffered bytes, that is an **out-of-bounds** read (`data[4]` OOB for size 3). **Fix:** condition `>= 5`.

Other points on the same trust boundary (local Unix socket to spawned drivers):
- `payload_length` is a 32-bit value **with no cap**; `recv_buffer` buffers until fully received → a compromised/faulty subprocess can exhaust memory. **Fix:** cap `payload_length`.
- `ExternProcClient::connectSocket` (`:428`) does `strcpy` into `sockaddr_un.sun_path` with no 108-byte bound. **Fix:** bound (`strncpy` + guaranteed termination).

### New — major/correctness: `sockfd` used uninitialized in the destructor
`ExternProcClient::sockfd` is declared `int sockfd;` with no initializer (`ExternProc.h:152`); `connectSocket` returns early before assigning `sockfd` when the path is missing (`:412-416`), yet `~ExternProcClient` runs `if (sockfd >= 0) close(sockfd);` → closes an arbitrary descriptor. **Fix:** initialize `int sockfd = -1;` in the class declaration.

### New — minor/other: frame-format comment contradicts the implementation
`ExternProc.h:40` documents a START byte `0x2` and a 2-byte SIZE field, but `getRawData`/`processFrameData` write no START byte and encode a 4-byte (uint32) length. **Fix:** update the comment to the actual `1-byte opcode + 4-byte big-endian length + payload` wire format.

## Acceptance
- Test: a 3-4 byte buffer → no OOB read (condition `>= 5`).
- Oversized `payload_length` → rejected without unbounded allocation.
- Socket path > 108 bytes → cleanly truncated / errored, no overflow.
- A failed/absent connect no longer closes an arbitrary fd (`sockfd = -1`).
