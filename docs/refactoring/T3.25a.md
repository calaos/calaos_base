## 1. ⭐ La frontière d'API laisse encore passer le **débordement**, et la suite est un UB signé

**C'est le point qui a fait réécrire la note de version de `T3.25`.**

`T3.25` ferme la commande **tronquée** (`{"value":"impulse up "}`) : `set_state` refuse une valeur
qui finit sur son séparateur. Ce n'est **pas** le seul chemin.

```
{"value":"impulse up 99999999999999999999"}
```

- **franchit la frontière d'API** — la valeur ne finit pas par une espace, la garde de `T3.25` ne
  la voit pas ;
- `OutputShutter.cpp:110-116` fait `val.erase(0, 11)` puis `from_string(val, v)` : depuis `T3.25`
  le retour est **honnêtement `false`** — mais il est **ignoré**, et `v` vaut **`INT_MAX`**
  (saturation, cf. le tableau de contrat de `StringUtils.h`) ;
- `impulse_action_time` vaut donc `INT_MAX`, et `OutputShutter.cpp:216` calcule
  **`impulse_action_time + impulse_time`** : c'est un **débordement d'entier signé, donc un
  comportement indéfini**. Le scénario « grande valeur ⇒ course complète du volet » **reste
  ouvert par ce chemin**.

**Correctif recommandé par la revue — 2 lignes par grammaire, dans l'IO, après l'`erase`** :

```cpp
val.erase(0, 11);
if (val.empty() || !Utils::is_of_type<int>(val))
    return false;                 //ou le refus habituel de l'IO
```

Il couvre les **trois orthographes** (`impulse up `, `impulse down `, et la forme de
`OutputShutterSmart`) **sans rétrécir aucune API** : contrairement à la garde de `set_state`, il
ne touche pas les IO de type texte. La revue le juge « le correctif durable ».

⛔ **Pourquoi ce n'est pas fait dans `T3.25`** : `fix/t3.34` travaille **en ce moment** sur
`IO/OutputShutter.cpp`. `T3.25` n'a pas touché ce fichier, délibérément. **Cette recommandation
lui revient**, ou à un ticket qui passe après lui.

⚠️ Même famille, même argument, non traités : `OutputShutterSmart` ×7, `OutputLightDimmer` ×8,
`OutputLightRGB` ×10, `OutputLight`, `IntValue`, `JsonApi.cpp:1964/2057` (§2 de `T3.25`).

## 2. `InputAnalog` — la période de scrutation, trouvée en fermant la précision

Trouvé en fermant `InputAnalog.cpp:119` (`precision`), **non listé par la revue**, même forme
exacte :

```cpp
    if (get_params().Exists("interval"))
        Utils::from_string(get_param("interval"), frequency);      // :103
    else if (get_params().Exists("period"))
    {
        Utils::from_string(get_param("period"), frequency);        // :107
        frequency /= 1000.0;
    }
    else
        frequency = 15.0;
```

`double frequency;` est un membre **sans initialiseur en-classe** (`InputAnalog.h:35`), et
`Exists()` prouve que la clé est là, **pas qu'elle porte un nombre**. Un `interval=` ou un
`period=` **présent et vide** donne donc une période de scrutation de **0 seconde**.

⛔ **Pourquoi ce n'est pas fait ici** : ce site **ne se répare pas** par un simple
`from_string_or_keep()`. La division `/= 1000.0` doit être conditionnée à la réussite de la
lecture, et `from_string_or_keep()` rend `false` **aussi** sur une lecture partielle réussie
(`"15000abc"` → 15000). Le corriger correctement demande de restructurer les trois branches et de
décider ce que vaut une période partiellement lisible — une décision, pas une substitution
mécanique. `T3.25` a fermé `precision` (substitution mécanique) et s'arrête là.

**Ce qu'il faudrait** : écrire le défaut `15.0` **avant** les branches, et distinguer explicitement
« rien de lisible » (garder 15) de « lu » (diviser).

## 3. La dette de fond, rappelée pour qu'elle ne se perde pas

`T3.25` a rendu **définies** toutes les destinations (`from_string` écrit sur tous les chemins).
Il n'a **pas** initialisé les destinataires eux-mêmes. Les locales sans initialiseur lisent
désormais **0** au lieu d'ordures : **le danger est tombé, la laideur reste**. → **[T3.35](T3.35.md)**.

**Sites bénins vérifiés par la revue, à NE PAS « corriger »** — les rouvrir serait du bruit :

| Site | Pourquoi c'est bénin |
|---|---|
| `DataLogger.cpp:139` | tous les consommateurs testent `== 2`, jamais autre chose |
| `IO/OutputShutter.cpp:64` | le cache est **toujours** réécrit avant lecture |
| `IO/Wago/WODaliRVB` `red`/`green`/`blue = -1` | `split(max=0)` **ne produit pas** de jeton vide |

## 4. Acceptation

1. La commande `{"value":"impulse up 99999999999999999999"}` est **refusée** (ou bornée), et un
   test l'épingle sur le **vrai transport**, pas seulement sur la primitive.
2. `impulse_action_time + impulse_time` ne peut plus déborder — démontré, pas affirmé.
3. `InputAnalog` : `interval=` / `period=` vides gardent **15 s**, et une lecture partielle a un
   comportement **écrit**.
4. La note de version de `T3.25` (§ « Ce que cette version ne corrige PAS ») est **mise à jour**
   quand le point 1 est fermé.
