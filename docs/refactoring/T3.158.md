# T3.158 — `WAGO_DALI_GET` dérive son drapeau de groupe de l'ADRESSE, en 1.7–2.3

**Statut** : 📋 · **Type** : fix · **Phase** : 3
**Origine** : trouvé en instruisant [T3.156](T3.156.md), 2026-09-07, à la relecture des huit
programmes automate de `calaos_wago`. ⛔ **Le correctif est dans l'AUTRE dépôt** (`calaos_wago`),
pas dans `calaos_base`.

---

## 1. Le défaut

Dans le gestionnaire `WAGO_DALI_GET` des sept versions **1.7 à 2.3** :

```pascal
p2 := GET_PARAM_DINT(cmd, 2); (* Short addr *)
...
IF (p2 = 1) THEN
    dali_group := TRUE;
ELSE
    dali_group := FALSE;
END_IF
```

`p2` est **l'adresse courte**, pas un drapeau. Un luminaire à l'adresse **1** y pose donc
`dali_group := TRUE`. Le même bloc, dans `WAGO_DALI_SET`, lit bien `p2` **qui y est** le drapeau —
c'est un copier-coller entre deux commandes dont les positions de paramètres diffèrent, et le
programme porte le commentaire hésitant `(* Short addr or group? *)` aux deux endroits.

## 2. ⚠️ La gravité réelle est plus faible que la lecture au premier abord

**C'est une écriture morte dans ces sept versions.** Balayage complet des extractions : après ces
lignes, `dali_group` n'est relu **nulle part** sur le chemin de réponse de `WAGO_DALI_GET`. Son
seul lecteur est `Dali_switch(xGroup := dali_group)`, **dans le gestionnaire `WAGO_DALI_SET`**, qui
réaffecte la variable juste avant de s'en servir dans le même cycle. Aucun luminaire n'est donc
**observablement** relu comme un groupe en 1.7–2.3.

⇒ Le défaut est réel **dans le code**, latent **dans le comportement**.

## 3. ⭐ La 3.0 l'a déjà corrigé, sans le dire

En 3.0 le gestionnaire lit `p3 := GET_PARAM_DINT(cmd, 3); (* Short addr or group? *)` et teste
`IF (p3 = 1)`. Le drapeau y est un vrai paramètre, et `dali_group` y est **relu** pour choisir
entre `DaliSendValueGrp647[]` et `DaliSendValue647[]`. C'est ce déménagement de `p2` vers `p3` que
le serveur n'avait jamais suivi — [T3.156](T3.156.md).

## 4. Ce qu'il faut faire

Retirer le bloc `IF (p2 = 1)` du gestionnaire `WAGO_DALI_GET` des sept versions maintenues, ou le
faire porter sur `p3` comme en 3.0. **Aucune ligne de `calaos_base` n'est concernée.**

⚠️ **Ne pas le faire sans lire [T3.159](T3.159.md)** : le même gestionnaire, dans les mêmes
versions, a une seconde dépendance sur les paramètres absents, et elle **n'est pas** une écriture
morte.

## 5. ⛔ Le nu

Lecture d'une extraction `strings` d'un binaire CoDeSys : la continuité du source n'est pas
garantie, donc « `dali_group` n'est relu nulle part » est un **balayage des lignes extraites**, pas
une preuve de portée. Rien n'a été exécuté sur un automate.
