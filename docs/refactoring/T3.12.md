# T3.12 — 🔴 URGENT : patcher les 2 CVE TinyXML atteignables

**Type** : fix (sécurité, URGENT) · **Phase** : 3 · **Indépendant de la migration pugixml**

## Pourquoi c'est urgent
Le TinyXML vendored est en **2.5.3** et porte **deux CVE vivantes**, atteignables **aujourd'hui**
depuis un endpoint HTTP hostile : `IO/Web/WebCtrl.cpp:343-357` (`getValue()`) télécharge une URL
distante dans `/tmp/calaos_<id>` puis la parse (`:249`). **C'est le seul site de parsing XML non
fiable de calaos** (les deux autres, `CalaosConfig.cpp:128` et `ConfigStore.cpp:541`, sont de la
config locale).

| CVE | Site | Bug | Effet |
|---|---|---|---|
| CVE-2023-34194 (7.5) | `src/lib/TinyXML/tinyxmlparser.cpp:1605-1606` | `TiXmlDeclaration::Parse` appelle `StringEqual` après `SkipWhiteSpace` sans revérifier `p` → `assert(0)` | **`abort()` du serveur** — `config.h:111` a `/* #undef NDEBUG */`, les asserts sont **actifs** |
| CVE-2021-42260 (7.5) | `src/lib/TinyXML/tinyxmlparser.cpp:267-279` | `Stamp()`, `case TIXML_UTF_LEAD_0` : `p` n'avance pas sur une séquence UTF-8 tronquée | **boucle infinie** |

Le durcissement T2.4 (`loadXmlDocument`) **ne protège pas** : il n'enveloppe que le chemin de
config, et un `abort()`/hang n'est pas une erreur de parsing rattrapable.

## Travail (fichier : `src/lib/TinyXML/tinyxmlparser.cpp` uniquement)
1. **CVE-2023-34194** (+4 lignes) : revérifier `p`/fin de buffer après `SkipWhiteSpace` avant
   `StringEqual` dans `TiXmlDeclaration::Parse`. La correction Debian
   (`2.6.2-6+deb12u1`) est **exactement** ce patch — s'en inspirer.
2. **CVE-2021-42260** (+6 lignes) : faire avancer `p` dans `Stamp()` sur séquence UTF-8
   tronquée pour garantir la terminaison.
3. Tests de régression : XML malformé déclenchant chacun des deux cas → parsing échoue
   proprement (pas d'abort, pas de hang). Timeout de test explicite pour le cas boucle infinie.

**Note** : la copie vendored est **déjà un fork local** (commits `5c49f066`, `70617f92`,
`d7a7a687`) — patcher sur place a un précédent et zéro coût de resynchro upstream.
Ce ticket reste utile même si E4.4 (pugixml) aboutit : il ferme le trou **maintenant**, la
migration prendra des semaines.

## Acceptation
`make check` vert + les 2 tests de régression ; les deux motifs de code vulnérables ont disparu.
