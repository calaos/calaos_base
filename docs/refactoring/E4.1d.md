## ⭐ Pourquoi ce ticket est le moins risqué de la série : le sens du flux

Ces deux drivers parlent à des **tiers** (LMS, pont Philips Hue) — mais **uniquement en lecture**.
Aucun des deux ne **construit** de JSON à destination du tiers :
- `Squeezebox.cpp` : `json_loads()` de la réponse, navigation `result.remoteMeta.artwork_url`, et
  **un seul** `json_dumps` (`:786`) dont la sortie va dans `cDebug()` — **une trace de log, pas un
  wire**.
- `HueOutputLightRGB.cpp` : `json_loads()` de `downloadedData`, lecture de `state.{sat,bri,hue,on,reachable}`.
  **Aucun `json_dumps`.** Les requêtes vers le pont sont construites en concaténation de chaînes,
  pas en JSON.

⇒ **La décision d'échappement (`ensure_ascii`) ne s'applique à rien ici.** Le seul changement
observable possible serait une différence de **tolérance de parsing**, traitée ci-dessous.

## Travail

Remplacer `json_loads` par `Json::parse(..., nullptr, /*allow_exceptions=*/false)` et les
accesseurs par les helpers nlohmann. Le `json_dumps` de log devient
`.dump(4, ' ', true, Json::error_handler_t::replace)`.

⛔ **Le piège du parsing** : `json_loads()` rend `NULL` sur entrée malformée et **tout le code
d'aval teste ce `NULL`**. `Json::parse()` **lève** par défaut. Un `parse()` nu dans un callback de
téléchargement **remonte l'exception dans la boucle d'événements** — même famille de faute que le
`terminate` d'E4.0, cause différente. **Utilise systématiquement la forme non levante** et teste
`is_discarded()` là où le code testait `!jroot`.

⚠️ Différence de tolérance mesurable, à ne pas laisser passer en silence : `json_loads` avec flags
`0` refuse une **racine scalaire** ; `Json::parse` l'accepte. Un tiers qui répondrait `null` ou
`"ok"` passerait désormais le premier garde. Garde un `is_object()` explicite là où le code testait
`json_is_object()` — le contrat de garde doit rester **exactement** celui d'aujourd'hui.

## Pièges propres

- `json_integer_value()` sur une clé **absente** rend `0` sans broncher (jansson rend `NULL`, la
  fonction rend 0). `j["sat"].get<int>()` sur clé absente **lève**. `HueOutputLightRGB.cpp:82-84`
  lit `sat`/`bri`/`hue` **sans vérifier leur présence** : la bascule mécanique transforme un `0`
  silencieux en exception dans un callback asynchrone. **Utilise `j.value("sat", 0)`.**
- `jansson_bool_get()` (`Jansson_Addition.h`) rend `default_value` si la clé n'est pas un booléen.
  Reproduis ce contrat exactement — pas `get<bool>()`.

## Acceptation vérifiable

1. Les deux fichiers ne contiennent plus le mot `jansson` ni `json_` (hors `json.hpp`).
2. **Un test neuf par fichier**, sur la fonction de décodage extraite ou appelée directement, avec
   au minimum : réponse bien formée · réponse malformée · racine non-objet · clé attendue absente ·
   clé présente au mauvais type. Chacun doit rendre **le même résultat qu'aujourd'hui**.
   Écris-les **avant** de toucher `src/` et vérifie qu'ils passent sur le commit d'origine.
3. Contre-mutation **par échange** : dans le test Hue, échanger `sat` et `bri` dans la réponse doit
   faire rougir — sinon le fixture est trop pauvre (`sat == bri` est le piège exact des 7 récidives).
4. `make check` vert en distclean, compte ≥ master. **Zéro golden modifié.**

## Méthode (rappel, non négociable)

Commit de **caractérisation d'abord** (tests seuls, **zéro `src/`**, vérifié commit par commit) ·
**contre-mutation PAR ÉCHANGE**, jamais par neutralisation · piège du **« fixture pauvre »** :
**7 récidives dans E4.0, toutes trouvées par les relecteurs, jamais par les implémenteurs** · une
**assertion d'absence** n'a de valeur que si le canal a été **flushé** · **ne recopie pas un
pompage que tu n'as pas mesuré** (3 des 6 rustines historiques n'absorbaient rien) · une **sonde de
test doit être une valeur qui ne peut pas devenir valide** · piège **`_DEPENDENCIES` variante faux
ROUGE** : `make distclean` avant de conclure · **zéro golden modifié** sauf déclaration explicite
et argumentée.

## Pièges de bascule communs à toute la série (mesurés par E4.0, ne pas redécouvrir)

- **Tout part en chaîne** : 32 `json_string`, **zéro** `json_real`/`json_integer` dans
  `JsonApi.cpp` ; seul `eventlog` émet de vrais entiers. **Un `int` devenu nombre JSON est une
  rupture de contrat** — l'oracle des tests est **type-strict** (`3 != "3"`).
- **`Utils::to_string(double)`** est un `ostringstream` nu (`1234.56789` → `"1234.57"`,
  `123456789.0` → `"1.23457e+08"`), épinglé par des goldens. **Ne le « corrige » pas.**
- **Clé absente ≠ `null`** : `buildJsonIO` **omet** une clé absente. Épinglé.
- **`Params` est un `std::map`** → itération **alphabétique**, jamais d'insertion.
- **Les trois invariants d'émission** (E4.1b) : clés triées · `ensure_ascii = true` ·
  `error_handler_t::replace`. Les trois vont ensemble sur chaque `dump()`.
