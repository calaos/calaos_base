## 1. Les trois défauts, revérifiés au source (2026-08-25)

`IO/Wago/WagoCtrl.cpp:152-176` (`write_multiple_bits`) et son jumeau `:220-242`
(`write_multiple_words`). **Les références de `FINDINGS.md` sont exactes** sauf une : elle situe
`setBit()` à `:50-58`, il est à **`:51-60`**. Corrigé.

```cpp
152| bool WagoCtrl::write_multiple_bits(UWord address, int nb, vector<bool> &values)
153| {
154|     if (!is_connected()) return false;
155|
156|     mbus_ubyte *data = new mbus_ubyte[nb / 8 + nb % 8];
157|     memset(data, '\0', nb/8);
158|
159|     for (int i = 0;i < nb;i++)
160|         setBit(*data, i, values[i]);
```

### (a) `nb` n'est jamais confronté à `values.size()` — et ce n'est pas « n'écrit rien »

`nb` vient du **message**, `values` du **tableau décodé**. Avant E4.1h, `values` arrivait **vide**
et `nb` valait le compte annoncé. ⭐ **La revue d'E4.1h a mesuré ce que cela fait : `values[0]` sur
un `vector<bool>` vide SEGFAUTE** — SIGSEGV **139**, `_M_start` nul. Ce n'était donc pas une
écriture qui ne partait pas : c'était **la mort de `calaos_wago`**, si le chemin avait été atteint.

⚠️ **E4.1h a corrigé l'émission, PAS ce défaut-ci.** Le message porte désormais son tableau
(`WagoWire::buildWriteBitsRequest()`), donc `values` arrive peuplé — mais **rien** dans
`WagoCtrl` ne vérifie que `nb == values.size()`. La correction rend le défaut inoffensif pour un
appelant qui se tient bien ; elle ne le referme pas.

Le jumeau `:224-226` a la **même** forme : `data[i] = values[i]` pour `i ∈ [0, nb)`, sans garde.

### (b) ⭐ `setBit()` prend une référence à **UN SEUL octet**

`WagoCtrl.cpp:51-60` :
```cpp
void WagoCtrl::setBit(unsigned char &mot, int pos, bool val)
{
    if (val)
        mot = mot | (0x01 << pos);
    ...
}
```
L'appelant passe **`*data`**, c'est-à-dire **toujours `data[0]`**, avec `pos = i` jusqu'à `nb-1`.

Deux conséquences :
- **seuls les bits 0 à 7 sont jamais écrits** — une écriture multiple de plus de 8 bits est
  fausse **même avec `values` livré** ;
- **`pos ≥ 32` est un comportement indéfini de décalage** (`0x01` est un `int`).

⭐ **Et le bon code est déjà dans le fichier, deux fonctions plus haut.** `read_bits()`,
`WagoCtrl.cpp:100-101` :
```cpp
    for (int i = 0;i < nb;i++)
        values.push_back(getBit(*(data + i / 8), i % 8));
```
`data[i/8]` et `i % 8`. **La lecture est correcte, l'écriture ne l'est pas** — c'est le meilleur
argument du ticket : il n'y a rien à inventer, seulement à recopier.

### (c) Le dernier octet du tampon part non initialisé

`:156-157` : `new mbus_ubyte[nb / 8 + nb % 8]` puis `memset(data, '\0', nb/8)`. **Le `memset` est
plus court que l'allocation.** Pour `nb = 17` → **3** octets alloués, **2** mis à zéro : le
troisième part vers l'automate avec de la mémoire arbitraire dedans.

⚠️ **Ce n'est pas un dépassement de tampon** : `nb/8 + nb%8` **sur-dimensionne** souvent
(`nb = 15` → 8 octets pour 2 nécessaires). L'expression correcte est `(nb + 7) / 8`.
`read_bits()` `:95-97` a **la même expression d'allocation** — mais son `memset` couvre bien
`data_size` entier, donc elle n'a que le sur-dimensionnement, pas l'octet sale.

## 2. Le travail

Un seul fichier, `IO/Wago/WagoCtrl.cpp`, et **les trois points ensemble** — corriger (a) seul
laisserait une fonction qui écrit faux, corriger (b) seul laisserait le segfault.

1. **Garde d'entrée** sur les deux fonctions : si `nb < 0` ou `(size_t)nb > values.size()`,
   `cError` + `return false`. **Refuser, pas tronquer** — tronquer enverrait à l'automate une
   écriture partielle qu'il ne saura pas distinguer d'une écriture complète.
2. **Réécrire la boucle de bits** : `setBit(data[i / 8], i % 8, values[i])`, sur le modèle exact
   de `read_bits()` `:100-101`.
3. **`(nb + 7) / 8`** pour l'allocation, `memset` sur **toute** l'allocation, dans les **deux**
   fonctions **et** dans `read_bits()` (la sur-allocation y est bénigne mais l'expression fausse
   se recopie).
4. Envisager de faire de `setBit()` une fonction qui prend le **tampon et l'index de bit**
   (`setBit(unsigned char *buf, int bit, bool val)`) plutôt qu'un octet et une position : la
   signature actuelle **invite** l'erreur. C'est la même leçon que **T3.31** — un trou de site
   d'appel se referme par la signature, pas par un test.

### ⚠️ Fixture pauvre — trois formes prévisibles ici, à écarter d'avance

1. **`nb` multiple de 8.** Avec `nb = 8` ou `16`, la frontière d'octet ne se voit pas, et le
   `memset` court ne laisse aucun octet sale (`nb%8 == 0` ⇒ allocation = `nb/8`). **`nb = 17` est
   le fixture qui mord** : 3 octets alloués, 2 memsettés, et le bit 16 doit atterrir dans le 3ᵉ.
2. **Toutes les valeurs à `true`** (ou toutes à `false`). Le tampon serait uniforme et une
   permutation de bits invisible. **Un motif non symétrique et non palindromique.**
3. **`nb == values.size()` partout.** C'est précisément le cas que (a) ne distingue pas.
   **Au moins un cas avec `nb != values.size()`**, dans les **deux** sens.

C'est la même leçon que **F-WAGO-6** — `FX_RCOUNT = 5` égalait `values.size()`, l'oracle était
mort, et c'est un relecteur qui l'a vu. **9 récidives dans la série, toutes trouvées par les
relecteurs.** Ne pas en offrir une dixième.

### Contre-mutation **par échange**
- Échanger `i / 8` et `i % 8` dans la boucle corrigée ⇒ rouge.
- Remettre `setBit(*data, i, …)` ⇒ `BitNineLands…` et `SeventeenBits…` rouges, **et eux seuls**.
- Remettre `memset(data, 0, nb/8)` ⇒ `SeventeenBits…` seul rouge.
- Retirer la garde (a) ⇒ les deux cas `…IsRefused` rouges.
**Quatre mutations, quatre ensembles DISTINCTS**, témoin sans mutation 0 rouge. Deux mutations qui
rendent le même ensemble = signature du piège `_DEPENDENCIES`, à traiter comme tel.

### ⚠️ Les cinq variantes du faux vert/rouge
`WagoBits.h` est un en-tête inclus par **deux binaires**. **Effacer le `.o` ET le binaire de test,
exiger la ligne `CXXLD <binaire>` dans le journal ET le code de sortie du binaire.** C'est le seul
contrôle qui attrape les cinq (faux ROUGE uniforme · faux VERT · faux ROUGE après rebase · faux
VERT total avec `check_PROGRAMS` non construit · faux VERT par mort du binaire ⇒ **aucune ligne
`FAILED`**). Un segfault dans un cas **ne produit aucune ligne `FAILED`** — ici c'est
particulièrement pertinent, le défaut *est* un segfault.

### 6.3 Épingler un SEGFAULT sans figer d'UB

**Aucun oracle de cette suite ne décrit un comportement indéfini.** Toutes les attentes écrivent
l'assemblage **correct** ; le seam livré meurt en essayant de l'atteindre, et c'est le **code de

### 6.4 Fixture — les trois formes de pauvreté écartées

`nb = 17` (**pas** un multiple de 8 : sur un multiple, `nb%8 == 0` fait coïncider allocation et
`memset`, et (b) comme (c) disparaissent) ; motif **asymétrique et non palindromique** à trois
octets **deux à deux distincts** `{0x8d, 0x1e, 0x01}` dont le **dernier NON NUL** (un `0x00`
final serait satisfait par un octet sale qui vaut zéro) ; comptes débordant `values.size()` dans
les **deux sens** ; et le tampon de sortie arrive **pré-sali** (`0xaa`), ce qui rend l'octet non
initialisé **déterministe** au lieu d'arbitraire. Les attentes sont écrites en littéraux, jamais
recalculées depuis le motif.
