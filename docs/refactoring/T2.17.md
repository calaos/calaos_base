# T2.17 — UrlDownloader : vérification TLS par défaut, insecure en opt-in explicite

**Type** : fix (sec)
**Phase** : 2

## Contexte

Item d'acceptation de T2.5 **volontairement différé** (FINDINGS wave 5) pour préserver
l'iso-comportement pendant la réécriture libcurl : `UrlDownloader` pose toujours
`CURLOPT_SSL_VERIFYPEER=0` / `CURLOPT_SSL_VERIFYHOST=0` globalement
(`UrlDownloader.cpp:543-544`, commentaire « insecure --> do not check ssl certificates,
needed for local https »). Tout HTTPS sortant du serveur — y compris notifications push,
mail, DataLogger, scripts Lua — accepte donc n'importe quel certificat : MITM trivial.

**Analyse des appelants** (grep 2026-08-15, `UrlDownloader` hors lib) :

- *Caméras locales en HTTPS auto-signé — le cas légitime d'insecure* :
  `IPCam/IPCam.cpp`, `IPCam/SynoSurveillanceStation.cpp`, `IPCam/Axis.cpp`,
  `IPCam/Planet.cpp`, `IPCam/Foscam.cpp`, et probablement `IO/Hue/HueOutputLightRGB.cpp`
  (bridge Hue local, cert auto-signé Philips).
- *Endpoints publics — doivent vérifier* : `NotifManager.cpp` (push/mail),
  `DataLogger.cpp`, `Calaos.cpp` (calaos.fr), `Audio/Squeezebox.cpp`, `Audio/AVRRose.cpp`,
  `JsonApiHandlerHttp.cpp`.
- *URL fournie par l'utilisateur — à trancher par config* : `IO/Web/WebCtrl.cpp`,
  `LuaScript/ScriptBindings.cpp`.

## Travail

Fichiers : `src/lib/UrlDownloader.{cpp,h}` + les appelants caméras/Hue listés ci-dessus
(un appel `setInsecure()` chacun) + tests.

1. Défaut : `VERIFYPEER=1` / `VERIFYHOST=2` (défauts libcurl — supprimer simplement les deux
   `setopt` à 0 et laisser le CA bundle système agir).
2. Ajouter `UrlDownloader::setInsecure()` (opt-in par appel, pas d'option globale) qui
   repose les deux options à 0 pour cette instance.
3. Appeler `setInsecure()` depuis les drivers caméras (`IPCam/*`) et Hue — ces devices
   locaux en cert auto-signé sont le risque de régression identifié ; ne PAS l'appeler
   depuis NotifManager/DataLogger/Calaos/Audio/JsonApiHandlerHttp.
4. Pour WebCtrl/ScriptBindings (URL utilisateur) : proposer à Raoul soit vérif stricte, soit
   un paramètre io/config `insecure="true"` par IO — **validation utilisateur requise**
   (changement de comportement, cf. DECISIONS contraintes permanentes).
5. Log clair en cas d'échec de vérification TLS (l'utilisateur doit comprendre pourquoi sa
   caméra ne répond plus et comment opter pour insecure si un chemin config est retenu).
6. Tests : instance par défaut → handshake refusé sur cert invalide ; `setInsecure()` →
   accepté (mock/serveur local du harnais T2.5/T2.10 si disponible).

## Acceptation

- Build docker + `make check` verts.
- Par défaut, un download HTTPS vers un cert invalide échoue avec une erreur explicite.
- Les caméras HTTPS auto-signées fonctionnent toujours (chemin `setInsecure()`).
- Aucun appelant hors caméras/Hue (et cas config validé) n'utilise `setInsecure()`.
