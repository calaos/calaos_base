# T2.19 — Option `insecure` par IO pour Web/Lua

**Type** : feature (validée utilisateur) · **Phase** : 2 (follow-up T2.17)
**Décision utilisateur (2026-08-15)** : depuis T2.17, les URLs utilisateur (IOs Web, scripts
Lua) sont vérifiées TLS par défaut — un endpoint HTTPS auto-signé échoue. Ajouter une
échappatoire explicite par IO.

## Travail
1. IOs Web : nouveau paramètre `insecure` (bool, défaut false) lu dans les mixins WebDocBase
   (T3.2d) et propagé au `UrlDownloader` de WebCtrl via `setInsecure()` ; entrée ioDoc
   (`paramAdd`) + doc régénérée si applicable.
2. Lua : équivalent pour les téléchargements initiés par ScriptBindings (option de l'appel ou
   du contexte — choisir la forme la plus simple cohérente avec l'API Lua existante).
3. Tests : parsing du paramètre + propagation du flag (niveau unité, pattern IOControllers).

## Fichiers
`src/bin/calaos_server/IO/Web/{WebDocBase.h, WebCtrl.*}`, `src/bin/calaos_server/LuaScript/`
(ScriptBindings), tests. Vérifier la disjonction avec les tickets en vol au lancement.

## Acceptation
Un IO Web avec `insecure="true"` télécharge depuis un endpoint auto-signé ; sans le param,
comportement vérifié (T2.17) inchangé ; `make check` vert.
