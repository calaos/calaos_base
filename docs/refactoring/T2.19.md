# T2.19 — TLS : insecure par défaut + param `insecure` par device

**Type** : fix de politique (décision utilisateur 2026-08-15, SUPERSÈDE le défaut T2.17)
**Phase** : 2 (correctif post-T2.17)

## Contexte
T2.17 a mis « vérifié par défaut » — inacceptable pour le parc réel (caméras HTTPS
auto-signées, devices LAN). Décision : **insecure par défaut** pour toute URL configurée par
l'utilisateur, grandfathering des configs existantes ; l'opt-in de durcissement est
`insecure="false"` par device. Voir DECISIONS.md (entrée « TLS : insecure par DÉFAUT »).

## Travail
1. **Correctif immédiat des défauts** : repasser en `setInsecure()` par défaut tous les
   consommateurs d'URLs utilisateur laissés « vérifiés » par T2.17 : WebCtrl, Lua
   ScriptBindings, DataLogger (influx), Squeezebox, AVRRose. Restent vérifiés UNIQUEMENT les
   URLs codées en dur calaos.fr (NotifManager push, update checks).
2. **Param par device `insecure`** (défaut **true**) : caméras (IPCam base — remplace le
   setInsecure inconditionnel), Hue, IOs Web (mixins WebDocBase → WebCtrl), et forme adaptée
   pour Lua/DataLogger si une config existe. Entrées ioDoc + doc régénérée.
3. Tests : défaut true sans param ; `insecure="false"` → transfert vérifié ; hardcodés
   calaos.fr toujours vérifiés.

## Acceptation
Une config d'installation existante (sans aucun param `insecure`) a un comportement TLS
identique à AVANT T2.17 sur tous les chemins device ; `insecure="false"` durcit par device ;
`make check` vert. Tâche EXTERNE liée (hors repo) : calaos_installer écrira
`insecure="false"` pour les nouveaux devices.
