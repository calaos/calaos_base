⚠️ **Et ce que ce script engendre est un produit de construction NON SUIVI** : il écrit dans

`data/doc/{en,fr}/io_doc.json` est **commité** — et ⛔ **rien ici n'accomplit ni ne surveille cette

## 2. Ce qui est MESURÉ — ce que la régénération armerait

⚠️ **Les ancres de ce paragraphe sont dans un AUTRE dépôt, `calaos_installer`** (lues et vérifiées
une à une dans `/home/raoul/repos/calaos/calaos_installer`). ⛔ **Rien n'y a été modifié** ; ce ticket
décrit un travail à faire là-bas, il ne le fait pas.

`io_doc.json` n'est pas une aide en ligne : c'est le **schéma de widget**. `WidgetIOProperties` en
construit le champ de saisie, et l'ordre est ce qui compte —

- `src/WidgetIOProperties.cpp:163-167` : `w->setMaximum(jparam["max"]…)` **puis**
  `w->setValue(pvalue.toInt())`. Le plafond est posé **avant** la valeur, donc Qt borne
  silencieusement : un luminaire déclaré à **612** sous un `max=355` **affiche 355**.
- `src/WidgetIOProperties.cpp:175-178` : `valueChanged` → `updateChangedParam(prop, w->value(), …)`.
  **Un seul** `valueChanged` — le premier geste sur ce champ — inscrit **355** dans les paramètres
  modifiés.
- `src/formrules.cpp:2244` : `*p = dialog.getParams();` — les paramètres du dialogue **écrasent**
  ceux de l'IO, et `io.xml` est réécrit.
- `src/WidgetIOProperties.cpp:180-183` : le bouton d'annulation ne fait que `w->setValue(612)`, qui
  est **re-borné à 355** ; la valeur ne change pas, **aucun signal n'est émis**, rien ne revient à
  612. ⭐ **Le bouton est mort sur ce champ.**

⇒ Ce n'est pas ce que l'installateur **propose**, c'est ce qu'il **réécrit** : une configuration qui
fonctionnait perd son adresse sans que personne l'ait demandé, et sans recours dans le dialogue.

## 3. Ce que la garde doit faire

⛔ **Rien n'est tranché ici** : ce ticket ouvre l'arbitrage, il ne le rend pas. Les formes possibles,
telles que les ancres du §2 les permettent :

- **une garde** : ne pas borner à l'affichage une valeur déjà hors plage — élargir le plafond du
  widget à la valeur courante quand elle le dépasse, et signaler plutôt que réécrire ;
- **une migration** : convertir explicitement les adresses 356..612 existantes, en le disant, plutôt
  que de les laisser tomber sur le premier clic ;
- ⚠️ et, dans les deux cas, **rendre le bouton d'annulation vivant** sur un champ borné — il est mort
  pour toute valeur hors plage, pas seulement pour les adresses DMX.

## 4. Ce qu'un cas devra prouver

Qu'un IO dont l'`io.xml` porte une adresse **au-delà** du `max` du schéma **ressort inchangé** d'un
aller-retour dans le dialogue quand l'utilisateur ne touche pas ce champ, **et** qu'il ressort
inchangé même après un geste sur un **autre** champ du même dialogue — sinon le cas ne mesure que la
moitié qui l'arrange. ⛔ **Ce cas s'écrit dans `calaos_installer`, pas ici** : `calaos_base` n'a aucun
chemin qui lise cette borne (mesuré en [T3.244](T3.244.md) §0).
