# T3.54 — `setBufferBit(unsigned char *buf, int bit, bool val)` : `int` ↔ `bool` dans les DEUX sens

## 1. Le trou

`src/bin/calaos_server/IO/Wago/WagoBits.h:114` :

```cpp
inline void setBufferBit(unsigned char *buf, int bit, bool val)
{
    unsigned char &byte = buf[bit / 8];
    const unsigned char mask = (unsigned char)(0x01u << (bit % 8));
    if (val) byte = (unsigned char)(byte | mask);
    else     byte = (unsigned char)(byte & (unsigned char)(~mask));
}
```

`int` et `bool` se convertissent **dans les deux sens** en silence. Les deux paramètres sont
**adjacents** et **nus** : `setBufferBit(buf, val, bit)` **compile sans un mot**.

⭐ **Les DEUX membres sont lus** — `buf[bit / 8]`, `0x01u << (bit % 8)`, puis `if (val)`. Ce n'est
donc **pas** le no-op sémantique que T3.50 a mesuré sur `(address, count)` : ⛔ **une permutation
change le programme** — même classe que **F-WAGO-10**.

⚠️ **Et la permutation est PIRE qu'un simple échange de rôles** : `bool val` reçoit un index
(`i` ≠ 0 ⇒ `true`) et `int bit` reçoit un booléen (0 ou 1) ⇒ **tous les bits demandés s'écrivent
dans le bit 0 ou le bit 1 du premier octet**, et la trame modbus part fausse à l'automate.
