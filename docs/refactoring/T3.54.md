## 1. Le trou

`IO/Wago/WagoBits.h`, avant :

```cpp
inline void setBufferBit(unsigned char *buf, int bit, bool val)
{
    unsigned char &byte = buf[bit / 8];
    const unsigned char mask = (unsigned char)(0x01u << (bit % 8));
    if (val) byte = (unsigned char)(byte | mask);
    else     byte = (unsigned char)(byte & (unsigned char)(~mask));
}
```

`int` et `bool` se convertissent **dans les deux sens** en silence, les deux paramètres sont
**adjacents**, **nus**, et **tous deux lus**. `setBufferBit(buf, val, bit)` compilait sans un mot :
`bool val` recevait un index (`i` ≠ 0 ⇒ `true`), `int bit` recevait un booléen ⇒ **tous les bits
demandés s'écrivaient dans le bit 0 ou le bit 1 du premier octet**, et la trame modbus partait
fausse à l'automate.

## 4. La forme retenue — **celle de [T3.53](T3.53.md), sans variante**

Deux structures d'**un champ**, **`explicit`**, **par valeur**, **aucune base commune**, **aucune
conversion de retour** : la forme W1/W4/W6 mesurée par [T3.31](T3.31.md), reprise par T3.53 §7.1.
⭐ **Aucune forme concurrente n'a été introduite** — ni `enum class`, ni `using` fort, ni type
paramétré : deux formes différentes pour la même classe de défaut coûteraient plus qu'une seule
imparfaite.

| | avant | après |
|---|---|---|
| définition | `(unsigned char *, int bit, bool val)` | `(unsigned char *, BitIndex bit, BitState val)` |
| l'appel de `packBits` | `setBufferBit(&out[0], i, values[i])` | `setBufferBit(&out[0], BitIndex(i), BitState(values[i]))` |

⭐ **Une seule divergence avec T3.53, et elle est délibérée : le LIEU.** T3.53 a posé ses deux types
dans `WagoTypes.h`, aux côtés des quatre de T3.31. Ici ils vivent **dans `WagoBits.h`**, parce que
cet en-tête **ne dépend que de `<vector>`** — c'est écrit en tête de sa propre documentation, et
c'est **ce qui permet à `WagoBits_test` de ne lier aucun objet serveur** et de rester ainsi hors du
piège `_DEPENDENCIES`. Inclure `WagoTypes.h` (qui tire `Utils.h`) aurait échangé une paire fermée
contre une dépendance ouverte. La **forme** est celle de T3.53 ; seule l'**adresse** change.

## 5. Le filet neuf — 2 cas, dans la suite existante

Ils demandent au système de types, pas au comportement — le comportement, lui, est déjà tenu par
les 5 cas du §3 :

- la permutation des deux arguments **ne type-checke plus** ;
- une paire `(int, bool)` **nue** n'atteint plus la fonction — c'est le trou du « second appelant » ;
- `explicit` des deux côtés, aucune conversion entre les deux types, aucune conversion de retour.

⚠️ **Les six façons dont un test peut mentir, prises une par une :**

| piège | ce qui le désamorce ici |
|---|---|
| **appel direct** | le comportement n'est **pas** re-testé au grain de `setBufferBit` : il reste exercé **à travers `packBits`**, par les 19 cas d'origine |
| **nom orthographié** | les deux types sont **lus DANS la signature livrée** (`SetterArgs<decltype(&WagoBits::setBufferBit)>`), jamais nommés ⇒ un renommage **casse le build** au lieu de désarmer les cas |
| **longueur mal bornée** | sans objet ici (aucun plafond) |
| **fixture fausse** | la fixture d'origine est conservée : 17 bits, non multiple de 8, motif non palindrome, trois octets deux à deux distincts, **dernier octet non nul** |
| **présence au lieu de position** | les oracles d'origine sont des **littéraux d'octets** (`0x8d, 0x1e, 0x01`), pas un recalcul de l'algorithme |
| **le foin qui exclut l'aiguille** | ⭐ **chaque `EXPECT_FALSE` est apparié à un contrôle qui doit rester VRAI** — un étalon local `(int, bool)` qui doit rester permutable, l'ordre correct qui doit rester accepté, un enrobage implicite et un enrobage fuyant. Contre une fonction qui n'accepterait rien, tous les `EXPECT_FALSE` passeraient **gratuitement** |
