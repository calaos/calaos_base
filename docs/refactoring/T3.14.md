# T3.14 — Lecture pendante à l'extinction (statiques détruits puis réutilisés)

**Type** : fix (UB, extinction) · **Phase** : 3
**Origine** : reproduit et diagnostiqué pendant la validation des configs réelles.

## Symptôme
À la fermeture de `calaos_server`, TinyXML affiche :
`Parse error: Error document empty. In file <octets illisibles>/local_config.xml`
— le chemin est **corrompu** : octets binaires suivis de la fin lisible du vrai chemin.
Reproductible à chaque exécution.

## Cause (chaîne complète, vérifiée)
1. `src/lib/ConfigStore.cpp:51` : `static string _configBase`.
   `Utils::getConfigFile()` (`ConfigStore.cpp:127-142`) le lit **sans garde de durée de vie** ;
   appelé après que le destructeur de ce statique a tourné, il fait
   `_configBase + "/" + configType` sur un buffer libéré — les ~16 premiers octets sont les
   métadonnées tcache de l'allocateur, la queue de l'ancien chemin survit. D'où le symptôme.
2. Le déclencheur : `maxLevelPrintable()` (`src/lib/Logger.cpp:85`) cache les niveaux dans un
   `static unordered_map logger_domains` **local à la fonction**. Construit pendant `main`, il est
   détruit **en premier** dans la chaîne atexit ; `~_Hashtable` remet le compte à zéro, donc un
   `.empty()` ultérieur est vrai, **tout le bloc d'init se ré-exécute**, appelle
   `Utils::get_config_option("debug_level", true)` → `getConfigFile(LOCAL_CONFIG)` sur
   `_configBase` mort → `LoadFile()` échoue → `loadConfigDocument()` (`ConfigStore.cpp:539-549`)
   met en file « Parse error… », vidée avec `noLoggerOut=true` → écrit brut sur `cout`.
3. **Deuxième UB dans le même appel** : `static std::mutex configMutex` (`ConfigStore.cpp:210`)
   est verrouillé alors que son destructeur a tourné.
4. `LogSetup.cpp` (`calaosLogShuttingDown` / `freeLoggers()`) ne protège que l'allocation de
   `logger_hash` — **ni le cache de niveaux, ni le chemin de config**. C'est le trou.

**Généralisation** : tout log émis depuis un destructeur statique s'exécutant après les statiques
de `libcalaos_common` reproduit le problème. Reproduit par un programme minimal linkant
`libcalaos_common.a` avec un statique de TU exécutable dont le destructeur logge.

## Travail (fichiers : `src/lib/ConfigStore.cpp`, `src/lib/Logger.cpp`, `src/lib/LogSetup.*`)
Deux approches, choisir et justifier :
- **Statiques immortels** : `_configBase`, `_cacheBase`, `configMutex`, `logger_domains`,
  `logger_hash`, `default_domain` alloués sur le tas et jamais détruits
  (`static T &x() { static T *p = new T(); return *p; }`). Supprime la classe entière de bugs.
- **Sortie anticipée** : `maxLevelPrintable()` renonce dès que `calaosLogShuttingDown` est posé,
  au lieu de relire la config. Plus ciblé, mais ne protège que ce chemin-là.

⚠️ Ce ticket est **indépendant de la migration pugixml** : le message vient de TinyXML
aujourd'hui, mais la lecture pendante est dans notre code et survivra au portage.

## Acceptation
`make check` vert ; plus aucun message parasite à l'extinction ; idéalement un test reproduisant
le motif (statique de TU dont le destructeur logge) qui échouait avant.
