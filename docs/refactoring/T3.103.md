# T3.103 — `calaos_mqtt` sort avec le code 0 et sans une ligne quand le courtier est injoignable

**Statut** : 📋 · **Type** : fix (robustesse, diagnostic) · **Phase** : 3
**Dépend de** : — (préexistant, antérieur à la série) · **Origine** : `F-EXTPROC-9`, mesuré en
écrivant [`T3.82`](T3.82.md) **sur le binaire livré**, puis confirmé verbatim à sa revue de merge.

---

## 1. La chaîne, mesurée

`MqttProcess` enregistre le descripteur de mosquitto par `appendFd()` et **ne le retire jamais**.
Quand la connexion TCP échoue **après** que `connect_async()` a répondu `MOSQ_ERR_SUCCESS` — c'est
le cas de **tout courtier éteint** — la bibliothèque ferme ce descripteur ; le `select()` d'
`ExternProcClient::run()` rend **`EBADF`**, la boucle sort, et `procMain()` répond **0**.

Mesuré : `EXIT=0` à 23 ms sur `192.0.2.42:1883`, **une seule ligne de journal en tout**.

## 2. Pourquoi c'est la pire forme du trou d'E4.5d

Le serveur relance sans backoff. Le sidecar n'écrit rien — il n'a pas d'erreur à publier, puisqu'il
croit être sorti normalement. Le serveur ne regarde pas le statut de sortie.

⭐ **Précisé à la revue de merge de [`T3.82`](T3.82.md)** : « muette » ne vaut que pour le sidecar.
`MqttCtrl` imprime `process exited, restarting...` à **WARNING**, donc **imprimé sur un boîtier
neuf**, **à chaque tour** — soit une dizaine de lignes par seconde. ⛔ **Ce n'est donc pas un
silence : c'est du bruit sans cause**, ce qui est plus long à diagnostiquer qu'un silence complet.

## 3. Second défaut, même site

Le diagnostic de l'autre branche appelle `strerror()` sur un code `MOSQ_ERR_*` et non sur un
`errno`. Mesuré : un port refusé donne `Error connecting : Bad address` — un message qui **désigne
la mauvaise cause**.

## 4. Ce qu'il faudra épingler

- Un courtier injoignable produit un **code de sortie non nul** et **une ligne nommant la cause**.
- Le descripteur est retiré de la boucle quand la bibliothèque le ferme.
- Le message d'erreur de connexion nomme la vraie cause (table `MOSQ_ERR_*`, pas `strerror`).
- ⭐ Le serveur devrait **regarder le statut de sortie** : aujourd'hui il relance à l'identique quel
  qu'il soit. C'est le vrai levier, et il dépasse MQTT.

## 5. ⛔ Nu

- Aucun courtier réel : la mesure utilise une adresse de documentation et un port refusé.
- Le backoff absent (E4.5d) reste hors périmètre — ce ticket rend la panne **visible**, il ne la
  ralentit pas.
- `T3.82` n'a pas touché ces deux défauts : elle a déplacé le `switch` sans le modifier.
