# T3.13 — TimeRange : garde d'include, UB de parsing, et plages nocturnes

**Type** : fix (dont décision produit) · **Phase** : 3
**Origine** : bugs révélés par les tests neufs d'E4.3ab (voir FINDINGS.md).

## 1. Garde d'include manquante — `src/lib/TimeRange.h`
Le header n'a **aucune** garde. L'inclure directement ET via `InPlageHoraire.h` donne une erreur
dure `redefinition of class TimeRange`. Ajouter la garde (style du dépôt : `CALAOS_*_H`).

## 2. UB atteignable — `TimeRange.cpp:100-104` et `142-146`
`getStartTimeSec()`/`getEndTimeSec()` déclarent `int h, m, s;` et **ignorent la valeur de retour**
de `from_string()`. Sur une borne vide ou non numérique — ce que produit
`TimeRange(string proto)` pour tout proto tronqué, puisque `split()` complète avec `""` — les
locales restent **non initialisées** ; valeur parasite observée : `-1858848627`. Atteignable
depuis le chemin proto/JSON.
→ Initialiser, tester le retour de `from_string`, et définir un comportement propre sur borne
invalide (rejet loggé, ou 0 documenté — choisir et le dire).

## 3. Plages nocturnes : wrap sur minuit — **DÉCISION UTILISATEUR (2026-08-16)**
Aujourd'hui une plage inversée (fin < début, ex. `23:00 → 01:00`) est **vide** : la condition
`now >= start && now <= end` ne peut jamais être vraie. Or c'est la façon naturelle d'écrire
« la nuit », et l'utilisateur n'obtient rien, silencieusement.
**Décision : faire wrapper sur minuit.** `23:00 → 01:00` doit matcher de 23h à 1h du matin.
- Implémenter : si `end < start`, la plage est l'union `[start, fin_de_journée] ∪ [début_de_journée, end]`.
- ⚠️ Le test caractérisant `InPlageHoraireEvalTest.InvertedRangeNeverMatches` (E4.3ab) fige le
  comportement actuel : **il doit être réécrit** pour affirmer le nouveau contrat, pas supprimé.
- Vérifier l'interaction avec le masque de jours de la semaine : une plage 23:00→01:00 « le lundi »
  couvre-t-elle lundi 23h→mardi 1h, ou lundi 00h-01h + lundi 23h-24h ? **Choisir la première**
  (continuité de la nuit du lundi), la documenter dans l'ioDoc et la couvrir par un test.
