# E4.4a — Introduire pugixml (build only, zéro consommateur)

**Type** : infra · **Phase** : 4 · **Série** : E4.4 (1/5)
**Décision utilisateur (2026-08-15)** : migrer TinyXML 2.5.3 + TinyXPath → **pugixml**
(XPath 1.0 natif, maintenu, MIT). Voir PHASE4.md.

## Objectif
Rendre pugixml disponible et linké, **sans modifier un seul consommateur**. À la fin de ce
ticket, TinyXML fonctionne toujours et pugixml compile à côté.

## Travail
1. **Vendored ou paquet distro** : trancher selon l'investigation consignée (dispo
   `libpugixml-dev` dans `debian:12` + Arch). Règle : si le paquet est disponible partout où
   calaos se construit → `PKG_CHECK_MODULES` ; sinon vendoring dans `src/lib/pugixml/`
   (2 fichiers : `pugixml.hpp`/`pugixml.cpp`, ~11k LOC, MIT) avec en-tête de licence intact.
   **Activer XPath** (pugixml le compile par défaut ; ne PAS définir `PUGIXML_NO_XPATH`).
2. `configure.ac` + `src/lib/Makefile.am` : détection/compilation, flags exportés comme pour
   les autres libs communes. Le résumé de configure doit mentionner pugixml.
3. Test de fumée minimal (`tests/`) : parser un petit XML, lire un attribut, exécuter une
   requête XPath simple — prouve que la lib est bien linkée **et que XPath est actif**.

## Interdits
Toucher un consommateur TinyXML, supprimer quoi que ce soit de `src/lib/TinyXML/`.

## Acceptation
`./autogen.sh && ./configure && make && make check` verts ; nouveau test de fumée au vert ;
`grep -c TIXML src/` inchangé.
