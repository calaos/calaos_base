# T3.232 — un correspondant injoignable fait refuser les réponses de tout ce qui est en file DERRIÈRE lui

**Statut** : 📋 · **Type** : fix · **Phase** : 3
**Origine** : mesuré en construisant le trafic alterné de [`T3.211`](T3.211.md) — le premier montage
**n'a pas alterné**, et c'est ce qui l'a révélé.
**Dépend de** : [`T3.211`](T3.211.md).

---

## 1. Le fait, mesuré

⭐⭐ **La règle est POSITIONNELLE, et c'est elle le cœur du ticket.** `sendmmsg` remet le **préfixe
sain** de la file — ces datagrammes-là partent — puis libuv charge de l'erreur le **fautif** et
**tout ce qui est en file derrière lui**. Ce n'est **pas** « tout le lot ». Mesuré, sonde libuv
directe, `g` = destination joignable, `b` = injoignable, `.` = parti, `X` = refusé :

| posté dos à dos | résultat | ce que cela dit |
|---|---|---|
| `gb` | `.X` | le fautif seul ; **aucun innocent** |
| `ggb` | `..X` | le fautif est dernier ⇒ **aucun innocent** |
| `gbg` | `.XX` | ⭐ le **premier innocent**, et il est **derrière** le fautif |
| `ggbggg` | `..XXXX` | deux devant épargnés, quatre derrière chargés |
| `bggg` | `X...` | le fautif **en tête** part en ligne et n'emporte personne |
| `gbbbb` | `.XXXX` | `status = -22` (`EINVAL`) sur chacun des quatre |

⭐ **Le seuil est de 2 datagrammes en file, soit 3 postés dos à dos** (le fautif ni premier ni
dernier). **Aucune rafale n'est nécessaire** : `gbg` suffit. Sur ce point le défaut est **pire** que
ce que cette fiche disait.

⛔ **Deux chiffres de la rédaction précédente étaient faux** :
- alterné dos à dos `gbgb…` ×40 ⇒ **39/40**, **jamais 40** : le tout premier envoi part **en ligne**
  quand la file est vide, donc `127.0.0.1` en tête est servie ;
- ⭐ **20 joignables PUIS 20 injoignables dos à dos ⇒ les 20 premières partent, aucun innocent n'est
  touché.** « Les innocents du même lot » était faux ; ce sont les innocents **postés après** le
  fautif.

Postées **un tour de boucle l'une après l'autre**, vingt partent et vingt sont refusées — la file
est vide à chaque envoi, donc chacun part en ligne. C'est la forme que
`core/UdpDiscoverJournalCadence_test` emploie pour son cas d'alternance, qui exige explicitement que
la moitié des réponses soient parties (`(16 refused so far)` et **pas** `(32 refused so far)`).

## 2. ⛔ Ce que cela coûte, et pourquoi ce n'est pas un défaut de journal

⛔ **C'est une perte de service, pas une ligne de trop.** Le seul appelant de `sendTo()` est la
réponse à `CALAOS_DISCOVER` : un tiers qui émet des découvertes depuis des sources usurpées et
injoignables fait **jeter la réponse aux découvertes légitimes lues derrière les siennes dans le
même tour**. Les clients Calaos ne trouvent plus le boîtier, et le journal accuse **leur** adresse —
chaque ligne nomme le correspondant innocent comme si c'était lui qui était injoignable.

⭐ **Et la règle positionnelle rend le tiers plus fort, pas moins** : il lui suffit d'émettre **avant**
la découverte qu'il veut faire taire, et trois datagrammes dans un tour de boucle suffisent. Elle dit
aussi ce qu'un remède doit obtenir : que le fautif ne soit **jamais devant** un innocent dans la file
— poster une réponse par tour, ou `uv_udp_try_send`, l'atteignent ; un plafond de journal, non.

⚠️ **Recoupe [`T3.194`](T3.194.md) sans la subsumer** : `T3.194` décrit une **mauvaise
attribution** quand la socket meurt avec des envois en attente. Ici l'attribution est **juste** — la
réponse à `127.0.0.1` a bien été refusée — et c'est le **refus** qui est faux.

## 3. Ce qui est établi, et ce qui ne l'est pas

⭐ **La cause est CONFIRMÉE, plus déduite.** `LD_PRELOAD` ne voyait rien parce que libuv n'importe
**aucun** `sendmmsg` : `nm -D --undefined-only /usr/lib/x86_64-linux-gnu/libuv.so.1.0.0` ne rend que
`sendmsg@GLIBC_2.2.5` et `syscall@GLIBC_2.2.5` ⇒ l'appel passe par `syscall(__NR_sendmmsg)` en
direct, hors PLT, donc hors de portée d'une interposition. Le refus est lu en clair côté libuv :
`uv_udp_send` rappelle avec `status = -22` (`EINVAL`) sur chaque position chargée.

⭐ **La version n'est plus une inconnue** : `libuv 1.44.2-1+deb12u1` dans l'image de build **et** dans
`ghcr.io/calaos/calaos_base:dev` (image livrée) — **identiques**, lues dans les deux.

Ce qui reste ouvert :
- ⛔ `configure.ac:51` et `:55` n'exigent que `libuv >= 1.19.0` : une compilation depuis les sources,
  ou un boîtier à libuv plus ancienne ou plus récente, **n'est couverte par aucune mesure**. Le
  regroupement est un détail d'implémentation de `uv__udp_sendmsg`, pas un contrat.
- ⛔ Combien de découvertes un tour de boucle lit réellement sur une installation.
- ⛔ Si le remède est de poster les réponses une par tour, de les envoyer par `uv_udp_try_send`, ou de
  ne rien changer parce que le cas ne se produit pas sans tiers hostile. **Les trois sont ouverts** —
  mais les deux premiers sont maintenant **jugeables** contre la règle positionnelle du §2.
- ⚠️ La sonde est un binaire **hors arbre** : elle poste sur une socket `uv_udp_t` liée à `127.0.0.1`
  vers `192.0.2.0/24`, comme le fait la suite, mais **aucun cas de l'arbre n'épingle la règle
  positionnelle**. Elle est mesurée, elle n'est pas **tenue**.
- ⛔ Le commentaire de `tests/core/UdpDiscoverJournalCadence_test.cpp:434-437` porte encore l'ancienne
  règle (« *the whole batch* », « *two answers posted back to back are refused TOGETHER* ») : `gb`
  rend `.X`, donc elle est fausse pour deux. **Non corrigé ici** — toucher la suite rejouerait la
  campagne de mesure de [`T3.212`](T3.212.md) ; à reprendre avec le remède.
