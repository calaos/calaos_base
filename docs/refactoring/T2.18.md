# T2.18 — Audit null-guard des appels `createIO` / `IOFactory::CreateIO`

**Type** : fix (correctness)
**Phase** : 2

## Contexte

FINDINGS « Sécurité / correctness », item 1 : T1.11 a durci la factory (`IOFactory` +
`genDocIO`, null sur type inconnu ou collision d'id « first-wins ») mais **pas les sites
d'appel externes**, hors périmètre fichiers. Deux sites déréférencent le retour sans garde —
un miss de factory (type inconnu dans io.xml, id dupliqué, ou IO retiré comme MySensors
post-T2.12) → segfault au boot ou sur appel API :

- `JsonApi.cpp:1580-1582` (création de scénario via l'API) :
  `createIO(params, room)` → `dynamic_cast<Scenario *>(in)` →
  `scenario->getAutoScenario()->checkScenarioRules()` sans vérifier ni `in` ni le
  `dynamic_cast` (deux façons d'être null). *(FINDINGS citait 1366-1368 ; l'arbre a bougé.)*
- `AutoScenario.cpp:157-160` : `in = createIO(params, roomContainer)` puis
  `in->setAutoScenario(true)` sans garde.

**Recensement exhaustif** (grep 2026-08-15, `createIO|CreateIO` hors IOFactory) :

- `Room.cpp:122` — `CreateIO(node)` **déjà gardé** (`if (io) AddIO(io)`) : rien à faire.
- `ListeRoom.cpp:288-310` — `ListeRoom::createIO` lui-même : retourne bien nullptr sur type
  absent / collision (garde T1.11 en place) : rien à faire, c'est la source des nulls.
- `JsonApi.cpp:1580` et `AutoScenario.cpp:157` — **les deux sites à corriger**.

**Sérialisation** : T2.15 touche aussi `JsonApi.cpp` → jamais dans la même wave que T2.18.

## Travail

Fichiers : `src/bin/calaos_server/JsonApi.cpp`,
`src/bin/calaos_server/Scenario/AutoScenario.cpp` + tests.

1. `JsonApi.cpp:1580` : si `in` est null **ou** si le `dynamic_cast<Scenario *>` échoue,
   répondre une erreur JSON propre (pattern des autres handlers d'erreur du fichier) et
   logger — pas de crash sur une requête API malformée.
2. `AutoScenario.cpp:157` : garde null sur `in` avant `setAutoScenario(true)` ; propager le
   null au retour (`createAutoScenario` renvoie déjà un `IOBase *` — vérifier que **ses**
   appelants tolèrent null, sinon les garder aussi ; rester minimal, c'est un audit).
3. Re-jouer le grep en fin de ticket pour attester qu'aucun site non gardé ne subsiste
   (nouveaux appelants apparus entre-temps compris).
4. Tests de régression : création de scénario via l'API avec un type/params forçant le null
   de factory → réponse d'erreur, pas de segfault (harnais JsonApi de T1.4 ; l'acceptation
   de T2.12 s'appuie explicitement sur ce chemin « config avec IO disparus »).

## Acceptation

- Build docker + `make check` verts (nouveaux tests inclus).
- `grep -rn 'createIO\|CreateIO' src` (hors IOFactory) : chaque site vérifie le retour.
- Une io.xml contenant un type inconnu et un appel API de création de scénario invalide
  loggent une erreur et continuent — plus aucun déréférencement null possible.
