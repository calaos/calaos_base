# T0.5 — clang-format + check CI (diff only)

| Phase | Type | Dépend de | Statut |
|---|---|---|---|
| 0 | infra | T0.2 | 📋 Backlog |

## Fichiers possédés
- `.clang-format`
- `.editorconfig`
- `.github/workflows/ci.yml`

## Objectif
Fournir un formatage automatique conforme aux conventions du projet **sans reformater l'existant** (un reformatage de masse créerait des conflits avec tous les tickets en cours).

## Conventions à encoder (voir `AGENTS.md`)
- C++ : camelCase variables/fonctions/méthodes, PascalCase classes.
- Accolade ouvrante `{` sur une nouvelle ligne.
- Corps mono-ligne sans accolades ; corps multi-lignes toujours avec accolades.
- Listes d'initialisation constructeur : `:` en fin de ligne de déclaration, un initialiseur par ligne avec `,` en fin.

## À faire
- Créer `.clang-format` reproduisant ces règles (base `Allman` pour les accolades).
- `.editorconfig` (indentation, fin de ligne, charset).
- Étendre `ci.yml` avec un check `clang-format --dry-run --Werror` **sur le diff de la PR uniquement** (`git diff --name-only origin/master` filtré `.cpp/.h`), pas sur tout l'arbre.

## Acceptance
- Le check CI échoue si le code **nouvellement modifié** n'est pas formaté.
- Aucun diff imposé sur les fichiers non touchés par la PR.

## Vérification
Une PR avec du code mal formaté échoue au check ; une PR propre passe. Pas de commit de reformatage de masse.

> ⚠️ Partage `ci.yml` avec T0.1 et `tests`-adjacent avec T0.2 → sérialiser après T0.2.
