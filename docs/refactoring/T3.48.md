# T3.48 — l'archive source est **inconstructible** : les arbres vendorés ne sont distribués par personne

**Statut** : 📋 · **Type** : fix (build/release) · **Phase** : 3 · **Dépend de** : [`T3.45`](T3.45.md)
**Origine** : révélé par le **premier `make distcheck` du dépôt**, exécuté sous `T3.45` une fois la
faute de chemin de `src/lib/calaos-python/Makefile.am` réparée. Fiché **F-DIST-1**.

> ⭐ **Point de départ imposé : `make distcheck` doit franchir le build.** Le critère d'entrée du
> ticket n'est pas « ajouter des fichiers à `EXTRA_DIST` », c'est **que l'archive dépliée compile**.
> Tant que `distcheck` meurt sur un `No such file or directory`, le ticket n'a pas commencé.

---

## 1. Ce que `distcheck` montre aujourd'hui

Après `T3.45`, la chaîne va **beaucoup plus loin** : `make distdir` passe (**0** occurrence de
`No rule to make target`), l'archive se déplie, **`configure` réussit** — puis la construction
échoue dans `_build/sub/src/lib` :

```
src/lib/ExpressionEvaluator.cpp:2: fatal error: exprtk.hpp: No such file or directory
src/lib/uvw/src/uvw.hpp:1:    fatal error: uvw/async.hpp: No such file or directory
```

⚠️ **`src/lib/calaos-python` traverse ce journal sans une seule erreur** (*« Nothing to be done for
'all' »*) : ce défaut-ci est **préexistant, indépendant de `T3.45`, et d'un tout autre ordre de
grandeur** que la faute de chemin d'une ligne qu'était `T3.45`.

**Le mécanisme** : `src/lib/Makefile.am` distribue l'**en-tête parapluie** `uvw/src/uvw.hpp` — et
**aucun** des `uvw/src/uvw/*.hpp` qu'il inclut. `exprtk.hpp` n'est listé **nulle part**.

## 3. Périmètre

**Dans le ticket** :

1. faire **franchir le build** à `make distcheck` — critère d'acceptation unique et suffisant ;
2. distribuer les arbres vendorés **par un mécanisme qui ne se dégrade pas** au prochain import
   amont (une liste de 400 chemins écrite à la main pourrit en un `git subtree pull`) ;
3. les **trois fichiers à nous** du §2.2 ;
4. les **licences** du §2.3.

**Hors ticket** : `docs/` (non distribué **par choix**), et le sens « un chemin déclaré ne résout
rien », déjà tenu par `tests/check-extra-dist.sh` ([`T3.45`](T3.45.md) §3).

⚠️ **`tests/check-extra-dist.sh` ne verra JAMAIS ce défaut** et c'est écrit dans sa docstring : il
vérifie « déclaré ⇒ existe », pas « existe ⇒ déclaré ». Le second sens **demande un vrai
`make dist`** ; c'est pourquoi le remède durable est le job CI de F-DIST-2 — **à brancher après ce
ticket**, sinon il est rouge dès le premier jour.

---

## 4. Portée du risque : **nulle** côté utilisateurs

**Aucun binaire n'a pu être construit depuis un tarball de ce dépôt depuis le 2025-02-16** :
d'abord parce que `make dist` **échouait** (`T3.45`), ensuite parce que l'archive, une fois
produite, est **incomplète**. Il est donc **exclu** qu'un binaire divergent ait circulé par cette
voie ⇒ **aucune `RELEASE_NOTES` n'est due**, ni pour `T3.45` ni pour celui-ci.

⚠️ **Cette conclusion porte sur le tarball et sur lui seul.** La construction depuis un `git clone`
**n'a jamais été cassée** — la CI la refait à chaque commit — et ne relève d'aucune note de version.

---

## 5. Pourquoi personne ne l'avait vu

**La CI ne lance ni `dist` ni `distcheck`** : les **deux** seules occurrences de « dist » dans
`.github/` sont des **commentaires** de `dependabot.yml` sur `data/debug/dist/`. Le chemin de
release n'est couvert **nulle part** (F-DIST-2). C'est la même cause racine que les 18 mois de
`T3.45`.
