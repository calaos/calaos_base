## 1. Le constat, revérifié au source (2026-08-25)

Les descriptions `_()` des paramètres `path` **donnent toutes** l'exemple **`weather[0]/description`**.

Le parseur, dupliqué à l'identique dans les deux pilotes, découpe le chemin **sur `/` seul** puis
ne traite un jeton comme index **que s'il commence par `[`** :

| Étape | MQTT | Web |
|---|---|---|
| découpage | `MqttCtrl.cpp:114` — `Utils::split(path, tokens, "/")` | `WebCtrl.cpp:184` — idem |
| test d'index | `MqttCtrl.cpp:125` — `if (val[0] == '[')` | `WebCtrl.cpp:195` — idem |
| branche objet | `:149` — `parent.at(val)` | `:216` — idem |
| journal d'échec | `:153` — `Error in path …, subpath not found` | `:210`/`:217` |

⇒ le jeton `weather[0]` part **entier** en `parent.at("weather[0]")`, la clé n'existe pas,
`nlohmann` lève, la valeur rendue est **vide** et un `cWarning` part dans un domaine que personne
ne lit. **La forme qui marche est `weather/[0]/description`** — l'index doit être **son propre
segment**.

⭐ **Ce n'est pas une coquille de documentation.** Ces chaînes passent par `_()` : elles alimentent
`--gendoc`, `data/doc/{en,fr}/io_doc.json`, **et l'interface de `calaos_installer`**. Tout
utilisateur qui configure un capteur MQTT dont le payload contient un tableau — Zigbee2MQTT,
OpenWeather, cas très courants — lit la mauvaise syntaxe **au moment exact où il en a besoin**,
puis obtient une valeur vide sans message compréhensible.

## 2. Le travail

1. **Les 8 chaînes `_()`** : `weather[0]/description` → **`weather/[0]/description`**.
   ⚠️ Dans `WebDocBase.cpp` la chaîne est **concaténée sur 5 lignes** ; le `msgid` est la
   concaténation. Ne pas casser le découpage sans regarder ce que ça fait au catalogue.
2. **Profiter du passage pour dire la règle**, pas seulement l'exemple : ajouter une phrase du
   type *« array indices are their own path segment: `weather/[0]/description` »*. Un exemple seul
   se recopie mal ; la règle explique pourquoi.
3. **Les catalogues** : régénérer `po/calaos.pot` puis `msgmerge` sur les 9 `.po`. Les entrées
   touchées passeront en `#, fuzzy` — **c'est le comportement attendu**, et il faut le dire dans
   la fiche de livraison plutôt que de le subir.
   ⚠️ **`fr.po` a 9 occurrences, les autres 8** : vérifier laquelle est en trop avant de conclure
   que le merge a mal tourné.
4. **Régénérer `data/doc/{en,fr}/io_doc.json`** — ou déclarer explicitement qu'on ne le fait pas,
   comme E4.1k l'a fait pour son diff de permutation.
5. 📏 **Au passage, une incohérence de bornes du même ordre** (trouvée en instruisant T3.25,
   vérifiée au source) : `IO/OLA/OLAOutputLightRGB.cpp:35` déclare `channel_red` sur **`0..9999`**
   alors que `:36` et `:37` déclarent `channel_green` et `channel_blue` sur **`0..512`**. Le
   `9999` est manifestement recopié de la ligne `universe` juste au-dessus (`:34`). **Mineur**, un
   seul caractère à changer, et la même famille (une chaîne d'ioDoc qui ment à l'utilisateur) —
   à faire ici ou à laisser, mais **le dire**.
6. ⛔ **Ne PAS toucher au parseur.** Faire accepter `weather[0]` demanderait de découper aussi sur
   `[`, c'est-à-dire de changer la sémantique d'un chemin sur **deux pilotes en service**, dont
   des installations réelles dépendent. **La doc a tort, pas le code.**

## 3. Les tests

**Commit de caractérisation d'abord — tests seuls, zéro ligne de `src/`.**

Deux niveaux, et **les deux sont nécessaires** :

**(A) Le parseur — pour figer *quelle* syntaxe marche.** C'est ce qui donne son autorité au
changement de doc. Suite sur la fonction de résolution de chemin des deux pilotes :

| Cas | Ce qu'il fige |
|---|---|
| `AnIndexAsItsOwnSegmentResolves` | ⭐ `weather/[0]/description` → la valeur — **c'est la forme qu'on va publier** |
| `AnIndexGluedToTheKeyDoesNotResolve` | ⭐ `weather[0]/description` → chaîne **vide** — **le défaut, figé** |
| `APlainKeyPathStillResolves` | **acquis** |
| `TheSameTwoCasesOnTheWebParser` | le parseur est **dupliqué** : deux copies, deux jeux de cas |

**(B) La chaîne de documentation — pour que la régression soit impossible.** Un cas qui lit la
description produite par l'ioDoc pour `path` et **exige qu'elle ne contienne pas** le motif
`\w\[\d+\]/`. Patron : `docParamNames()` / `genDocJson()` d'E4.1k.
⭐ **C'est le seul cas qui protège le produit ici** : (A) prouve ce qui marche, mais seul (B)
attrape quelqu'un qui réécrirait la description.

### ⚠️ Fixture pauvre — la forme qu'elle prendrait
Un payload dont le tableau n'a **qu'un** élément, ou dont tous les éléments sont égaux : `[0]` et
`[1]` rendraient la même chose, et une mutation de l'index serait **invisible**. **Trois éléments,
trois valeurs distinctes et non substituables**, et un cas qui lit `[1]`.

### Contre-mutation **par échange**
Permuter les deux cas ⭐ (`AnIndexAsItsOwnSegment` ↔ `AnIndexGluedToTheKey`) doit rougir **deux
fois**. Remettre `weather[0]` dans la chaîne `_()` ⇒ **(B) seul rouge**, témoin 0.
Effacer le `.o` **et** le binaire, exiger la ligne `CXXLD` **et** le code de sortie du binaire :
c'est le seul contrôle qui attrape les cinq variantes du faux vert/rouge.
