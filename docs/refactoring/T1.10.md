# T1.10 — RemoteUI WebSocket/OTA lifecycle

| Phase | Type | Depends on | Status |
|---|---|---|---|
| 1 | fix | Phase 0 | 📋 Backlog |

## Owned files
- `src/bin/calaos_server/RemoteUI/RemoteUIWebSocketHandler.{cpp,h}`
- `src/bin/calaos_server/RemoteUI/OtaHttpHandler.{cpp,h}`
- `src/bin/calaos_server/RemoteUI/OtaFirmwareManager.{cpp,h}`

> Disjoint from T1.6 (which owns `IO/RemoteUI/RemoteUI.cpp`, `HMACAuthenticator.cpp`, `RemoteUIManager.cpp`). The RemoteUI HMAC/nonce auth core is solid; the defects here are lifetime windows tied to an embedded device dropping its connection right after authenticating.

## Findings

### Critical — lifetime: post-auth timer captures raw `this`
`RemoteUIWebSocketHandler.cpp:89` — after auth, `Timer::singleShot(0.1, [this]() { sendConfigUpdate(); sendInitialIOStates(); … checkDeviceForUpdate(this, …); })`. `Timer::singleShot` (`Timer.cpp:87-99`) fires the slot unconditionally (not bound to the handler); `WebSocket.cpp` deletes the handler on disconnect, so if the device drops within 100 ms the callback dereferences freed `this` → **UAF**. **Fix:** cancel the timer in the destructor, or guard the lambda with a weak/shared ownership token (validity flag) so it no-ops after destruction.

### Major — lifetime: async `buildJsonState` callback captures `this`
`sendInitialIOStates` (`RemoteUIWebSocketHandler.cpp:223`) — `buildJsonState(iolist, [this, iolist](json_t *jret){ … sendJson("remote_ui_io_states", data); … authenticated_remote_ui->get_param("id"); })`. `buildJsonState` (`JsonApi.cpp:207+`) defers the callback through async audio-player queries; it is also invoked from `RemoteUIManager::notifyAllIOStates` on every connected handler → a disconnect mid-query frees `this`. **Fix:** capture a weak validity handle, or route the result through `RemoteUIManager` keyed by device id, so the completion callback is dropped if the handler died.

### Major — error-handling: unvalidated `std::stoi` in a timer callback
`RemoteUIWebSocketHandler.cpp:247` — `grid_h`/`grid_w` are parsed with `std::stoi` on client-supplied strings inside a timer callback. A non-numeric value throws `std::invalid_argument` out of the callback into the libuv loop, taking down the event loop. **Fix:** validate / use a non-throwing parse (`Utils::from_string`) with a default.

### Minor — lifetime: OTA response materializes the whole firmware in memory
`OtaHttpHandler.cpp` reads and concatenates the full firmware body plus a copy before sending. **Fix:** stream the file to the client in fixed-size chunks.

### Minor — correctness: rescan interval can overflow `int`
`OtaFirmwareManager.cpp:113` — `unsigned int intervalMs = rescanIntervalMinutes * 60 * 1000;`; `rescanIntervalMinutes` is a clamped-`>=1` `int` with no upper bound, so values above ~35791 minutes overflow the signed multiply (UB) → a wrong (possibly tiny) timer period. **Fix:** compute in 64-bit unsigned and clamp to a sane maximum.

### Minor — duplication: jansson→text→nlohmann round-trip per broadcast
`RemoteUIWebSocketHandler.cpp:226` — `json_dumps(jret) → Json::parse(str) → free(str)` converts jansson to nlohmann on every state message, repeated on connect and on each `notifyAllIOStates` broadcast. **Fix:** build the state directly in nlohmann, or add a single jansson→nlohmann converter (aligns with E4.1).

## Acceptance
- Device disconnect within 100 ms of auth → no UAF (ASan) on the post-auth timer or the `buildJsonState` callback.
- Malformed `grid_h`/`grid_w` → no exception escapes into the loop.
- OTA transfer does not hold the whole image twice in memory.

## Verification
`make check`; ASan on the "authenticate then immediately drop" and "disconnect during IO-state broadcast" scenarios; feed a non-numeric grid dimension and confirm the loop survives.
