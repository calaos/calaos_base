# T3.53 — la paire DALI `(string command, string result)` : **types IDENTIQUES**, donc hors de portée de tout compilateur

**Statut** : 📋 · **Type** : correctif de typage (callbacks internes) · **Phase** : 3 · **Dépend de** : —
**Origine** : **balayage de la revue de [T3.50](T3.50.md)**, vérifié au source par l'auteur de
T3.50 (§7.5.1) puis **re-vérifié au merge**. Fiché sans numéro dans `FINDINGS.md` (entrée
« deux autres paires adjacentes nues dans `IO/Wago/` ») ; **numéro attribué au merge de T3.50**.

> ⭐ **CE QUI REND CE TICKET DIFFÉRENT DE TOUTE LA CHAÎNE WAGO QUI PRÉCÈDE.** [T3.31](T3.31.md),
> [T3.46](T3.46.md) et [T3.50](T3.50.md) ont fermé des paires dont les deux types se
> **convertissaient** l'un dans l'autre (`UWord` ↔ `int`) : un compilateur ne disait rien, mais il
> *aurait pu* le dire si les types avaient été distincts. ⛔ **Ici les deux types sont
> `std::string` — le MÊME type.** Il n'existe **aucune conversion à diagnostiquer** : aucun
> compilateur, aucun drapeau, aucun analyseur statique de type ne pourra **jamais** rien en dire.
> **Le typage par rôle est le seul remède possible**, et **aucun test ne couvre ce chemin**.
> ⇒ **C'est la plus exposée des deux paires remontées par T3.50.**

## 1. Le trou

`WODali::WagoUDPCommand_cb` et ses trois jumeaux RVB reçoivent la réponse UDP d'un ballast DALI :

```cpp
void WODali::WagoUDPCommand_cb(bool status, string command, string result);   /* WODali.h:38 */
```

Les deux derniers paramètres sont **adjacents**, **nus** et de **type identique**. Une permutation
au site d'invocation ou dans une implémentation **compile sans le moindre diagnostic possible**.

⭐ **Les DEUX membres sont lus** — ce n'est donc **pas** le no-op sémantique que T3.50 a mesuré sur
`(address, count)` : une permutation **change le programme**.

```cpp
/* WODali.cpp:86  */ cInfoDom("output") << "Error with request " << command;
/* WODali.cpp:92  */ if (command.find("WAGO_DALI_GET") != string::npos)
/* WODali.cpp:95  */ split(result, tokens);
```

`command` est **testé** (`find("WAGO_DALI_GET")`), `result` est **découpé** (`split`) et ses jetons
pilotent l'état du ballast. Permutés, on découpe la commande et on cherche `WAGO_DALI_GET` dans la
réponse ⇒ **la branche `GET` ne se prend plus jamais**, silencieusement.

## 3. ⛔ Ce qu'il ne faut PAS re-débattre

- ⛔ **« Un compilateur finira bien par le voir »** — **non, jamais** : `std::string` et
  `std::string` sont le même type. C'est **mesuré par construction**, pas supposé.
- ⛔ **« Écrivons un test rouge comportemental d'abord »** — celui-là est **possible** (contrairement
  à T3.50, où une permutation était un no-op) **mais il n'existe pas** : ⚠️ **il n'y a aucun test
  DALI dans l'arbre** (`tests/` : zéro fichier `*Dali*`). Un test de caractérisation est donc à
  **écrire**, et c'est une part réelle du coût.
- ⛔ **Ne pas avaler le reste de `WODaliRVB`** : ce ticket ferme **une paire**, pas la classe.

## 5. Acceptation

1. La paire est **typée par rôle** aux **10** sites (5 décl. + 5 déf.), **le paramètre anonyme de
   `WODaliRVB.cpp:164` compris**, et le `typedef` de la fente `SendUDPCommand` suit.
2. Les **4** `sigc::mem_fun` compilent — c'est le filet, pas un obstacle.
3. ⭐ **Une contre-mutation par ÉCHANGE est mesurée sur chaque site** : avant le typage elle

   est publié, et un site où la mutation **compile encore** est un site **non fermé**.
4. **Un test de caractérisation existe** (il n'y en a aucun aujourd'hui) et il **exerce** la
   branche `WAGO_DALI_GET`.
5. `make check` **recompté** (pas recopié), `# FAIL: 0` hors `F-FLAKY-1`, goldens intacts.
