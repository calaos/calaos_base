## Owned files

## Goal
Clean up the test build and remove stale include paths.

## Findings
- **Dead include paths** — `tests/Makefile.am:18,22,23` reference non-existent dirs `IO/Scripts`, `IO/X10`, `IO/Zibase`; `:33` references `src/lib/cJSON` (cJSON was replaced by `json.hpp`). All four dirs are confirmed absent on disk.
- **Duplicate define** — `-DPACKAGE_DATA_DIR` is defined twice with two different values (`tests/Makefile.am:11` = `$(datadir)/calaos`, `:12` = `$(pkgdatadir)`); the second silently wins.
- **Orphan test** — `tests/WebSocketClient_test.cpp` exists but is referenced by no `Makefile.am`, so it is never compiled. Wire it into `TESTS`/`check_PROGRAMS`.
- **gtest LDADD ordering** (major/build) — `tests/Makefile.am:38` puts `-lgtest -lgtest_main` in `AM_LDFLAGS`, which Automake emits *before* the object files. Under the Debian/Ubuntu `--as-needed` default the libs are dropped, leaving undefined gtest symbols and a failing link. **Fix:** move `-lgtest -lgtest_main` out of `AM_LDFLAGS` into each test's `*_LDADD` (after the objects).

> The identically-committed dead includes / duplicate define in `src/bin/calaos_server/Makefile.am` are fixed by **T0.6** (production Makefile), not here.

> Note: earlier drafts asked to "remove committed `.pyc`". None are git-tracked (`git ls-files` is empty for them) and `__pycache__/` is already in `.gitignore:108`; nothing to remove. Adding an explicit `*.pyc` pattern is optional.

## Acceptance
- `make check` compiles and runs `WebSocketClient_test` (the 4th test) and links cleanly under `--as-needed`.
- No `-I` to a non-existent directory; a single `-DPACKAGE_DATA_DIR`.

## Verification
`make check` green including the 4th test; `grep -n PACKAGE_DATA_DIR tests/Makefile.am` → one occurrence; build succeeds on a stock Debian 12 (`--as-needed`).
