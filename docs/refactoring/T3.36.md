# T3.36 — ⭐ 47 suites sur 80 peuvent répondre VERT sans avoir relié le code modifié

**Statut** : 📋 · **Type** : infra · **Phase** : 3 · **⚠️ PRIORITÉ HAUTE**
**Dépend de** : — (transverse à `tests/Makefile.am`)
**Origine** : rencontré en livrant [T3.29](T3.29.md) §5.7, **reproduit en revue** le 2026-08-25.

---

## 1. Le défaut, reproduit

Réintroduire la forme fautive dans `IO/Mqtt/MqttCtrl.cpp`, puis :

```
make -j16 && make check -j8      →  83/83 PASS, relinks CXXLD JsonPathSyntax_test = 0
```

**Vert. Sur un défaut réintroduit.** Le `.o` serveur est reconstruit, le binaire de test ne l'est
pas, `make check` exécute **l'ancien binaire**.

**Cause** : la convention du fichier veut qu'on écrive
`<suite>_DEPENDENCIES = $(top_builddir)/src/lib/libcalaos_common.la`
avec le commentaire *« Built elsewhere, do not let automake turn them into prerequisites »*, pour
que `make` ne tente pas de construire les `.o` de `calaos_server` depuis `tests/`. L'effet de bord
est que **les objets réellement testés ne sont plus des prérequis du binaire**.

## 2. La portée — mesurée en `python3`, pas en `grep`

⚠️ **Le « 48 sur 82 » annoncé en revue ne se reproduit pas tout à fait chez moi ; voici mes
chiffres**, mesurés en `python3` sur `tests/Makefile.am` (continuations `\` recollées avant
analyse — un balayage ligne à ligne se trompe ici) :

| | |
|---|---|
| `check_PROGRAMS` | **81**, dont `StaticLogShutdown_helper` qui n'est pas un `TESTS` ⇒ **80 binaires de test** |
| `TESTS` | **83** = 80 binaires + 3 scripts (`check-config-{options,docs}.sh`, `run-python-tests.sh`) |
| suites portant l'override `_DEPENDENCIES` | **48** ✅ (le chiffre de la revue) |
| … **dont celles reliant réellement des `.o` serveur** (directement ou via `CORE_TEST_LDADD` → `CORE_SERVER_OBJECTS`) | ⭐ **47** |
| … override **inoffensif** (ne relie que `libcalaos_common.la`) | **1** |

⇒ **47 suites sur 80 — près de six sur dix — peuvent répondre vert sans avoir testé le code
modifié.** Le constat de la revue est donc **confirmé et légèrement aggravé en proportion**
(47/80 plutôt que 48/82) ; le seul écart est le dénominateur.

⚠️ **Le piège du décompte** : `CORE_TEST_LDADD` **contient** `CORE_SERVER_OBJECTS`, une trentaine
de `.o` serveur. Une suite qui n'écrit jamais `$(CALAOS_SERVER_BUILDDIR)` en relie quand même —
un premier balayage naïf m'a donné **27** au lieu de 47 pour cette seule raison. **À recompter
dans le ticket, avec la substitution des variables.**

⭐ **C'est la cause racine des cinq variantes de faux vert/faux rouge** rencontrées en deux jours
de série (faux rouge sur `.o` périmé après rebase, faux vert sur mutation jamais reliée…). Les
consignes de ticket les contournent **une par une, à la main** (`rm -f tests/<suite>` + exiger la
ligne `CXXLD`) ; ce ticket propose de **réparer la cause** au lieu de la contourner.

## 3. Le travail

1. Recompter les 48 sites et **classer** : ceux qui relient des `.o` serveur directement, et ceux
   qui le font **via `CORE_TEST_LDADD`** — le correctif n'est probablement pas le même.
2. Faire dépendre chaque suite des objets qu'elle relie, **sans** rendre `tests/` capable de les
   construire — piste à instruire : un `_DEPENDENCIES` qui **liste les `.o` en plus** de la `.la`
   (automake ne fabrique alors pas de règle, mais compare les dates), ou une cible `check-local`
   qui force le relink.
3. ⚠️ **Prévenir dans la fiche de livraison qu'on découvrira peut-être des tests qui ne passaient
   que grâce à l'absence de relink.** C'est le résultat le plus utile du ticket, et il ne doit pas
   être vécu comme une régression du ticket.
4. Tant que ce n'est pas fait : **tout** ticket touchant un `.o` serveur doit faire
   `rm -f tests/<suite>` et **exiger la ligne `CXXLD <binaire>`** dans la sortie de `make check`.

## 4. Les tests

Un contrôle de harnais, pas une suite gtest : **mutation-témoin scriptée**. Réintroduire un défaut
connu dans un `.o` serveur relié par une suite, lancer `make -j && make check`, et **exiger** que
la suite rougisse. À faire tourner sur les 47 sites, et publier la liste de ceux qui **restaient
verts** avant le correctif.

## 5. Acceptation

1. Le scénario du §1 (défaut réintroduit dans `MqttCtrl.cpp`) rougit **sans** `rm -f` manuel.
2. La liste des suites qui étaient aveugles est publiée, site par site.
3. Aucune suite ne devient rouge pour une autre raison que celle-là — sinon **c'est un finding**,
   pas une régression.
4. `tests/Makefile.am` : ⚠️ **régénération + contrôle tous préfixes `^if*` confondus** (le piège
   de merge connu : « garder les deux côtés » perd le `endif` extérieur → `unterminated
   conditionals`).
