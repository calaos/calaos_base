## Constats

### M1 — majeur : condition multi-input réduite au dernier input
`ConditionStd::Evaluate` (`ConditionStd.cpp:59-186`) **assigne** `ret` à chaque itération de la boucle sur les inputs (`ret = eval(...)` aux lignes 103, 139, 169…). Pour une condition contenant plusieurs `<calaos:input>`, seul le **dernier** input décide du résultat ; les précédents sont évalués mais leur valeur de vérité est jetée. `LoadFromXml` supporte explicitement N inputs (`ConditionStd.cpp:321-368`) → vrai bug logique.

**Remédiation** : accumuler en conjonction — seed `ret = true`, puis `ret = ret && eval(...)`. (Confirmer la sémantique attendue : ET logique de tous les inputs.)

### M7 — majeur : duplication ConditionStd / ConditionOutput
Les 3 overloads `eval(bool/double/string)` de `ConditionStd.cpp:202-307` et `ConditionOutput.cpp:157-262` sont quasi identiques, tout comme les branches TBOOL/TINT/TSTRING de leurs `Evaluate`. Divergence déjà présente : `ConditionOutput` laisse `bval/dval` **non initialisés** (`ConditionOutput.cpp:39-40`) alors que `ConditionStd` les initialise (`:62-63`).

**Remédiation** : extraire un helper d'évaluation d'opérateurs partagé (fonction libre ou base commune), initialiser systématiquement les temporaires. Corriger le bug d'init non-initialisée au passage.
