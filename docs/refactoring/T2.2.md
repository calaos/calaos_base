## Fichiers possédés

- mise à jour des `#include` dans tout le dépôt

## Constat
`lib/Utils.h` (429 l.) est un fourre-tout inclus quasi partout ; `lib/Utils.cpp` (1004 l.) mélange ≥ 6 domaines : URL encode/decode, base64, hex/time, string (split/trim/replace/case), **lecture/écriture config XML** (`get/set/del_config_option`, `getConfigPath/getCachePath`), cycle de vie logger (`initLogger`/`freeLoggers`), hardware id + UUID + uptime + watchdog, helper `CStrArray`.
Problèmes majeurs :
- `using namespace std;` **au scope global** dans le header partagé (`Utils.h:126`) → fuit dans tout le codebase.
- Constantes hétéroclites (`WAGO_LISTEN_PORT`, `JSONAPI_PORT`, tailles GUI `WIDTH/HEIGHT`, macros ANSI couleur).
- Macros mémoire non hygiéniques `DELETE_NULL`/`FREE_NULL` (`:177-184`, sans `do{}while(0)` ni parenthèses).
- Deux templates `to_string`/`from_string` (`:304-318`) qui shadowent `std::to_string` sous le `using namespace std;`.

## Remédiation
- Éclater par domaine :
  - `StringUtils` : split/trim/replace/case, url/hex, base64 wrappers, to_string/from_string.
  - `ConfigStore` : get/set/del config XML, chemins config/cache.
  - `LogSetup` : init/free loggers, macros `cDebugDom` (rester dans un header dédié).
  - `SystemInfo` : hardware id, uuid, uptime, watchdog.
- Retirer `using namespace std;` du header partagé (qualifier `std::` explicitement).
- Déplacer constantes/macros vers des headers dédiés (`Constants.h`, `MemMacros.h`).
- `Utils.h` peut rester un agrégateur d'includes transitoire pour limiter le churn, puis être retiré progressivement.

## Acceptance
- Build complet OK (C++20).
- Plus de `using namespace std;` dans un header partagé.
- Aucun changement de comportement (refactor pur).

`make && make check` verts ; diff de comportement nul (smoke-test serveur). Réaliser ce ticket **seul** dans sa vague pour un rebase propre.
