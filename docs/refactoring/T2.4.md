# T2.4 — Config robuste (m1–m6)

| Phase | Type | Dépend de | Statut |
|---|---|---|---|
| 2 | fix | Phase 1 | 📋 Backlog |

## Fichiers possédés
- `CalaosConfig.{cpp,h}`

## Constats

### m1 — majeur : `exit(-1)` sur XML malformé
`Config::LoadConfigIO`/`LoadConfigRule` appellent `exit(-1)` sur toute erreur de parse TinyXML (`CalaosConfig.cpp:61,143`). Un seul octet corrompu dans `io.xml`/`rules.xml` tue le daemon, sans recovery.
**Remédiation** : échouer proprement, restaurer le dernier backup connu (`BackupFiles` existe déjà), logguer l'erreur.

### m2 — échec de save silencieux et mal étiqueté
`SaveConfigIO`/`SaveConfigRule` testent `document.SaveFile(tmp)` mais logguent « Done. » inconditionnellement ensuite (`:113-119,196-202`) → un save échoué produit un log de succès.
**Remédiation** : logguer une erreur sur la branche `false`.

### m3 — fenêtre de remplacement non atomique
Save config et `saveStateCache` font `unlink(file); rename(tmp,file)` (`:115-116,276-277`). `rename` seul est atomique ; le `unlink` préalable ouvre une fenêtre où le fichier config est absent.
**Remédiation** : supprimer le `unlink` (garder `rename` seul).

### m4 — state cache non flush au shutdown
`Config::~Config()` est vide (`:35-37`) ; le timer 60 s `saveCacheTimer` est abandonné sans `saveStateCache()` final → jusqu'à 60 s d'états `save=false` perdus à l'arrêt.
**Remédiation** : flush dans le destructeur / sur SIGTERM.

### m5 — code mort
`CONFIG_STATES_CACHE_VERSION` (`CalaosConfig.h:35`) défini jamais utilisé ; `loadStateCache` teste `is_object()` 2× (le 2ᵉ, `:231`, inatteignable). Nettoyer.

### m6 — message de log copié-collé faux
`BackupFiles` logue « Unable to backup file rules.xml » alors que la copie qui échoue est `LOCAL_CONFIG` (`:355-358`).

## Acceptance
- XML corrompu → fallback backup + log erreur, **pas** d'`exit`.
- Save échoué → loggué en erreur (pas « Done. »).
- Pas de fenêtre sans fichier config (rename seul).
- Flush du state cache au SIGTERM/destruction.
- Code mort retiré ; message de backup correct.

## Vérification
`make check` (fixtures T0.3) : charger un XML volontairement corrompu → recovery ; couper le serveur (SIGTERM) → cache flushé ; simuler un échec d'écriture → log erreur.
