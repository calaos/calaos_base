# T3.17f — `eventlog` : UAF non gardé, sur les deux transports

**Type** : fix (sec) · **Phase** : 3 · **Série** : T3.17 (f/f) · **Dépend de** : T3.17c (possède `JsonApi.cpp`)
**Origine** : découvert par l'audit T3.17e, qui s'est **arrêté et l'a signalé** plutôt que de le corriger à moitié.

## Le bug

`JsonApiHandlerWS::processEventLog` (`JsonApiHandlerWS.cpp:493-499`) passe `[=](Json &j){ sendJson(...); }`
— qui **capture `this`** — à `JsonApi::buildJsonEventLog` (`JsonApi.cpp:1974-2027`). Celle-ci la confie à
`HistLogger::getEvents` / `getEvent`, qui la stocke dans un `uvw::AsyncHandle` **possédé par la boucle**
(`HistLogger.cpp:137-141, 154-158`) pendant qu'un **thread sqlite** travaille.

Un client qui se déconnecte pendant la lecture de la base fait donc rappeler `sendJson` **sur un handler
libéré**. C'est exactement la forme du **premier UAF de T3.17a**, sur une famille qu'**aucun** des
sous-tickets a/b/c/d/e ne couvre.

Le site HTTP jumeau est identique : `JsonApiHandlerHttp.cpp:877`, `[this](Json &j){ sendJson(j); }`.

## Pourquoi T3.17e ne l'a pas corrigé (raisonnement à conserver)

1. Corriger seulement le versant WS aurait donné une **fausse impression de couverture** — le jumeau HTTP
   serait resté nu.
2. Le correctif durable couvrant **les deux transports d'un coup** est dans `JsonApi::buildJsonEventLog`,
   fichier qui ne lui appartenait pas.
3. Il ne pouvait pas l'épingler par test sans faire entrer `HistLogger` (thread sqlite + base dans le
   répertoire cache du fixture, détruit entre les cas). **Standard de la série : pas de preuve, pas de
   changement.**

`T3.17.md:193-195` rangeait ces familles en « hors périmètre, à recenser séparément si un besoin
apparaît ». **Le besoin est apparu, et il est mesuré.**

## Travail (fichier : `src/bin/calaos_server/JsonApi.cpp`)

Poser `std::weak_ptr<bool> alive = apiAlive` dans `buildJsonEventLog` et tester `alive.expired()` en
**tête des deux callbacks** (`:1986` chemin uuid, `:2003` chemin pagination).

**Cela couvre WS et HTTP par le même mécanisme transitif que T3.17e vient de valider par la mesure** :
les deux handlers dérivent de `JsonApi` (base unique non virtuelle, un seul propriétaire
`JsonApi *jsonApi`, une seule destruction `HttpClient.cpp:162`). Aucun handler ne doit être édité.

⚠️ **Le jeton de cette famille est invalidé implicitement** — le membre meurt avec l'objet. **N'ajoute
aucun `.reset()`** : ce pattern appartient à `aliveTag` (`src/lib/Timer.cpp`), dont l'objet est réutilisé
entre cycles.

⚠️ **Vérifier le second UAF par la mesure, pas par symétrie.** Bilan de la série : le pointeur d'IO brut
n'est réellement déréférencé après l'aller-retour **que** sur la chaîne playlist (T3.17a). T3.17b et
T3.17d ont mesuré son absence et n'ont **rien** appliqué. Fais la même mesure ici.

⚠️ **Fuites** : déterminer si un `json_t*` brut est vivant au point de garde. T3.17a a dû ajouter des
`json_decref` explicites, T3.17b non (tout son JSON était construit après la garde). Mesurer avec
`detect_leaks=1`.

## Le vrai poste d'effort : la preuve

C'est **la raison pour laquelle ce ticket est séparé**. Il faut faire entrer `HistLogger` dans le harnais
de test — thread sqlite, base dans le répertoire cache du fixture (détruit entre les cas) — ou trouver un
moyen de découpler. **Si la conclusion est que ce n'est pas raisonnablement testable, le dire et démontrer
la fenêtre par lecture de code** est recevable ; mais il faut avoir essayé, et dire précisément ce qui
bloque.

## Acceptation

`make check` vert en distclean complet, compte au moins égal à celui de master. UAF reproduit sous ASan
(`./configure --enable-asan`, `ASAN_OPTIONS=detect_leaks=0 make check`) **ou** fenêtre démontrée par
lecture de code avec la raison du non-test. Aucun handler édité. Aucun `.reset()` ajouté. Aucune réponse
mutilée : quand la garde se déclenche, le client est déjà parti — un `return` nu est correct (T3.17d l'a
établi).

⚠️ **Piège `_DEPENDENCIES`** : effacer **le `.o` de production ET le binaire de test**, voir `CXXLD` dans
le log. La variante **faux ROUGE** existe aussi — `make distclean` après tout rebase avant de conclure.
