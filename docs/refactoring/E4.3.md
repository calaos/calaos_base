| Phase | Type | Dépend de | Statut |
|---|---|---|---|
| 4 | epic | Phase 0 | 📋 Backlog |

## Portée
Épic — étendre progressivement la couverture GTest. Peut démarrer **dès la Phase 0** (dépend de T0.3 scaffolding) et progresser en parallèle des autres phases ; c'est aussi le prérequis des epics E4.1/E4.2.

## Constat
Aujourd'hui **3 tests seulement** sont buildés (`ColorValue`, `ExpressionEvaluator`, `FileUtils`) + 1 orphelin (`WebSocketClient_test`, wiré par T0.2). Couverture nulle sur : moteur de règles, round-trip XML config, tous les drivers IO (81 classes `REGISTER_IO`), `TimeRange` (435 l.), `Calendar` (431 l.), `Params`, `WebSocketFrame`, `tcpsocket`, framing `ExternProc`, `Timer`, `SHA1`/`base64`, bindings Lua.

## Remédiation (cibles prioritaires)
1. **Moteur de règles** : évaluation conditions (mono/multi-input), exécution actions, `AutoScenario`.
2. **Round-trip XML config** : `io.xml`/`rules.xml` load → save → reload identiques ; recovery sur XML corrompu (aligné T2.4).
3. **Cycle de vie IO/règles** : création/suppression sous ASan (support E4.2).
4. **Utilitaires** : `TimeRange`, `Calendar`, `WebSocketFrame`, framing `ExternProc`, `Timer` (aligné T2.1).

## Acceptance (epic)
- Couverture significative du cœur métier (règles + config) et des utilitaires critiques.
- Tests exécutés en CI (T0.1) à chaque PR.

## Vérification
`make check` vert avec la suite étendue ; rapport de couverture (gcov/lcov) suivi dans le temps.

> Beaucoup de sous-tickets de correction (T1.x, T2.x) ajoutent déjà leurs tests de non-régression : cet epic centralise les cibles restantes non couvertes.
