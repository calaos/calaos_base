# T3.104 — la moitié « actions » : le dernier chemin par lequel des octets d'un tiers entrent dans la configuration

**Statut** : 📋 · **Type** : fix · **Phase** : 3 · **Dépend de** : [T3.72](T3.72.md) ✅
**Origine** : ouvert et **mesuré** par la revue de merge de [`T3.72`](T3.72.md) (2026-09-05).
⭐ **Arbitrage tranché le 2026-09-06** : voir `DECISIONS.md` § « Cinq arbitrages du 2026-09-06 ».

---

## 1. Ce que la revue a mesuré

La valeur d'action d'un auto-scénario devient **aussi** l'attribut `val` d'une action de règle
(`AutoScenario::addRuleAction()` → `ActionStd::SaveToXml()`). Une maison qui s'en sert garde donc
**deux** fichiers non conformes — `io.xml` **et** `rules.xml` —, pas un.

⭐ **Ce n'est PAS « `rules.xml` n'est pas gardé »** : `JsonApi` n'expose **aucun verbe d'écriture de
règle**. Les règles viennent de `calaos_installer`, un autre dépôt.

## 2. La décision, et pourquoi cette forme

✅ **Refuser à la source** — la garde se pose sur la valeur d'action **au moment où l'API l'accepte**,
pas dans l'écriture des règles.

⛔ **Écarté : garder `Rules/`.** Poser la garde à l'écriture refuserait de **ré-enregistrer ce qu'un
Calaos plus ancien a écrit** — exactement l'écueil que [`T3.72`](T3.72.md) a évité en plaçant sa
garde dans le **modèle** et non dans le sérialiseur, ce qui laisse une configuration existante se
charger et se sauver à l'identique.

## 3. Ce qu'il faudra épingler

- Une valeur d'action portant un caractère de contrôle est **refusée par l'API**, avec un message
  qui nomme l'octet sans l'imprimer (la forme de `T3.72`).
- ⛔ Une configuration **existante** qui en porte un se charge et se ré-enregistre **à l'identique** —
  mesuré, pas déduit.
- Le refus emprunte **le même prédicat** que `T3.72`, pas une copie : la revue de `T3.72` a mesuré
  que deux copies d'une règle se comportent comme **une règle non testée** (0 rouge sur 133 suites).

## 4. ⛔ Nu

- Le vrai porteur reste `calaos_installer` : ce ticket ferme le chemin de l'API, pas celui de
  l'installateur. **La limite doit être écrite dans les notes de version.**
- La conformité XML d'un `rules.xml` déjà écrit n'est pas rétablie par ce ticket.
