# T3.142 — le tampon d'une réponse UDP peut survivre à la chaîne qui le possède

**Statut** : 📋 · **Type** : fix · **Phase** : 3
**Origine** : lu en écrivant [T3.135](T3.135.md). **Non mesuré.**

---

## 1. Ce qui est lu

`uvw::UDPHandle::send(const sockaddr &, char *data, unsigned int len)`
(`src/lib/uvw/src/uvw/udp.hpp:396`) construit sa `SendReq` avec un **suppresseur qui ne fait rien** :

```cpp
std::unique_ptr<char[], details::SendReq::Deleter>{ data, [](char *) {} }
```

Le tampon n'est **ni copié ni possédé** : `uv_buf_init` pointe dessus, et libuv le lit quand la
requête est dépilée. Or `UDPServer::processRequest()` lui donne le `c_str()` d'une `string`
**locale** :

```cpp
string packet = "CALAOS_IP ";
packet += ip;
sendTo(remoteIp, remotePort, packet);   // packet meurt au retour
```

Tant que la file d'envoi du handle est vide, `uv__udp_send` appelle `uv__udp_sendmsg`
**immédiatement** et le tampon est lu avant le retour. Ce n'est plus vrai dès qu'un envoi est déjà
en attente : `send_queue_count != 0` fait mettre la requête en file, et elle est lue au tour de
boucle suivant, quand `packet` n'existe plus.

⭐ **Que la mise en file arrive réellement est mesuré** — c'est ce sur quoi repose le cas
`TwoOutstandingAnswersAreNamedInTheOrderPosted` de `core/UdpSendFailureIsolation_test` : deux
réponses postées dos à dos sont toutes les deux en attente au même moment. Ce cas garde ses tampons
en vie **exprès**, précisément parce que la production ne le fait pas.

## 2. Ce qui n'est pas mesuré

**Personne n'a vu la lecture après libération.** Il faut deux `CALAOS_DISCOVER` lus dans le même
tour de boucle — un balayage de découverte en fait — et un build `--enable-asan`. Tant que ce n'est
pas fait, cette fiche est une lecture du code, pas une trouvaille.

## 3. Ce qu'il faudra mesurer et trancher

1. Deux `CALAOS_DISCOVER` dans le même tour, sous ASan : y a-t-il `heap-use-after-free` ?
2. Le recensement des autres appelants du même `send(…, char *, …)` de l'arbre.
3. L'arbitrage : copier dans la surcharge `unique_ptr<char[]>` de uvw (qui, elle, possède), ou
   garder le tampon vivant côté `UDPServer` jusqu'à l'événement terminal — la file `pendingSends`
   de [`T3.135`](T3.135.md) est déjà exactement cette durée de vie.
