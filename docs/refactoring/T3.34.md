# T3.34 — `impulse down` ne peut pas fonctionner : `erase(0, 11)` sur un préfixe de **13** caractères

**Statut** : 📋 · **Type** : fix (fonctionnel) · **Phase** : 3 · **Dépend de** : —
**Origine** : trouvé en instruisant **T3.25** (revue parallèle, revérifié au source ici).
**Ticket court, indépendant, sans décision à prendre.** Le plus petit correctif du lot.

---

## 1. Le défaut, revérifié au source (2026-08-25)

`IO/OutputShutter.cpp:110-123` — les deux branches d'impulsion, côte à côte :

```cpp
110|    else if (val.compare(0, 11, "impulse up ") == 0)
111|    {
112|        val.erase(0, 11);          // ← "impulse up " fait 11 caractères. Correct.
113|        int v;
114|        from_string(val, v);
115|        ImpulseUp(v);
116|    }
117|    else if (val.compare(0, 13, "impulse down ") == 0)
118|    {
119|        val.erase(0, 11);          // ← ⛔ "impulse down " fait 13 caractères.
120|        int v;
121|        from_string(val, v);
122|        ImpulseDown(v);
123|    }
```

Le `compare` teste bien **13** ; le `erase` en retire **11**. Il reste donc **`"n "` collé devant
la valeur** : `"impulse down 500"` devient **`"n 500"`**.

`from_string("n 500", v)` : le caractère `n` n'est pas numérique, la sentinelle passe (la chaîne
n'est pas blanche), `num_get` échoue ⇒ **retour `false`, et `v` vaut `0`** (voir T3.25 §1, régime
« illisible non blanc »).

⇒ **`ImpulseDown(0)`, systématiquement, quelle que soit la durée demandée.**
`OutputShutter.cpp:164-172` pose alors `impulse_action_time = 0`, et `DownWait()` arme une
minuterie d'arrêt à `impulse_time / 1000` seconde — c'est-à-dire **la seule durée d'impulsion du
paramètre `impulse_time`, jamais celle que le client a demandée**.

⭐ **La commande `impulse down` ne fait pas ce qu'elle annonce, et ne l'a jamais fait.**

### Le jumeau, dans l'autre volet

`IO/OutputShutterSmart.cpp:169-175` porte **exactement** la même faute :

```cpp
169|    else if (val.compare(0, 13, "impulse down ") == 0)
170|    {
171|        val.erase(0, 11);
```

⇒ **deux fichiers, deux lignes** : `OutputShutter.cpp:119` et `OutputShutterSmart.cpp:171`.

### Pourquoi personne ne l'a vu

- L'échec est **silencieux** : `from_string` rend `false`, **et son retour est ignoré** aux deux
  sites (comme aux 310 autres — cf. T3.25).
- L'IO **répond `success`** : `set_value()` rend `true` sur la branche reconnue, le `compare`
  ayant matché. Le client n'apprend rien.
- Le volet **bouge quand même** — `DownWait()` est bien appelé. C'est la **durée** qui est fausse,
  pas le mouvement. Sur un volet à impulsion courte, la différence est facile à mettre sur le
  compte du matériel.
- `cmd_state = "impulse down " + to_string(0)` (`:169`) publie **`"impulse down 0"`** dans l'état
  de l'IO ⇒ **la trace du défaut est visible dans l'API depuis toujours**, personne ne l'a lue.

⚠️ **Non vérifié** : depuis quand. Le défaut est manifestement ancien mais l'archéologie git n'a
pas été faite, et elle ne changerait pas le correctif.

## 2. Le travail

Deux caractères, deux fichiers :

- `IO/OutputShutter.cpp:119` → `val.erase(0, 13);`
- `IO/OutputShutterSmart.cpp:171` → `val.erase(0, 13);`

⭐ **Et pendant qu'on y est, retirer la duplication du littéral.** Le défaut vient de ce que la
longueur est écrite **deux fois** (`compare(0, 13, "impulse down ")` puis `erase(0, 11)`) et que
rien ne les lie. La forme qui rend la faute impossible :

```cpp
static constexpr std::string_view kImpulseDown = "impulse down ";
...
else if (val.compare(0, kImpulseDown.size(), kImpulseDown) == 0)
{
    val.erase(0, kImpulseDown.size());
```

Ou, plus simplement, `Utils::strStartsWith()` — **qui existe déjà et est déjà utilisé douze
lignes plus bas**, à `OutputShutter.cpp:124` (`Utils::strStartsWith(val, "set_state ")`).
Le fichier contient donc **les deux styles**, et seul celui qui compte deux fois est faux.

C'est la même leçon que **T3.31** : *le trou ne se referme pas par la vigilance, il se referme par
une forme où l'erreur ne s'écrit pas.*

⛔ **Hors périmètre** : le fait que `v` soit lu sans garde et que `from_string` mente — c'est
**T3.25**, et les deux tickets touchent les **mêmes lignes**. ⚠️ **À sérialiser : T3.34 d'abord**
(deux caractères, zéro risque), **T3.25 L1 ensuite**. L'inverse ferait rebaser T3.25 sur un
correctif d'une ligne, pour rien.

## 3. Les tests

**Commit de caractérisation d'abord — tests seuls, zéro ligne de `src/`.**

| Cas | Ce qu'il fige |
|---|---|
| `ImpulseDownCarriesTheRequestedDuration` | ⭐ **le défaut** — `"impulse down 500"` ⇒ durée **500**, pas 0 ⇒ 🔴 puis 🟢 |
| `ImpulseUpCarriesTheRequestedDuration` | **acquis** — la branche qui marchait ne régresse pas |
| `ImpulseDownAndUpAgreeOnTheSameDuration` | ⭐ **le cas porteur** : les deux branches, **même** durée demandée, **même** durée armée |
| `TheSameOnOutputShutterSmart` | le jumeau — **les deux fichiers, deux jeux de cas** |

### ⚠️ Fixture pauvre — la forme exacte qu'elle prendrait ici

**Demander `0`.** Le défaut produit `0` ; un cas qui demande `0` est **vert avant et après**.
De même, un oracle qui vérifie seulement « `ImpulseDown` a été appelé » est vert des deux côtés :
c'est **l'argument** qui est faux, pas l'appel. ⇒ **demander une durée non nulle, distincte de
`impulse_time`, et asserter la valeur reçue** — jamais le fait de l'appel.
Et **ne pas utiliser la même durée pour `up` et `down`** : le cas porteur perdrait son sens.

### Contre-mutation **par échange**
- Remettre `erase(0, 11)` sur `down` ⇒ **les cas `down` rouges, les cas `up` verts**. Deux
  ensembles **distincts** — c'est ce qui prouve que le filet distingue les deux branches.
- Échanger les deux littéraux (`"impulse up "` ↔ `"impulse down "`) ⇒ rouge des deux côtés.
- Témoin sans mutation : **0 rouge**.

⚠️ **Les cinq variantes du faux vert/rouge** : effacer le `.o` **et** le binaire, exiger la ligne
`CXXLD <binaire>` dans le journal **et** le code de sortie du binaire — jamais compter les
`FAILED`.

### Le filet doit protéger le produit
`OutputShutter::set_value(string)` est appelable depuis un test sans singleton ni socket (c'est un
`IOBase`, pas un contrôleur) — **le cas doit passer par `set_value("impulse down 500")`**, pas
par une fonction d'analyse recopiée dans le test.

## 4. Acceptation

1. Les **deux** lignes sont corrigées ; le littéral n'est plus compté à la main (constante
   partagée ou `strStartsWith`).
2. Un balayage `python3` des `compare(0, N, "…")` suivis d'un `erase(0, M)` avec `N != M` est
   publié, sur tout `src/` — **c'est ce qui dira s'il y a un troisième site**.
3. Le fixture demande une durée non nulle, différente de `impulse_time`, et différente entre `up`
   et `down`.
4. Contre-mutation par échange : deux ensembles rouges distincts, témoin 0, `CXXLD` **et** code de
   sortie exigés.
5. `make check` vert, **145 goldens intacts** — ⚠️ à vérifier : `cmd_state` passe dans l'état de
   l'IO, donc potentiellement dans un golden.
6. **Entrée `RELEASE_NOTES`** : `impulse down` respecte enfin la durée demandée. C'est un
   changement de comportement observable — un volet qui s'arrêtait après `impulse_time` va
   désormais s'arrêter après la durée réellement demandée.
