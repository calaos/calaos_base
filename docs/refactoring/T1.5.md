## Findings

### F9 — major: unbounded buffering (pre-auth DoS)
- No HTTP body cap: `_parser_body_complete` (`HttpClient.cpp:124-131`) accumulates the whole body in `bodymessage` before any handler. A large POST exhausts memory **before auth**. (The RemoteUI 1 MB check at `RemoteUIProvisioningHandler.cpp:94` runs *after* full buffering.)
- WS message cap `MAX_MESSAGE_SIZE_IN_BYTES = INT_MAX-1` (`WebSocket.cpp:36`) and frame `MAX_FRAME_SIZE_IN_BYTES = INT_MAX-1` (`WebSocketFrame.cpp:23`) → ~2 GB accumulable, effectively unbounded on a small appliance.
- No connection cap and no idle/header timeout in `HttpServer::addConnection`; WS keep-alive starts only after the handshake (`WebSocket.cpp:201`) → slowloris (a silent client held indefinitely).

**Fix:** realistic body/message/frame size limits; concurrent-connection cap; header/idle read timeout.

### F10 — minor (logic): a protocol-violating frame is still dispatched
`WebSocket::processFrame` (`:454-490`): the three violation branches (continuation without start, non-continuation mid-fragmentation, message too large) call `reset()` + `sendCloseFrame(...)` but **without `return`/`continue`** → execution falls through to `currentData.append(...)` (`:490`) and may still dispatch. **Fix:** early exit after each violation.

### F12 — major/minor: `McpProxyHandler` lifecycle
`WebSocket.cpp:121`: `mcpProxy = new McpProxyHandler(client_conn, buffered)` shares the `HttpClient`'s `client_conn`; `teardown()` (`McpProxyHandler.cpp:291-306`) does `client->close()` then the proxy is `delete`d **synchronously** from `~WebSocket` (`WebSocket.cpp:55`). The uvw callbacks (`connectToSidecar`, `:215-234`) capture raw `this`; uvw close is async → a late `DataEvent`/`ErrorEvent` after delete = UAF. The `closed` flag does not protect the raw-`this` callbacks. **Fix:** detach the callbacks before delete, or use `shared_ptr`/`weak_ptr` lifetime.

### New — minor/correctness: 64-bit WS payload length shifted as `int`
`WebSocketFrame.cpp:163` — bytes 4-7 use `(uint8_t(data[4]) << 24) | ...` without a `uint64_t` cast (unlike bytes 0-3). `uint8_t` promotes to `int`, so `0xFF<<24` is signed-int overflow (UB) and sign-extends into `payload_length`. **Fix:** cast each of bytes 4-7 to `uint64_t` before shifting.

### New — minor/correctness: switch fall-through + dead CORS block
- `WebSocket::ProcessData` (`WebSocket.cpp:172`) — the `case HTTP_PROCESS_WEBSOCKET:` block has no `break;` and falls through into the MOREDATA/DONE cases (harmless today, latent). **Fix:** add an explicit `break;`.
- `HttpClient.cpp:388-410` — a second CORS/OPTIONS block tests capitalized header names (`"Origin"`, …) but headers are stored lowercased (`:62/95`), so it can never match; it is also unreachable because OPTIONS already returned at `:224`. **Fix:** delete the dead duplicated block.

## Acceptance
- Huge POST → rejected without OOM (configurable limit).
- WS frame > cap → cleanly rejected, connection closed.
- Silent client → closed on timeout.
- Protocol-violating frame → not dispatched (F10).
- Closing `/mcp` during sidecar traffic → no UAF (ASan).
- 64-bit-length frame parsed without overflow.
