# T3.35 — Un `path` valant `[` fait tomber le serveur, et le message d'échec n'aide personne

**Statut** : 📋 · **Type** : fix (plantage + ergonomie, **même `catch`**) · **Phase** : 3
**Dépend de** : — · **Origine** : caractérisation de [T3.29](T3.29.md) §5.1/§5.6, reproduit en
revue le 2026-08-25. ⚠️ **Collision de fichier** avec T3.37 (extraction du parseur partagé) :
si T3.37 part d'abord, ce correctif se fait **une seule fois** dans le parseur extrait.

---

## 1. Le plantage — mesuré, sur les deux parseurs

Un `path` de configuration valant exactement `[` (une faute de frappe) suffit :

| Étape | MQTT | Web |
|---|---|---|
| jeton reconnu comme index | `if (val[0] == '[')` | idem |
| `val.erase(0, 1)` | `val` devient **vide** | idem |
| `val.pop_back()` | **sous-flue le `size_t`** | idem |
| `Utils::from_string(val, idx)` | **`MqttCtrl.cpp:132` — HORS du `try`** | **`WebCtrl.cpp:202`** |

⇒ `std::bad_alloc` **s'échappe de `getValueJson()`**. Aucun `catch` sur toute la chaîne
(`getValue` → l'IO Mqtt → `main.cpp`) ⇒ **`std::terminate()`**.

⭐ **Ce n'est pas « de l'UB théorique », c'est un plantage déterministe**, reproduit sur les deux
pilotes. La première rédaction du finding disait « UB » et **sous-vendait gravement le défaut** ;
c'est corrigé dans `FINDINGS.md`.

⛔ **Aucun vecteur distant** : le `path` n'est jamais écrit par un client, seulement par
`calaos_installer`. Le déclencheur réaliste est **une faute de frappe dans un paramètre**.

## 2. Le message d'échec — l'« option C » de T3.29, instruite et décidée

T3.29 a tranché : **la doc avait tort, pas le code** — accepter aussi `weather[0]/description`
casserait les charges dont une clé s'**appelle** `action[0]`, ce qui existe (Zigbee2MQTT, mesuré).
Reste que l'utilisateur qui a copié l'ancienne syntaxe n'a **aucun moyen de comprendre**.

**Décision utilisateur (2026-08-25) : améliorer le message, dans le même ticket et le même
`catch`** — `MqttCtrl.cpp:151-155` et `WebCtrl.cpp:221-225`, 3-4 lignes chacun. Quand la recherche
de clé échoue sur un jeton qui **contient** `[`, journaliser en clair
*« did you mean `a/[0]/b` ? array indices are their own path segment »*.

⭐ **Le faux positif est IMPOSSIBLE PAR CONSTRUCTION, et c'est ce qui sépare l'option C de
l'option B** : on n'entre dans ce `catch` que si `parent.at(val)` a **déjà** échoué. Une charge
dont la clé s'appelle vraiment `action[0]` **n'y passe jamais** — elle a résolu. L'option C donne
l'aide sans rien casser, là où l'option B cassait en silence.

## 3. Le travail

1. Garde `if (val.size() < 2)` → chemin d'erreur (retour vide + `cWarning` nommant le jeton),
   **avant** `erase`/`pop_back`. Une ligne, deux fichiers.
2. Rentrer `Utils::from_string(val, idx)` **dans le `try`** (`MqttCtrl.cpp:132`,
   `WebCtrl.cpp:202`) — la garde suffit au cas connu, le `try` ferme la famille.
3. Le message d'aide dans le `catch` de la branche objet, aux deux sites.
4. ⚠️ **Ne pas** faire accepter la forme collée : c'est l'option B, tranchée **non** par T3.29.
