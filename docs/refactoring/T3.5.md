## Findings

### Major — error-handling: a request timeout permanently stalls the command queue
`Squeezebox.cpp:379` — `requestTimeout_cb` calls `processMessage(false,"")` which closes both handles and `return`s (`:380-385`) **without** popping the front command, clearing its `inProgress` flag, or freeing `timer_timeout`. `_sendRequest` then early-returns forever (`:441 if (!empty && front().inProgress) return;`) → the command queue is stuck after any timeout (even post-reconnect). **Fix:** on timeout, pop (or reset `inProgress` on) the front command, delete `timer_timeout`, and re-drive `_sendRequest`.

### Major — lifetime: `json_decref` on borrowed `json_object_get` references
`Squeezebox.cpp:801` — `remoteMeta`/`artwork_url`/`jresult` are **borrowed** `json_object_get` refs (`:786-794`) but are passed to `json_decref` (`:801-803`, `:841-842`) alongside the decref of the owned `json` root → refcount underflow / double-free. **Fix:** only `json_decref` the `json_loads`-owned root; never decref `json_object_get` results.

### Major — correctness: `get_artist` returns the title
`Squeezebox.cpp:676` — `get_artist` sends `remote ?` but connects `&Squeezebox::get_title_cb`, so it follows the title chain and returns the title as the artist; `get_artist_cb`/`get_artist2_cb` (`:678-701`) are dead. **Fix:** connect `get_artist` to `get_artist_cb` (routing to `get_artist2_cb`), or delete the dead callbacks if a title-based flow is intended.

### Major — correctness: buffered-fragment path discards the completing packet
`Squeezebox.cpp:211` (and `:245-249`) — `if (!buffer_notif.empty()) { msg = buffer_notif; buffer_notif.clear(); }` **overwrites** `msg`, discarding the just-arrived fragment that carries the terminating newline. **Fix:** append first, then swap: `buffer_notif += msg; msg = buffer_notif; buffer_notif.clear();` — same for `buffer_main`.

### Minor — edge-case: trailing-trim reads `msg[-1]`
`Squeezebox.cpp:217` (and `:252-253`) — `int i = msg.length()-1; while ((msg[i]=='\n'||...) && i>=0) i--;` evaluates `msg[i]` before the `i>=0` guard → `msg[-1]` for all-newline input; the computed `i` is unused. **Fix:** reorder the guard (`i>=0 && msg[i]==...`); use or delete the result.

### Minor — correctness: unreachable `?playerid=` branch in the cover-art URL
`Squeezebox.cpp:888` — `if (aid=="") aid="current"; …; if (aid=="") aurl << "?playerid=" << id;` — the second test can never be true. **Fix:** capture emptiness before defaulting, and append `?playerid=` on that flag (or remove the dead branch).
