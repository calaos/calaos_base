## Constat (findings bonus relevés pendant T1.5, non corrigés)

1. **En-têtes HTTP non bornés.** llhttp n'impose aucune limite ; `hvalue` s'accumule et
   seul le timeout de 30 s (F9) borne la fuite. Un cap de taille d'en-têtes répondant
   **431 Request Header Fields Too Large** est le complément logique de F9.

2. **Pas de cap de connexions par IP.** `MaxConnections = 100` est global : une seule IP
   peut occuper les 100 slots et évincer tous les autres clients. Ajouter un sous-cap par
   source (comme le backoff par IP de T1.4/F3).

3. **Limites de transport câblées en dur.** T1.5 a introduit `TransportLimits`
   (`MaxHttpBodySize`, `MaxWebsocketMessageSize`, `MaxConnections`, `RequestReadTimeout`)
   en constantes, faute de posséder `ConfigOptions.cpp`/`docs/16_config_options.md` (le
   registre + le doc sont contrôlés par `check-config-options.sh`/`check-config-docs.sh`).
   Les exposer en clés de config avec valeurs par défaut identiques.

4. **`WebSocketFrame::checkValid()` — test control-frame sur le mauvais champ.** Appelé
   depuis `StateReadHeader` alors que `payload_length` contient encore le *code* 7 bits
   (126/127) : le test « control frame > 125 » porte sur le code, pas sur la longueur
   réelle. À vérifier/corriger.

5. **Timer supprimé depuis son propre callback.** `WebSocket::sendCloseFrame`
   (`Timer::singleShot` closeTimeout) : sigc reprend l'émission sur un signal libéré.
   Même famille que les autres « Timer-from-callback » du tree (cf. T2.1).

6. **Captures uvw brutes de `this`/`conn`.** `HttpClient::sendToClient` /
   `sendFrameData` capturent `this` brut dans les callbacks `WriteEvent` ;
   `HttpServer::addConnection` capture `conn` brut dans le lambda `DataEvent`. Sûr
   *aujourd'hui* seulement parce que libuv livre les callbacks des requêtes annulées avant
   `CloseEvent`. Audit de durée de vie à faire (pattern alive-token comme F12/T1.18) pour
   ne pas dépendre de cet ordre de livraison.

## Acceptance
- Une requête aux en-têtes surdimensionnés reçoit 431 puis close, sans accumulation.
- Une seule IP ne peut pas monopoliser toutes les connexions.
- Les quatre limites de transport sont pilotables par config (défauts inchangés), doc et
  checks verts.
- Les points 4-6 sont soit corrigés, soit tracés comme sûrs après audit.
