# T2.13 — GPIO : honorer `debounce_time` de la config

**Type** : fix (comportement, validé utilisateur)
**Phase** : 2
**Décision utilisateur (2026-08-15, voir DECISIONS.md)** : câbler le paramètre — la config
devient effective, fallback 0.05 s si absente/invalide.

## Contexte

`GpioInputSwitch.cpp:50` lit `debounce_time` de la config et le passe à `GpioCtrl`, mais le
debounce du callback GPIO utilise un `0.05` codé en dur (`GpioCtrl.cpp:~185`,
`Timer::singleShot`) : le paramètre est décoratif depuis toujours. T1.19 a conservé ce statu quo
en attendant validation — accordée.

## Travail (fichiers : `src/bin/calaos_server/IO/Gpio/GpioCtrl.{h,cpp}` + tests)

1. Utiliser le membre `debounce_time` (déjà transmis par le ctor) dans le `Timer::singleShot`
   du debounce, au lieu du littéral 0.05.
2. Validation robuste : si la valeur est absente, non-numérique, ≤ 0 ou aberrante (> 5 s),
   retomber sur 0.05 s. Attention au piège `Utils::from_string("")` → true avec dest = 0
   (voir FINDINGS) : passer par un helper de parsing borné testable (pattern
   `parseGridDimension` de T1.10).
3. Nettoyage opportuniste : supprimer la déclaration morte `getFd()` (`GpioCtrl.h:60`,
   jamais définie — erreur de link si utilisée).
4. Tests unitaires du helper de parsing (bornes, vide, garbage, valeurs nominales) dans
   `tests/IOControllers_test.cpp` (binaire existant).

## Acceptation

- Build docker + `make check` verts (tests existants + nouveaux).
- Comportement : sans `debounce_time` dans la config → 0.05 s inchangé ; avec une valeur
  valide → utilisée ; invalide → fallback 0.05 s + warning loggé.
