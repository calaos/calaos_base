# E4.4b — WebCtrl : TinyXPath → XPath pugixml

**Type** : refactor · **Phase** : 4 · **Série** : E4.4 (2/5) · **Dépend de** : E4.4a
**Contexte** : `IO/Web/WebCtrl.cpp:25,257` est le SEUL consommateur de TinyXPath
(`xpath_processor` / `S_compute_xpath`). C'était le bloqueur de la migration vers TinyXML2 ;
avec pugixml il devient un portage direct (`pugi::xpath_query` / `node.select_node()`).

## Travail (fichiers : `src/bin/calaos_server/IO/Web/WebCtrl.{cpp,h}`, tests)
1. Porter l'évaluation XPath sur pugixml. Le document parsé pour cette évaluation devient un
   `pugi::xml_document` **local à ce chemin** — le reste de WebCtrl peut rester sur TinyXML
   jusqu'à E4.4d si ça évite un gros diff (dire lequel a été choisi et pourquoi).
2. **Sémantique préservée** : expression invalide, nœud absent, résultat multiple, résultat
   texte vs nœud — même comportement observable qu'avant (valeur extraite, ou échec loggé).
   Une expression XPath fournie par l'utilisateur qui marchait doit continuer à marcher.
3. Robustesse : `pugi::xpath_query` **lève** `xpath_exception` sur expression invalide, là où
   TinyXPath renvoyait un code — encapsuler pour ne jamais laisser fuir l'exception (le
   pattern maison est un parse non-throwant qui logge et retombe sur un échec propre).
4. Tests : expressions simples ET les formes réellement utilisées en config (relevées par
   l'investigation), plus expression invalide → pas de crash, pas d'exception qui s'échappe.

## Acceptation
`make check` vert ; tests XPath neufs ; comportement identique sur les expressions existantes.
