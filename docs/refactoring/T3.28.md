## 1. Le mécanisme exact de `paramAdd`, lu à la source et vérifié à l'exécution

`IO/IODoc.h:46` (signature réelle, **relue**, non déduite) :

```cpp
void paramAdd(const string &name, const string &description, ParamType type, bool mandatory,
              const string defaultval = string(), bool readonly = false);
```

`IO/IODoc.cpp:52-63` (le corps, qui est la moitié que la fiche d'origine n'avait pas ouverte) :

```cpp
param.Add("mandatory", mandatory ? "true" : "false");
if (!defaultval.empty())
    param.Add("default", defaultval);
```

⇒ `paramAdd("port", …, IODoc::TYPE_INT, 9330)` :

1. `9330` occupe **`bool mandatory`** ⇒ conversion `int → bool` ⇒ **`true`**, **sans avertissement**
   (`-Wall` ne dit rien : ce n'est pas un rétrécissement dans une liste d'initialisation) ;
2. `defaultval` garde son défaut `""` ⇒ le `if` ne tire pas ⇒ **la clé `"default"` n'existe pas du
   tout** dans le document. Pas `"default": ""`, **pas de clé**.

⚠️ **`TYPE_INT` ne produit RIEN de particulier ici** — et c'est le point que la fiche d'origine
laissait ouvert (« que produit `TYPE_INT` avec `mandatory=9330` ? »). `paramAdd` n'utilise `type`
que pour `typeToString()`. **Il n'y a ni `min`, ni `max`, ni validation** dans `paramAdd` :
seul `paramAddInt` (`IODoc.cpp:65-77`) émet `min`/`max` **et émet `default` inconditionnellement**.
Un `TYPE_INT` déclaré via `paramAdd` est donc un entier **sans bornes annoncées**.

**Mesuré à l'exécution** (`TheIoDocDeclaresPortOptionalWithADefault` sur `eb369987`) :
`mandatory` valait `"true"`, `default` était **absent** (`value("default", "")` → `""`).

## 2. Ce que reçoit réellement le sidecar

`Audio/ExternProcRoon_main.py`, **lu au source** :

- `:43` — `parser.add_argument('--port', help='Roon port', default=9330)`. **Pas de `type=int`.**
- `:42` — `parser.add_argument('--host', help='Roon host')`. **Pas de `default` du tout.**
- `:75-83` — `get_roon_host()` : `if self.roon_host: return (self.roon_host, self.roon_port)`,
  sinon `RoonDiscovery`. **Le port est ignoré tant qu'aucun hôte n'est donné.**

| Cas | `args.host` | `args.port` | Ce que fait le sidecar |
|---|---|---|---|
| **drapeaux absents** (`host` vide côté Calaos) | `None` | **entier `9330`** | `RoonDiscovery` — **le défaut Python s'applique, et ne sert à rien** puisque la découverte rend aussi le port |
| `--host … --port 0` | `"…"` | **chaîne `"0"`** | `RoonApi(appinfo, token, host, "0", …)` — port 0 n'est pas connectable |
| `--host … --port <ordure>` | `"…"` | **chaîne** telle quelle | idem, aucune validation, aucun message |

⇒ **le défaut `9330` n'existe côté Python que lorsque le drapeau est ABSENT — confirmé au
source** — et le C++ passait **toujours** le drapeau dès que `host` était renseigné. Le défaut
Python ne pouvait donc **jamais** rattraper le défaut C++.

⚠️ Deux précisions que personne n'avait relevées :
- `--port` **présent** rend une **chaîne**, `--port` **absent** rend un **entier**. Le sidecar vit
  avec les deux (`roonapi` construit une URL), mais c'est une incohérence de type latente.
- une valeur **négative** (mémoire indéterminée) passe quand même `argparse` : le
  `_negative_number_matcher` la prend pour une valeur et non pour une option, faute d'option
  numérique déclarée. Elle arrive donc **jusqu'à `RoonApi`**.

## 5. Écart assumé avec §3 de la fiche

§3 proposait `paramAddInt("port", …, 0, 65535, false, 9330)`. **Le plancher livré est `1`, pas
`0`**, et `portFromParams()` refuse `0` de la même façon. Raison : le port 0 n'est **pas

Déclarer `0..65535` tout en refusant `0` ferait de surcroît mentir la plage affichée par
`calaos_installer`.

### ⭐ Ce que la campagne a trouvé, et qui n'était pas prévu

**M5 a d'abord SURVÉCU** — 0 rouge sur les 12 cas. **Trou réel**, mesuré, pas théorique. Raison,
et elle est instructive : avec l'initialiseur en-classe posé, `from_string` et `portFromParams`
répondent **la même chose** pour une valeur blanche (`from_string` n'écrit rien, `9330` survit)
comme pour une valeur bien formée. Elles ne divergent **que** là où `from_string` écrit une valeur
que personne n'a demandée (`0` pour `"abc"`, `12` pour `"12abc"`) ou réussit sur un nombre qui
n'est pas un port (`70000`). Le cas
`ThePortDefaultsTo9330WhenTheParamIsUnreadableOrOutOfRange` (commit `86cbe7ee`) couvre ces trois
formes **sur un vrai `RoonPlayer`** ; M5 rougit maintenant, **et ce cas seul**.

⚠️ **Corollaire à retenir pour les tickets voisins** : une fonction libre extraite peut être
parfaitement testée **et son site d'appel avoir disparu**. Seul un cas qui traverse la production
de bout en bout le voit. C'est la quatrième forme de contournement de la consigne (« site d'appel
non lié »), rencontrée pour de vrai.
