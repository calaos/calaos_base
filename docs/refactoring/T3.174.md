# T3.174 — aucun délai libcurl : un pair muet retient un transfert pour toujours

**Statut** : 📋 · **Type** : fix · **Phase** : 3
**Origine** : [T3.141](T3.141.md) — mesuré en cherchant ce que devient un transfert que plus rien
ne réveille.

---

## 1. Le fait

`UrlDownloader::start()` (`src/lib/UrlDownloader.cpp:629-678`) pose une vingtaine d'options sur le
handle easy et **aucune** n'est un délai : ni `CURLOPT_TIMEOUT`, ni `CURLOPT_CONNECTTIMEOUT`, ni
`CURLOPT_LOW_SPEED_LIMIT`/`_TIME`. Un pair qui accepte la connexion puis ne répond jamais garde
donc :

- son `UrlDownloaderCurlConn` dans `live`, avec son handle easy, sa `curl_slist` et, en
  téléchargement vers fichier, son flux ouvert ;
- son `uvw::PollHandle` et son descripteur, `CURLOPT_FORBID_REUSE` garantissant une connexion par
  transfert ;
- son appelant dans l'état `m_isRunning`, sans qu'aucun signal ne soit jamais émis.

⚠️ Ce n'est **pas** une régression de la bascule vers libcurl-multi : l'ancien moteur lançait le
binaire `curl` sans délai non plus. C'est un trou hérité, rendu visible par `T3.141` — c'est
précisément parce que rien n'expire qu'une socket non surveillée devait être terminée à la main.

## 2. Pourquoi ça compte ici

Les porteurs sont ceux du chemin HTTP du serveur : instantané de caméra, notification sortante,
sidecar MCP, `UrlDownloader` d'un script Lua ou d'une Web IO. Une caméra qui se fige — le mode de
panne ordinaire d'une caméra IP bon marché — retient un descripteur et un objet par tentative, et
chaque cycle de relecture en ajoute un.

## 3. Ce qui est demandé

Un délai par défaut, réglable, et **distinguer les deux** : `CURLOPT_CONNECTTIMEOUT` borne
l'établissement, `CURLOPT_LOW_SPEED_LIMIT`/`_TIME` bornent un transfert qui n'avance plus sans
casser les flux longs légitimes. ⛔ **Un `CURLOPT_TIMEOUT` sec est le mauvais réflexe** : il
tuerait le flux MJPEG d'une caméra, qui est un transfert sans fin **par construction**
(`m_signalData`, plafond d'accumulation de `dataCb()`).

## 4. Le Nu

⛔ Aucune fuite n'a été observée sur une installation réelle : le fait est lu dans la liste des
options posées, pas mesuré sur un pair qui se fige. La fréquence réelle est inconnue.
