# T3.15 — RemoteUI : `device_info` ne fait pas l'aller-retour

**Type** : fix · **Phase** : 3 · **Décision utilisateur (2026-08-16)** : à corriger, `device_info`
doit faire l'aller-retour.
**Origine** : découvert pendant le portage pugixml (E4.4cd), reproduit tel quel pour ne pas
mélanger portage et correction.

## Le bug
`RemoteUI::SaveToXml` rattache `<calaos:device_info>` au nœud **pièce** (`room`), alors que
`RemoteUI::LoadFromXml` le cherche **à l'intérieur** de `<calaos:remote_ui>`. Les deux ne se
rencontrent donc jamais : ce qui est écrit n'est jamais relu.

## À déterminer AVANT de coder (ne pas présumer)
1. **Quel emplacement est le bon ?** Lire le schéma implicite du reste du fichier et l'intention :
   un `device_info` décrit *un device*, il appartient donc logiquement au nœud `remote_ui`
   — mais le vérifier plutôt que le supposer, y compris côté calaos_installer si le format y est
   connu.
2. **Que contient `device_info` en pratique ?** Lire le code qui le remplit et le consomme. Si
   c'est de l'information rapportée par le device à chaque connexion (firmware, MAC, modèle…),
   sa perte est bénigne et se répare toute seule au prochain contact. Si c'est de la
   configuration saisie par l'utilisateur, c'est une perte de données et la migration ci-dessous
   devient importante. **Cette réponse conditionne le point 3.**
3. **Migration des configs existantes** : comme `SaveToXml` écrivait sous `room`, les io.xml des
   utilisateurs contiennent des `<calaos:device_info>` orphelins à cet endroit, jamais relus.
   Après correction, ils resteraient ignorés puis seraient **supprimés silencieusement** à la
   première sauvegarde. Deux options, trancher selon le point 2 :
   - **Récupération** : au chargement, si un `device_info` est trouvé sous `room`, l'adopter pour
     l'IO `remote_ui` correspondant (migration ponctuelle, puis réécrit au bon endroit).
   - **Abandon assumé** : ne rien récupérer, et le **dire** dans les notes de version.

## Travail
Fichiers : `src/bin/calaos_server/IO/RemoteUI/RemoteUI.{cpp,h}` (+ tests).
⚠️ **Sérialisé après E4.4cd** : ce ticket touche exactement les fonctions que le portage pugixml
retype. À faire **sur le code déjà porté**, jamais en parallèle.

## Tests (le cœur du ticket)
Aller-retour explicite : construire un `remote_ui` avec un `device_info` peuplé → sauver →
recharger → `device_info` **identique**. C'est précisément ce que personne n'avait jamais testé.
Plus, si l'option « récupération » est retenue : une config legacy avec `device_info` sous `room`
→ chargement → l'info est adoptée → sauvegarde → elle est au bon endroit.
