# T3.16 — Réparer le job `format-check` de la CI

**Type** : infra · **Phase** : 3
**Origine** : répétition générale de la CI en local avant le premier push (155+ commits).

## Constat
`format-check` ne s'exécute que sur les **pull requests** (`if: github.event_name ==
'pull_request'`), il ne bloquera donc pas le push de master. Mais il est cassé et échouerait dès
la première PR, pour trois raisons indépendantes :

1. **`src/lib/pugixml` absent de la liste `:(exclude)`** de la pathspec (~`.github/workflows/ci.yml:205`),
   alors que les autres arbres embarqués y sont. Sur une PR master→origin/master l'outil sort
   **31 246 lignes sur 121 fichiers, dont 26 242 (84 %) rien que pour `src/lib/pugixml/pugixml.cpp`**
   (indentation par tabulations, `#\tinclude`…). Seul le `.cpp` est touché : les `.hpp` ne
   correspondent pas à la pathspec `'*.h'`.
2. **Notre propre code n'est pas conforme non plus** — indépendamment de pugixml, et c'est le
   point le plus gênant : 84 lignes sur `src/bin/calaos_server/ListeRule.cpp` et
   `tests/core/RuleOwnership_test.cpp` (E4.2d), 34 lignes sur `src/lib/ConfigStore.cpp`
   (`for (;keyNode;` → `for (; keyNode;`, ×2) et `src/lib/XmlUtils.h` (indentation de
   continuation 8→4 sur `CONFIG_PARSE_OPTIONS`). **La prochaine PR de taille normale échoue.**
3. **`actions/checkout@v4` s'exécute avant l'installation de `git`** : il retombe alors sur
   l'archive REST et ne laisse pas de dossier `.git`, si bien que le `git diff origin/...`
   ultérieur échouerait avec « not a git repository ». *(Déduit du comportement documenté de
   checkout, non reproduit — à vérifier.)*

## Travail
1. `.github/workflows/ci.yml` : ajouter `':(exclude)src/lib/pugixml' \` à la liste de pathspec du
   job `format-check`, au même endroit que les autres arbres embarqués.
2. Installer `git` **avant** l'étape `actions/checkout` (ou confirmer que le point 3 n'est pas
   réel — le vérifier compte autant que le corriger).
3. **Ne PAS reformater notre code dans ce ticket** : `ListeRule.cpp` appartient à E4.2e, en vol.
   Le nettoyage de formatage se fera en une passe dédiée, **après** le merge d'E4.2e, et devra
   couvrir aussi ce qu'E4.2e aura ajouté.

## Acceptation
Le job `format-check` reproduit localement sur une PR simulée ne signale **plus aucune ligne de
`src/lib/pugixml`** ; `make check` inchangé (le ticket ne touche pas au code).
