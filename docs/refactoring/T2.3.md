## Fichiers possédés
- `lib/SHA1.{cpp,h}` (suppression)
- `WebSocket.cpp`
- `src/lib/Makefile.am`

## Constat
`lib/SHA1.cpp`/`SHA1.h` = implémentation bundled (public-domain, Dominik Reichl) de ~500 lignes de crypto maison. Son **unique** consommateur est `WebSocket.cpp` (calcul du `Sec-WebSocket-Accept` du handshake WS). Or OpenSSL est **déjà une dépendance dure** (`configure.ac:52`, et utilisé directement dans `RemoteUI/OtaHttpHandler.cpp`, `RemoteUI/FirmwareManifest.cpp`, `IO/RemoteUI/RemoteUI.cpp`). Le SHA1 maison est donc redondant.

## Remédiation
- Remplacer l'appel SHA1 dans `WebSocket.cpp` par OpenSSL (`SHA1()` / EVP).
- Supprimer `lib/SHA1.{cpp,h}` et leurs références dans `src/lib/Makefile.am`.

Risque faible : le digest sert à un handshake public (non secret), pas d'implication cryptographique sensible.

## Acceptance
- Handshake WebSocket fonctionnel (client se connecte, `Sec-WebSocket-Accept` correct).
- `SHA1.cpp`/`SHA1.h` supprimés, plus aucune référence dans le build.

## Vérification
Suite Autobahn (`tests/websockets/`) + connexion d'un client WS réel ; `grep -rn SHA1 src/` ne renvoie plus que des usages OpenSSL.
