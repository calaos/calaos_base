## Owned files

> Path note: `RemoteUI.cpp` lives under `IO/RemoteUI/`, not `RemoteUI/`. The WS/OTA handlers under `RemoteUI/` are owned by **T1.10** — disjoint.

## Findings

### F2 (HMAC) — non-constant-time comparison on the auth gate
`RemoteUI::validateHMAC` (`IO/RemoteUI/RemoteUI.cpp:354`, comparison at `:376`) ends with `return oss.str() == hmac;` — a byte-by-byte short-circuiting comparison of the computed vs supplied HMAC. This is the real device authentication gate. **Fix:** `CRYPTO_memcmp` (constant-time). Mitigated in practice by nonce-replay + 10/min rate-limit, but a real side channel.

### Duplication to consolidate (divergence risk)
- `findHeader` (case-insensitive) is defined **twice identically**: `HMACAuthenticator.cpp:34-48` and `:121-134` → factor into a single function.
- `validateAuthentication` vs `validateAuthenticationWithReason` (`RemoteUIManager.cpp:125-297`): same logic duplicated, differing only by return type → one must delegate to the other.

### New — minor/lifetime: reconnect replaces a live handler without closing it
`RemoteUIManager::addWebSocketHandler` (`RemoteUIManager.cpp:456`) logs "Replacing existing handler … (device reconnected while old connection still open)" then `connected_handlers[id] = handler;` — the previous handler's WebSocket is never closed, leaving a half-open connection until TCP timeout. **Fix:** explicitly close/tear down the previously-registered handler before overwriting the map entry.

## Notes (positive — preserve)
The RemoteUI HMAC flow is otherwise well built: rate-limit → nonce-replay cache → nonce length (64) → time window → HMAC, with cleanup timers; nonces/secrets via OpenSSL `RAND_bytes`. Do not regress these properties.

## Acceptance
- HMAC compared in constant time (`CRYPTO_memcmp`).
- Single `findHeader`; one `validateAuthentication*` delegates to the other.
- Device reconnect closes the stale handler's socket.

## Verification
`make check`; unit test that a wrong HMAC is rejected and a valid one accepted; simulate a reconnect and confirm the old socket is closed. Do not regress the nonce-replay / rate-limit behavior.
