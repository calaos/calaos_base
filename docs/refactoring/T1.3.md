## Constats

### M6 — majeur : clé/valeur inversées sur le nom par défaut
`ListeRoom::createIO` (`ListeRoom.cpp:275`) :
```cpp
if (!param.Exists("name")) param.Add("<No Name>", "Input");
```
La clé et la valeur sont transposées : ça ajoute un param **nommé** `"<No Name>"` de valeur `"Input"` au lieu de `name="<No Name>"`. Les IO créés sans nom n'ont donc toujours pas de param `name`.

**Remédiation** : `param.Add("name", "<No Name>");`

### m9 — `EventIOAdded` émis même si la création a échoué
`ListeRoom::createIO` (`ListeRoom.cpp:280-289`) garde `room->AddIO(io)` avec `if (io)` mais émet `EventIOAdded` inconditionnellement ensuite → annonce un IO inexistant.

**Remédiation** : émettre l'événement uniquement si `io != nullptr`.

### m10 — IDs dupliqués écrasés silencieusement
`addIOHash` (`ListeRoom.cpp:47-59`) fait `io_table[id] = io` sans contrôle de collision → deux IO de même id : le premier devient inaccessible par id, `get_io_count()` sous-compte, et `delIOHash` de l'un supprime l'entrée partagée.

**Remédiation** : détecter la collision, logguer via `cErrorDom("root")`, rejeter le doublon (ou suffixer). Décider et documenter le comportement.
