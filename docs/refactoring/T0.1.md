# T0.1 — CI build + `make check`

| Phase | Type | Dépend de | Statut |
|---|---|---|---|
| 0 | infra | — | 📋 Backlog |

## Fichiers possédés
- `.github/workflows/ci.yml` (nouveau)

## Objectif
Ajouter un job GitHub Actions qui build le projet et lance `make check` sur chaque PR et push. Aujourd'hui la CI ne contient que des workflows de build/publish Docker (`docker-publish.yml`, `docker-publish-dev.yml`) — **aucun ne lance les tests**. Les 3 tests GTest existants ne gardent donc jamais les merges.

## À faire
- Installer les dépendances de build (`libuv`, `jansson`, `libcurl`, `luajit`, `sigc++`, `sqlite3`, `gtest`) sur l'image CI (Debian 12 pour aligner avec le `Dockerfile`).
- `./autogen.sh && ./configure && make && make check`.
- Faire échouer la CI si un test échoue.

## Acceptance
- Une PR déclenche le pipeline build + les tests existants (`ColorValue_test`, `ExpressionEvaluator_test`, `FileUtils_test`).
- Un test rouge ⇒ CI rouge.

## Vérification
`gh pr checks` montre le job « build & test » ; simuler un test cassé et confirmer l'échec CI.
