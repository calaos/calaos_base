# E4.3cd — Option `--enable-asan` + rapport de couverture en CI

**Type** : infra · **Phase** : 4 · **Origine** : les 2 items restants d'E4.3 (voir PHASE4.md)

## E4.3c — `--enable-asan` dans `configure.ac`
Aujourd'hui il n'existe **aucun câblage ASan** : les runs se font à la main en passant des
`CXXFLAGS` bricolés. C'est précisément l'outil qui valide la série E4.2 (ownership, `unique_ptr`,
suppression des `delete` manuels) — il doit être une option de premier ordre, pas une recette.

- Ajouter `AC_ARG_ENABLE([asan])` → `-fsanitize=address -fno-omit-frame-pointer -g -O1`
  sur CFLAGS/CXXFLAGS **et** LDFLAGS. Désactivé par défaut.
- Mentionner l'état dans le résumé de configure.
- ⚠️ **Ne pas modifier les flags par défaut** : un build sans l'option doit produire exactement
  les mêmes flags qu'aujourd'hui (à vérifier en comparant `config.log`/`Makefile` avant/après).
- Documenter l'invocation recommandée (dont `ASAN_OPTIONS=detect_leaks=0`, cf. ORCHESTRATION.md).
- Vérifier que `make check` passe **sous ASan** : le seul échec historique (exprtk) a été corrigé
  par T2.8, donc la suite doit être propre. Si un test échoue sous ASan, **le rapporter** — c'est
  une vraie trouvaille, ne pas le contourner.

## E4.3d — Job de couverture en CI
`.github/workflows/ci.yml` lance `make check` mais ne mesure rien. Ajouter un job (séparé, non
bloquant pour la PR) qui build avec `--coverage`/gcov, lance `make check`, produit un rapport
lcov et le publie en artefact. Pas de seuil imposé pour l'instant — l'objectif est d'avoir la
mesure, pas de faire échouer sur un chiffre arbitraire.

## Fichiers
`configure.ac`, `.github/workflows/ci.yml`, éventuellement `docs/` pour l'invocation.
**Aucun fichier source de production.**

## Acceptation
`./configure` sans option → flags inchangés, `make check` vert (49/49) ; `./configure --enable-asan`
→ build ASan, `make check` vert sous ASan (ou échecs rapportés) ; le job CI de couverture produit
un artefact lisible.
