## 1. Le constat, revérifié au source (2026-08-25)

**Les références de `FINDINGS.md` sont exactes**, ligne pour ligne.

`LuaScript/ScriptBindings.cpp:293` (fin de `setIOParam`) et `:333` (fin de `waitForIO`) portent
tous deux `return 1`. Corps relus intégralement : `:254-292` et `:300-331`. **Aucun
`lua_push*` sur le chemin de succès** — les seuls `lua_pushstring` sont les préambules de
`lua_error()` (`:260`, `:279`, `:289`, `:306`, `:321`, `:329`), qui font un `longjmp` et ne
reviennent jamais.

Ce n'est **pas** « une valeur indéterminée ». `Lunar::thunk` (`LuaScript/Lunar.h:130-137`) :

```cpp
  static int thunk(lua_State *L) {
    // stack has userdata, followed by method args
    T *obj = check(L, 1);  // get 'self', or if you prefer, 'this'
    lua_remove(L, 1);  // remove self so member function args start at index 1
    RegType *l = static_cast<RegType*>(lua_touserdata(L, lua_upvalueindex(1)));
    return (obj->*(l->mfunc))(L);
  }
```

`self` est retiré, **les arguments de l'appel restent sur la pile**, et `return 1` demande à Lua
de prendre le **sommet** comme unique résultat. Donc, de façon parfaitement reproductible :

| Appel Lua | Ce qui est rendu | Ce que le script croit lire |
|---|---|---|
| `calaos:setIOParam(id, key, val)` | **`val`** (3ᵉ argument, sommet) | un statut de succès |
| `calaos:waitForIO(id)` | **`id`** (1ᵉʳ et seul argument) | un statut de succès |

⭐ **Conséquence** : `if calaos:waitForIO(io) then …` est **toujours vrai** — `id` est une chaîne
non vide, et en Lua toute chaîne non vide est truthy. Idem pour `setIOParam` dès que `val` n'est
ni `nil` ni `false`. **Il n'existe aucune manière, depuis un script, de savoir si l'appel a
réussi** — sauf que l'échec passe par `lua_error()`, donc par une **exception Lua**, pas par un
retour.

⚠️ **Ce dernier point atténue la gravité, et il faut le dire** : les chemins d'erreur réels
(`invalid IO id`, `wrong value`, `Abort script`) **lèvent**. Un script qui teste le retour
n'apprend rien, mais un script qui **ne** teste pas le retour se fait quand même interrompre.
Le défaut est donc **un mensonge d'API**, pas une perte de détection : il fait écrire du code de
garde qui ne garde rien. Il est documenté comme tel dans `docs/09_lua_scripting.md` (E4.5e).

## 2. Le travail

Deux issues, à trancher **dans le ticket** :

- **`return 0`** — l'appel ne rend rien, `waitForIO(io)` vaut `nil`. Le plus honnête, et il
  **casse** tout script qui teste le retour aujourd'hui : le test devient faux au lieu d'être
  toujours vrai. C'est un changement observable ⇒ `RELEASE_NOTES`.
- **empiler un vrai booléen** (`lua_pushboolean(L, true)` sur le chemin de succès, `return 1`) —
  le retour devient enfin ce que le script croyait lire. Rétro-compatible au sens truthy pour
  `setIOParam` (`val` truthy → `true`), **et pour `waitForIO`** (`id` truthy → `true`).

**Recommandation : le booléen.** Il rend l'API conforme à ce que la documentation et l'intuition
promettent, sans invalider un script existant qui écrivait `if calaos:waitForIO(io) then`.
`return 0` invaliderait exactement ces scripts-là.

**Balayer les voisins dans le même ticket** : toute méthode de `ScriptBindings.cpp` qui rend
`return N` sans empiler `N` valeurs sur **chacun** de ses chemins. C'est un balayage `python3`,
pas un `grep`.

### 5.1 ⭐ Ce que voit le script, **prouvé par exécution**

Pas repris de la fiche : **remesuré**. Le défaut vit dans la **pile Lua**, pas dans la valeur de
retour C++, donc les 12 cas poussent un vrai `lua_State` via `ScriptManager::ExecuteScript()` — le
seul endroit de l'arbre qui en crée un, celui que `calaos_script` emprunte en production — et
exécutent du **Lua littéral**.

⚠️ `ExecuteScript()` ne rend qu'un **booléen** : un script ne peut donc pas dire au test ce qu'il a
vu. Le cas `WhatTheScriptActuallySeesComingBack` contourne ça en faisant **remonter
`type(r)`/`tostring(r)` par le fil `set_param`**, sur une **vraie socket AF_UNIX** que le fixture
ouvre et décode (`ScriptWire::parseMessage` + `decodeObject`, l'en-tête livré, pas une copie).
Sortie réelle du binaire, **avant** correctif :

```
[ OBSERVED ] calaos:setIOParam(id, key, value) -> string/sentinel-42-gamma
[ OBSERVED ] calaos:waitForIO(id)              -> string/io_probe_alpha
```

et **après** :

```
[ OBSERVED ] calaos:setIOParam(id, key, value) -> nil/nil
[ OBSERVED ] calaos:waitForIO(id)              -> nil/nil
```

Le script recevait bien **son propre dernier argument**, typé `string`. Et
`TheClassicGuardNoLongerReadsTrueByAccident` mesure la conséquence : avant correctif,
`if calaos:waitForIO(io) then return true else return false end` **rendait `true`**.

⚠️ **Piège du fixture pauvre, évité explicitement** : les trois valeurs (`io_probe_alpha`,
`probe_key_beta`, `sentinel-42-gamma`) sont **trois chaînes sans rapport**, dont aucune n'est un
booléen. Avec `value = true` — la forme naturelle — le défaut et le correctif rendraient **la même
chose** et les 12 cas resteraient verts dans les deux mondes.

### 5.2 ⚠️ L'arbitrage : `return 0`, **contre la recommandation du §2 de cette fiche**

Le §2 recommandait **le booléen**. La livraison rend **`return 0`**, et le motif est mesuré :

- **La convention de la table est sans ambiguïté.** Balayage `python3` (acceptation #2) des
  `lua_CFunction` de **tout l'arbre** — il y en a **9**, toutes dans ce fichier :

  | | Fonctions | Contrat |
  |---|---|---|
  | **Accesseurs** | `getIOValue`, `getIOParam`, `getEnv` | `return 1` + **1 `lua_push*`** sur chaque chemin de succès |
  | **Mutateurs / actions** | `setIOValue`, `requestUrl`, `sendPushNotif`, `Lua_print` | `return 0`, rien d'empilé |
  | **Les deux défauts** | `setIOParam`, `waitForIO` | `return 1`, **rien d'empilé** |

  `setIOParam` est le **frère direct** de `setIOValue`. **Aucun binding de l'arbre ne rend un
  booléen de succès** : le proposer, c'est *inventer* une convention. Après correctif :
  **0 suspect sur 9**. (⚠️ Le compteur de `lua_push*` du script sur-compte de 1 sur `setIOParam` —
  un `lua_pushstring` de préambule de `lua_error()` séparé de son `lua_error` par plus de sa
  fenêtre ; les **9 corps ont été relus à la main**, c'est la preuve, pas l'heuristique.)

- ⭐ **Il n'y a aucune information de succès à empiler.** `LuaIOBase::set_param()` (`:502-509`) est
  `void` et poste un message **sans réponse** sur la socket `ExternProc` ; `waitForIO()` ne revient
  normalement que si `waitForIOChanged.emit()` a répondu vrai **et** que `abort` est faux — le cas
  `abort` **lève**. ⇒ `lua_pushboolean(L, true)` serait une **constante**, et
  `if calaos:waitForIO(io) then` resterait **vrai pour toujours**. La rétro-compatibilité que le
  booléen achetait est la **rétro-compatibilité avec le bug**.

⚠️ **La contrepartie est réelle et assumée : la bascule est SILENCIEUSE.** Un script qui écrivait
`if calaos:waitForIO(io) then A else B end` passait **toujours** par `A` et passera **toujours** par
`B`. Ni erreur, ni ligne de journal. C'est le sujet de l'entrée `RELEASE_NOTES`.
**Retour arrière : UNE ligne par fonction** (`:311`, `:360`) + les 6 cas ⭐ du filet, si un relecteur
ou l'utilisateur tranche autrement.
