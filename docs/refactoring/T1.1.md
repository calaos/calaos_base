# T1.1 — Rule/IO lifecycle (C1, C2 + scenario)

| Phase | Type | Depends on | Status |

## Owned files
- `src/bin/calaos_server/ListeRule.{cpp,h}`
- `src/bin/calaos_server/Scenario/AutoScenario.{cpp,h}`

## Findings

### C1 — critical: `RemoveRule` leaves dangling IO pointers
`ListeRule::RemoveRule(IOBase*)` (`ListeRule.cpp:188`) only scans `ConditionStd` (inputs, `dynamic_cast` at `:197`) and `ActionStd` (outputs, `:209`). A rule that references the deleted IO **only** via:
- `ConditionOutput` (member `output`), or
- `ConditionScript` (map `in_event`),

is **not** removed → its `IOBase*` dangles. It is then dereferenced at `Rules/ConditionOutput.cpp:45` (`output->get_type()`), `Rules/ConditionOutput.cpp:327` (`output->get_param("id")`), and `Rules/ConditionScript.cpp:101` (`io->get_param("id")`). `ListeRoom::deleteIO` is reachable at runtime (IO deletion via the JSON API) → **UAF** at the next `SaveConfigRule` or evaluation.

**Fix:** extend `RemoveRule` (or a dedicated visitor) to **all** condition/action subtypes that reference an IO. Do not modify `ConditionOutput.*`/`ConditionScript.*` (owned by other tickets) — do it in `ListeRule` via the existing public accessors.

### C2 — critical (latent): `reinterpret_cast` instead of `dynamic_cast`
`AutoScenario.cpp` performs **8** `reinterpret_cast<ConditionStd*>` / `<ActionStd*>` at lines 170, 188, 223, 238, 254, 274, 606, 640, whereas `ListeRule.cpp` correctly uses `dynamic_cast` (e.g. `:118,197,209`). A `reinterpret_cast` to the wrong subtype is undefined behavior. **Fix:** convert to `dynamic_cast` with null checks.

### New — major/lifetime: `getCategory` dereferences a null `ScenarioAction::io`
`AutoScenario::getCategory` (`AutoScenario.cpp:685`) does `sa.io->get_param("gui_type")` where `getStepAction` (`:596-626`) returns a default `ScenarioAction{io=nullptr}` when no index matches. Its skip-list (`ioStep/ioTimer/ioIsActive/ioScenario/ioScheduleEnabled`) is wider than `getStepActionCount`'s fixed `-3`, so counts diverge and `io` can be null. **Fix:** null-check `sa.io`, and align `getStepActionCount`'s subtraction with `getStepAction`'s skip-list.

### New — minor/concurrency: `execInProgress` released before async script executions run
`ExecuteRuleSignal` (`ListeRule.cpp:185`) sets `execInProgress = false` after the synchronous loop, but the `ConditionScript` branch (`:158-165`) schedules `Rule::CheckConditionsAsync` whose callback toggles `execInProgress` later; the deferral guard (`:96-106`) relies on it to serialize, so a new signal can run concurrently with a still-pending script execution. **Fix:** refcount outstanding async executions and clear `execInProgress` only when they complete.

## Acceptance
- Deleting an IO referenced only via `ConditionOutput`/`ConditionScript` removes the rule (no dangling `IOBase*`); `SaveConfigRule` after deletion is clean.
- No `reinterpret_cast` in `AutoScenario.cpp`; misclassified casts null-checked.
- `getCategory` on a step whose action targets a skip-listed IO does not crash.
- Regression test (fixtures from T0.3): create/delete IOs referenced by every condition/action type under ASan with no memory error.

## Verification
`make check` with lifecycle fixtures; run the IO-deletion scenario under `valgrind`/ASan with no memory-access error.
