# E4.2 — Modèle de propriété (smart pointers / références par id)

| Phase | Type | Dépend de | Statut |
|---|---|---|---|
| 4 | epic | Phase 3 | 📋 Backlog |

## Portée
Épic architectural — **cause racine** de la majorité des bugs de cycle de vie. À découper module par module.

## Constat
Le modèle actuel repose sur des **pointeurs bruts** avec de multiples alias non-propriétaires du même objet :
- `ListeRoom` → `Room*` → `IOBase*` (propriétaires) ; mais `io_table`, `cameraCache`, `audioCache`, `ListeRule::in_event`, et chaque `Condition*`/`Action*` détiennent des `IOBase*` **non-propriétaires**.
- `ListeRule` → `Rule*` → `Condition*`/`Action*` (propriétaires) ; `rules_scenarios`, `in_event`, `AutoScenario` détiennent des back-pointers bruts.

Toute suppression d'IO/règle au runtime doit nettoyer manuellement **tous** les alias, et plusieurs chemins ne le font pas → classes de bugs UAF (voir T1.1/C1, ainsi que M2, M5, m12 de l'audit).

## Remédiation (proposée)
- Conteneurs propriétaires en `unique_ptr<IOBase>` / `unique_ptr<Rule>` (+ `unique_ptr` pour Condition/Action).
- Références secondaires **par id** (string) résolues à la demande via `ListeRoom::get_io(id)` au lieu de pointeurs bruts aliasés — supprime la classe entière de dangling pointers.
- Alternativement `shared_ptr` + `weak_ptr` pour les caches/observers si la résolution par id est trop coûteuse en chemin chaud.
- Migration **module par module** (IO d'abord, puis Rules, puis Scenario), chaque étape gardée par des tests.

## Acceptance (epic)
- Plus de `delete` manuel sur les objets métier ; propriété exprimée par le type.
- Les références secondaires ne peuvent plus dangler (résolution par id ou weak_ptr).
- ASan/valgrind propres sur les scénarios de suppression IO/règle au runtime.

## Vérification
Suite de tests de cycle de vie (création/suppression d'IO référencés par tous types de conditions/actions) sous ASan ; non-régression fonctionnelle complète.

> Prérequis absolu : E4.3 (couverture de tests) sur le moteur de règles et le cycle de vie IO. Ne pas démarrer sans filet.
