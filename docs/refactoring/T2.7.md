## Findings

### Major — lifetime: NTPClock deletes its own repeating Timer from inside that timer's tick
`NTPClock::TimerTick()` (`NTPClock.cpp:96`) does `delete timer; timer = NULL; updateClock(); timer = new Timer(...);`. `TimerTick` is invoked from `Timer::Tick()->emit()` **on the same Timer**, so `~Timer()` (`handleTimer->stop()/close()`) runs while that Timer's uvw callback is still on the stack — a "delete this from within the callback" pattern, use-after-free-prone. This is a distinct site from T2.1's `singleShot` but the same class of bug. **Fix:** do not delete-from-within-tick — reuse/reset the existing repeating Timer (it already repeats), or defer destruction to after the callback returns via the loop, matching T2.1's approach.

## Acceptance
- The periodic clock update no longer destroys its own Timer from inside the tick; ASan clean over many ticks.
- Clock update cadence unchanged.

## Verification
`make check` with an NTPClock test running several tick cycles under ASan (no use-after-free / double-free); confirm the update interval is unchanged.
