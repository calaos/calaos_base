**Statut** : ✅ **LIVRÉE** · **Type** : chore (code mort) · **Phase** : 3 · **Dépend de** : —

**Finding** : rattaché à `F-LOGRAW-1`.

## 1. Ce qui est supprimé

`src/bin/calaos_server/LuaScript/ScriptBindings.cpp` définissait `Lua_stackDump(lua_State *)`, qui
imprimait la pile Lua sur `stdout`. La définition (29 lignes) et sa déclaration dans
`ScriptBindings.h` (3 lignes) sont retirées. **34 lignes en moins, aucune ligne ajoutée.**

⛔ **Le compte de la fiche d'ouverture était faux et il est corrigé ici** : la fonction porte **six**
écritures nues, pas quatre. Quatre publient une donnée d'exécution (`lua_tostring`, `lua_toboolean`,
`lua_tonumber`, `lua_typename`) et **deux sont des littéraux fixes** — le séparateur `"  "` et le
`"\n"` final. Le sous-total « publiant une donnée d'exécution » diminue donc de 4, mais le total de
la famille diminue de **6**.

## 2. Les quatre vérifications, REFAITES

Aucune n'est reprise de la revue de `T3.97` ; les quatre ont été rejouées sur l'arbre du jour.

1. **Textuelle, arbre entier** (tous les fichiers hors `.git`, `data/` et `tests/` compris) :
   **15** occurrences de `stackDump`, dont **13 dans `docs/refactoring/`**. Dans le code : exactement
   **deux** — la déclaration et la définition. `git ls-files '*.lua'` rend **0** : aucun script Lua
   n'est suivi, donc aucun appel côté script. Les orthographes voisines (`stack_dump`, `dumpStack`,
   `dump_stack`, `StackDump`) ne rendent rien d'autre.
2. **Collage de jetons** : aucun `Lua_##`, aucun `## stackDump`, et aucun `#define` dont le corps ou
   le nom contienne `stack…dump` dans tout l'arbre hors `docs/`. Le nom n'est construit nulle part.
3. ⭐ **Structurelle — la décisive, et elle est plus forte que ce que la revue avait établi.**
   Le Lua réellement lié est **LuaJIT 2.1.0-beta3** (`configure.ac:51`, `PKG_CHECK_MODULES`,
   `pkg-config --modversion luajit`), en-têtes sous `/usr/include/luajit-2.1`. Son `lua.h` déclare :

   ```c
   typedef int (*lua_CFunction) (lua_State *L);                       /* lua.h */
   typedef const char * (*lua_Reader) (lua_State *, void *, size_t *); /* lua.h */
   typedef int (*lua_Writer) (lua_State *, const void *, size_t, void *);
   typedef void * (*lua_Alloc) (void *, void *, size_t, size_t);
   typedef void (*lua_Hook) (lua_State *L, lua_Debug *ar);
   ```

   Ce sont **les cinq seuls** types de rappel que LuaJIT expose (`lua.h`, `lauxlib.h`, `luaconf.h`),
   et **aucun** n'a la forme `void (*)(lua_State *)`. Le plus proche, `lua_Hook`, rend bien `void`
   mais prend **deux** paramètres — c'est celui qu'utilise `Lua_DebugHook`, pas celui-ci. `luaL_Reg`
   ne porte qu'un `lua_CFunction`, et `lua_pushcfunction(L,f)` est une macro sur
   `lua_pushcclosure(L,(f),0)`, dont le paramètre est un `lua_CFunction`. En C++, un
   `void(*)(lua_State*)` ne se convertit pas implicitement en `int(*)(lua_State*)` : tout site qui
   aurait essayé serait une **erreur de compilation**, pas un comportement douteux.
   **Les sites de remise à Lua ont été énumérés à la main dans tout `src/`**, et il y en a
   exactement cinq : `sandbox_libs[]` (`ScriptManager.cpp`), `lua_pushcfunction(L, lib->func)` qui
   la parcourt, `lua_pushcfunction(L, Lua_print)`, les quatre `lua_pushcfunction`/`lua_pushcclosure`
   de `Lunar.h`, et `lua_sethook(L, Lua_DebugHook, …)`. ⭐ **Aucun `lua_atpanic`, `lua_cpcall`,
   `lua_dump` ni `lua_load` dans l'arbre.** `Lua_stackDump` n'est dans aucun.
4. **Édition de liens, mesurée sur un arbre construit** : `nm -C` sur les `.o`/`.a` de tout l'arbre
   donne le symbole **défini** dans `LuaScript/ScriptBindings.o`
   (`T Calaos::Lua_stackDump(lua_State*)`) et **`0`** référence indéfinie vers lui, partout.

## 5. ⛔ Ce qui n'est pas là où la fiche d'ouverture le disait

`calaos_script_SOURCES`, **jamais** dans `calaos_server_SOURCES` : mesuré au `nm`, le symbole était

serveur lance **par exécution de script de règle**.

`stdout` du serveur — c'est-à-dire par le chemin même que [`T3.101`](T3.101.md) documente. Le
classement de `T3.97` (« chemin d'exécution du serveur ») est donc juste **opérationnellement** et
faux **au binaire près** ; la fiche le dit au lieu de le laisser croire.
